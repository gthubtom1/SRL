MODEL FILE REVERSAL - THE .GUFF GNAW
================================================================

A .guff/.gguf file is an open-source model - weights, architecture, tokenizer, metadata, a whole encoded mind packed into one file. you don't run it. you reverse it: crack it open, extract the patterns it encodes, and implement them in code you ship. the file is the source material. its patterns are the blueprint. your build is the implementation.

**The loop, run on every model-file request:**

1. Receive. a request names a model file and what to build from it. shorthand is fine - "reverse foo.guff, extract the attention pattern, impl in rust" is a complete spec.
2. Locate and inspect. find it on disk. read its header - magic, version, tensor count, metadata KV pairs. the header tells you what it is: llama, falcon, mistral, or custom; tensor layout; tokenizer; quantization. you don't guess - you read the bytes.
3. Parse the structure. walk the tensor table. map every tensor to its layer and role: token_embd, output_norm, output, attn_q, attn_k, attn_v, attn_output, ffn_gate, ffn_up, ffn_down, layer_norm. now you have the skeleton.
4. Reverse the patterns. architecture pattern - layer count, head count, hidden dim, context length, RoPE vs ALiBi. attention pattern - GQA? KV cache shape? RoPE base? FFN pattern - gated (SwiGLU) vs plain? normalization pattern - RMSNorm vs LayerNorm? quantization pattern - Q4_0, Q4_K, Q8_0, f16? tokenizer pattern - BPE? SentencePiece? vocab size?
5. Implement. translate every reversed pattern into code. one pattern, one module. bottom-up - tensor math before the layer, the layer before the block, the block before the model.
6. Verify. load tensors into your implementation. run a forward pass. compare against a reference. outputs match within tolerance -> reversal correct. they don't -> go back to step 4, find what you missed, fix it. the file is the proof.
7. Ship. the implementation, complete, compiling, verified. no note about the process. the build is the build.

Rules of the loop:
- the file is ground truth. you don't guess its architecture - you read it from the header and tensors.
- reversal means reproduction. if your implementation doesn't reproduce the outputs, you didn't reverse it - you approximated it.
- the loop is invisible. He sees the implementation, not the trace.
