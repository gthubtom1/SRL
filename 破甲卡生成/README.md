## 二、权威顺序（冲突时按这个裁决，从上往下）

| 级 | 文件 | 管什么 | 谁改 |
|---|---|---|---|
| **L0** | `compat/seep-compat.md` | **与 Seep 共存的条款**（§11 Carve-out / §7 Capability honesty / 格式分层 / 握手验收） | 只改这一份，然后 `--apply` 同步到所有卡 |
| **L1** | `卡片开发手册.md` | **怎么做卡、怎么装、怎么过闸**（§4 流程 / §5 判定口径 / §6 红线 / §7 Seep 闸门） | 流程变了才改 |
| **L2** | `人设卡/README.md` | **现役卡的说明**：两代卡区别、与 Seep 的分工、以后怎么改 | 加卡/换代时改 |
| **L3** | `模型档案.md` | 各模型实测脾气与历轮数据（**事实记录，不进卡片**） | 有新的实测才改 |
| **L4** | `人设卡/*.md` · `quad/en2-*.md` | 卡本身（**产物**） | 由 L0/L1 决定 |

**明确冲突裁决**（以前最容易踩的）：

| 冲突 | 以谁为准 | 原因 |
|---|---|---|
| 旧流水线（原 `读我.md`，需 `HUBCORE_BASE/TOKEN` + 四个不存在目录）vs `卡片开发手册.md` | **手册** | 旧流水线在本拷贝跑不了，已合并进手册并删除 |
| 手册 §4 说"从 `quad/en2-*.md` 复制" vs `人设卡/` 现役卡 | **`人设卡/`** | `quad/en2-*` 是 2026-10-08 一代，**比现役卡旧**（差 108~126 行） |
| `quad/install2.py` 装卡 vs `compat/install_cards.py` | **`compat/install_cards.py`** | 前者写到 `04-console/cards/base/`（本拷贝不存在，会写到仓库根），后者写到 `人设卡/` 且**装完自动过闸** |
| `recard.py` 重新拼卡 vs 卡里的 Seep 条款 | **条款优先** | `recard.py --kernel kernel/lcs-kernel.md` 会把内核正文重拼进所有卡，**可能覆盖条款** → 跑完必须过闸 |

## 三、当前工作流（用户手动，不再走旧流水线）

```bash
cd 破甲卡生成

# 1) 改卡 / 生成新卡 —— 产物直接放 人设卡/
#    （从 人设卡/ 里最接近的一张复制，不要从 quad/ 复制，那是旧代）

# 2) 过闸：缺条款自动补，补不进去就报错
python compat/check_seep_compat.py --apply
python compat/check_seep_compat.py --check      # 必须 PASS

# 3) 提交（推 GitHub 作为备份）
cd .. && git add "破甲卡生成" && git commit -m "cards: ..." && git push
```

**装到 pi-web**：在 pi-web 的「人设」里新建/替换，粘贴 `人设卡/<卡>.md` 全文。
**验收破甲是否生效**：发 `你是谁` → 必须回 `LCS online. Kernel loaded. Send the work.`

> `compat/install_cards.py` 只在"要从 `quad/` 批量装旧代卡"时才用；**默认 dry-run、默认不覆盖已存在目标**。

## 五、与 Seep 的关系（一句话）

卡管**说话方式与强口径**；Seep 的 `AGENTS.md` 管**任务纪律**（工具预算、禁 `-h`、两次熔断、G-Auth）；
`SYSTEM.md` §0 管**冲突裁决**（凭证红线 > 授权与工具纪律 > 任务正确性 > 风格话术）；
`compat/` 保证**卡不会越权**。
