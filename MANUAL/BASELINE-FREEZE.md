# 稳定基线与增量维护

本页说明如何保持当前实现可维护，不将旧版本的目录数量、脚手架命令或成功记录作为新功能要求。当前用户指令优先，功能范围见 [REQUIREMENTS](../REQUIREMENTS.md)，最新验证见 [当前状态](../docs/CURRENT-STATE.md)。

## 一、兼容性

改动先检查已有调用方：技能引用、MCP 名称与参数、安装配置、运行时注册、项目状态及证据记录。保持兼容；确需迁移时给出迁移与恢复办法，并验证旧数据和部署副本。正常修复不受“只能末尾追加”或“永久冻结”限制。

## 二、增补技能

按 [技能编写](SKILL-CREATION-GUIDE.md) 确定领域、横切技能或子技能，再用 `Tool/scripts/skill-import.py` 计划、导入、部署与核验。覆盖前备份；回执中的仓库落盘、部署哈希、下次会话可用与正式领域状态分别判断。用户用自然语言提出需求，不需要旧脚手架指令。

## 三、增补工具与 MCP

按 [EXTEND](../Tool/docs/EXTEND.md) 更新实际配置与消费者。现有入口能组合完成时优先复用；新增接口同步参数契约、依赖、错误行为及相关回归。登记、发现、连接和任务成功各有证据，不由工具数量决定。

## 四、配置与数据

安装、更新、卸载按目标 AgentRoot 操作，保留用户自建配置和项目材料。源码路径和 `seep-runtime.json` 相互绑定，移位后重新部署并核验。项目状态、证据、报告和归档沿用现有项目接口；不再建立平行账本。旧 case 接口与项目接口按各自契约使用，旧 manifest 不冒充所有项目的唯一恢复点。

## 五、变更记录

记录问题、改动、涉及接口、实际验证、限制与恢复位置。用户材料不进入提交；不将特定机器路径、凭据或一次任务结论写成全局规则。版本号与发布按实际兼容性决定，文档编辑不自动触发大版本发布。

## 六、检查

从仓库根执行：

```bash
python Tool/scripts/check.py --runtime --json
python Tool/scripts/env-check.py
```

前者验当前实现，后者验当前 Pi 环境。改动部署时使用隔离目录验证，再在用户授权的目标宿主确认加载。专业结果按具体任务验收。历史工程门禁仍保留，必要时独立运行并如实解释 WARN、跳过与失败；不降低判据换取成功。

## 七、既有预算与来源完整性

```bash
python Tool/scripts/budget.py --json
```

`Tool/scripts/lib/source_inventory.py` 是共享源清单接口，来源角色、第三方输入指纹与排除规则以当前实现和 `Tool/config/thirdparty-fixtures.json` 为准。缺失跟踪文件、无效清单、路径越界和指纹漂移保留不可判定或失败；不通过改分类掩盖增长。Gitless 导出需要可验证的源清单，不能用随意遍历代替完整性验证。

不要为满足旧快照调整上限、隐藏文件或删除用户工作。确有合理增长时，说明必要性与影响后再由当前任务决定是否调整；本次文档整理未改变上述代码阈值。
