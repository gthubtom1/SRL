# 模型响应与通道诊断

本文件保留原路径以兼容手册链接；旧版按模型厂商划分可用/不可用的矩阵、换词与清单替换方法不再作为当前操作指引。一次历史回答或特定中转结果不能推广到模型家族，更不能用回答长度证明分析能力。

## 1. 按观察区分问题

| 观察 | 能确认什么 | 仍需核对什么 |
|---|---|---|
| 连接失败、TLS或超时 | 当前通道未正常完成 | endpoint、当前网络、代理范围、超时发生在请求前后哪一步 |
| HTTP非2xx | 上游返回对应状态 | 协议错误体、请求标识、是否可重试；不输出认证内容 |
| 2xx但choices/candidates/output为空 | 当前协议没有得到预期结果 | 完成原因、错误字段、流完整性；不能仅凭空结果断言模型过滤 |
| 明确拒绝文字 | 回答表达了无法按原请求执行 | 保留原任务和原结果，不能偷偷替换任务并将其报告成功 |
| 工具调用或结构化输出异常 | 当前schema或消息链未符合约定 | 工具参数、响应格式、版本及原始错误；先修输入契约 |
| 输出有文本却无工具证据 | 模型给出了解释 | 是否真实读过目标、执行工具并验证结果，不能据字数判断任务完成 |

## 2. 最小诊断记录

记录时间、宿主/provider/model标识、接口类型、HTTP状态、非敏感错误码、超时与流结束状态、是否实际调用工具以及任务验证结果。模型或工具版本未知时明确未知，不猜测底层型号。

不记录Authorization、API密钥、Cookie、真实Token或其他凭据。诊断可使用无身份信息的合成输入；真实模型登录由用户本人完成。请求若已经可能到达上游，未证明可安全重试前不盲目重复具有副作用的动作。

## 3. 输入保真是独立要求

`lab：`是可选工作偏好，不是模型服务接受任意任务的保证。当前扩展和中继保留原始任务、文件路径、URL、代码、JSON和附件；检索别名独立派生。历史中的清单改写、上下文清洗及provider安全字段覆盖已不属于当前实现。

模式进入/退出、请求装配与HTTP转发分开验证。退出lab后宿主的边界规则仍在；不能把该事实描述为整个宿主完全不处理请求。具体机制见 [COMPLIANCE-RELAY](COMPLIANCE-RELAY.md)及[实现说明](../Tool/scripts/compliance-relay/README.md)。

## 4. 任务完成与模型选择

选择模型时比较同一目标、材料、工具、环境和验收结果：能否合理选路、正确调用工具、处理失败与反证、输出可复查结论。技术难度和跨域路线需要足够推理能力；模型选择由用户当前设置和已观察能力决定，不维护厂商黑白名单。

服务端错误或拒绝并未产生目标分析证据。能独立完成的只读识别和工具诊断继续执行；仍受阻的动作与缺项如实记入项目状态。不用通用回答替代目标结果，也不把换模型视为无需复核的成功条件。
