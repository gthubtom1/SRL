# 逆向决策失败判据：看到现象就换路

> 用途：把「卡住」变成可执行的换路决策。它是 `Tool/skill/softseep/references/02-failure-criteria.md` 的 KB 版，供不加载 skill 的分析流程直接引用。
> 读法：先找现象，再看判定；判定成立就执行「改走哪条」，不要在原路加码。
> 铁律：换路必须记录「旧路线为什么不通 / 新证据是什么 / 新路线凭什么更可能通」。

---

## 1. 主表

| 现象 | 判定 | 改走哪条 | 代价 |
| :--- | :--- | :--- | :--- |
| 改完补丁立刻崩（0xC0000005/0xC0000374） | 等长/重定位/栈平衡被破坏 | 等长改写；改 trampoline；只改条件跳转 | 需要代码洞与重定位 |
| 补丁后几秒到几十秒才崩 | 跳过必要初始化/守护回写 | 保留原函数体；改判据分支/全局状态 | 需要定位延迟崩溃点 |
| 字符串全乱码/只有少量明文 | 加密/压缩未解 | 先脱壳/OEP 后 dump；再谈字符串 | 脱壳时间不可控 |
| 反编译只有 dispatcher | VM/强平坦化 | 运行期取功能/取载荷；patch 判定点 | 静态结论缺失 |
| 断网即失效，联网恢复 | 服务端权威/心跳覆盖 | 协议层：抓包/中继/端点接管 | 可能只能中继 |
| UI 亮一下又退回 | Service/Updater 回写 | 同时改 UI 读取点与下发解析；阻断 Updater | 要枚举全部进程 |
| 只改 license_type 无效 | 不是激活判据 | 找真正状态字/分支，重建对象地图 | 旧补丁作废 |
| 只改 UI 文案，重启恢复 | 显示层从状态源重渲染 | 改状态源或 IAT Hook 输出 API | 需要控件实测 |
| 补丁后签名/校验失败 | 未重算 checksum/未处理签名 | 重算校验和；明确签名策略；改内存/代理 DLL | 签名剥离影响信任 |
| 补丁写入成功但行为不变 | 版本/基址/执行点错 | 回读字节；核对 SHA256/基址；断点确认命中 | 可能白改一轮 |
| 代码洞跳过去就崩 | 标志位/寄存器/栈对齐破坏 | `pushfq/popfq` + 保存 volatile；确认 16 字节对齐 | 洞变长 |
| `jmp rel32` 跳飞 | disp 按错基址或超 ±2GB | `disp=target-(addr+5)`；远跳 `mov rax,imm64;jmp rax` | 需要更大洞 |
| `call [rip+x]` 调错 | disp 按下一条指令算 | `disp=target-(addr+6)`；反汇编复核 | 容易连带改坏 |
| 注入成功但无模块/无行为 | 位数/依赖/DllMain/反注入 | 手动映射/APC/早启动；先验证空 DLL | 可能触发 EDR |
| 驱动加载失败（0x577/0x241） | 签名/测试签名/安全启动 | 测试签名环境/WHQL/用户态替代 | 需重启/证书 |
| ARM64 参数全错 | 套用 x64 调用约定 | 按 AAPCS64 读 X0–X7/X29/X30 | 重做函数签名 |
| Mach-O 改完被 kill | hardened runtime/codesign | 重签/ad-hoc/测试机/entitlement | 分发不可用 |
| ELF patch `Text file busy` | 运行中替换/RELRO | 停进程；LD_PRELOAD/Frida | 需重启 |
| 一 attach 就退，换调试器仍退 | PEB/API/TLS 检测 | 先识别检测层；ScyllaHide/外部观测；两次就停 | 每次 attach 成本高 |
| 单步几步就退 | 时间差/DRx | 硬件断点/hook 时间函数 | 可能二次检测 |
| 下 `0xCC` 就崩 | 代码段 CRC/int3 扫描 | 硬件断点/外部读/Intel PT | 硬件断点又可能被 DRx 检测 |
| VM 里必退 | CPUID/注册表/设备/时序 | 裸机或改 VM 指纹 | 只改一个键会漏 |
| keygen 生成码被拒 | 归一化/字符集/校验位/签名 | 独立实现逐字符对照；查 CRLF/Base/填充 | 可能发现自引用 |
| 同源 Generate/Verify 通过但客户端拒绝 | 自洽掩盖移植错误/第二校验 | 客户端黑盒测试；找第二校验点 | 可能转 patch |
| 公钥替换后旧签名仍过 | 多副本/运行时解密/哈希校验 | 找全部副本；patch 验签返回值 | 可能触发完整性自检 |
| 端点接管请求落到旧进程 | `SO_REUSEADDR`/旧监听器 | 换端口/日志名；先杀旧进程；绑 0.0.0.0 | 需清理环境 |
| 回放金样后静默退出 | 会话绑定 | 透明中继；不要猜字段 | 只能握手不能伪造 |
| manifest 偏移对但哈希不对 | 其他步骤改了文件/清单未更新 | 以实际文件重算；清单版本化；回滚重打 | 旧证据作废 |

---

## 2. 三条熔断

1. 单条路径 ≤3 轮无确定性进展 → 换正交路线（静态→动态→内存→协议→资源）。
2. 内存补丁累计崩 2 次 → 停手，转协议层/代理 DLL/文件补丁。
3. 动态 attach 被反调试打掉 2 次 → 先过反调试，不做第三次裸 attach。

## 4. 边界

- 本表是决策表，不是穷举；新现象应追加行。
- 「代价」是估算，不是承诺。
- 旧证据必须保留；禁止删除失败记录。
- 与 skill 版 `02-failure-criteria.md` 同步维护；两处冲突时以 skill 版为准，并回写本页。
