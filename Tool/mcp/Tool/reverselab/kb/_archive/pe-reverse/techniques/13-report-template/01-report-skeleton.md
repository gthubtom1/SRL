# 逆向测绘报告骨架（可复用）

> 用途：把分析结论落成可复核报告；每一节都要能指到证据文件/命令/哈希。
> 原则：先事实后判断；证据分级；限制与未验证项必须写。

### 范式库补充 D —— 复现报告模板（可复用）

```markdown
# <目标> 客户端离线鉴权体系 —— 逆向测绘报告 (CWE-602 走查基线)

## 1. 目标指纹
  路径 / MD5 / SHA256 / ImageBase / 映像大小 / 签名状态 / 版本

## 2. 全局对象地图          ← 表：全局符号 | 取得函数 | 语义 | 关键字段+偏移
## 3. 完整鉴权链路          ← ASCII 流：输入 → 解密 → 校验 → 状态落地 → 消费者
## 4. 编解码 / 密码学原语   ← 表：RVA | 函数名 | 语义（含自洽验证式）
## 5. 存储布局              ← 注册表 / 配置文件 / 许可文件，逐值名标注语义
## 6. 外部依赖守门人        ← 缺失即退出的关键模块
## 7. 微创热补丁清单        ← 表：RVA | 原始字节 | 补丁字节 | 语义（分方案 A/B/C）
## 8. 闭环验证结果          ← 写入成功率 / UI 落地 / 签名完好性
## 9. CWE-602 根因分析      ← 逐条 + CWE 编号
## 10. 纵深防御整改建议      ← 加载期 / 运行期 / 逻辑层 / 服务端
## 11. 证据文件索引         ← 截图 / 日志 / dump / CSV 落地路径
## 12. 限制与未验证项       ← 残差风险，必须写
```

**证据分级标签（沿用仓库强度标签规则）**：
- `[observed]` —— 命令已跑过且有输出
- `[inferred]` —— 由观测推导，步骤本身未执行
- `[unverified]` —— 假设或转述，未在此复现

## 每节写法与判据

| 节 | 必须写什么 | 可机检判据 | 常见失败 |
| :--- | :--- | :--- | :--- |
| 1 目标指纹 | 路径代号、SHA256、ImageBase、体积、签名、版本 | `sha256sum` 复算一致 | 只写文件名，不写哈希/版本 |
| 2 全局对象地图 | 符号、取得函数、语义、关键字段+偏移 | 至少一个偏移能在反汇编/动态断点复现 | 把猜测字段写成确定 |
| 3 鉴权链路 | 输入→解密→校验→状态落地→消费者 | 每跳有函数/RVA/字符串证据 | 只画框图不落地址 |
| 4 编解码/密码学 | RVA、函数、语义、自洽验证式 | 测试向量/自洽式可复算 | 把「有 AES 常量」当「算法已还原」 |
| 5 存储布局 | 注册表/配置/许可文件，逐值名+语义 | 读回值/路径存在 | 把缓存当权威 |
| 6 外部依赖守门人 | 缺失即退出的模块/服务 | 断网/删文件复现 | 漏掉 Updater/Helper |
| 7 微创补丁清单 | RVA、原始字节、补丁字节、语义、方案 A/B/C | `patch-verify.py` 通过 | 无原始字节/无回滚 |
| 8 闭环验证 | 写入成功率、UI 落地、签名/哈希 | 窗口文本/返回码/存活时长 | 只写「成功」无输出 |
| 9 CWE-602 根因 | 逐条+CWE 编号 | 每条对应证据 | 泛泛而谈「客户端校验不安全」 |
| 10 纵深防御 | 加载期/运行期/逻辑层/服务端 | 每条有修复动作与残差风险 | 只写「加壳/加签名」 |
| 11 证据索引 | 截图/日志/dump/CSV 路径 | 路径存在、哈希一致 | 引用本机绝对路径 |
| 12 限制与未验证 | 残差风险、未跑项、版本边界 | 与正文一致 | 省略未验证项 |

---

## 证据分级标签

- `[observed]` —— 命令已跑过且有原始输出（日志/JSON/hex/窗口文本）。
- `[inferred]` —— 由观测推导，步骤本身未执行；必须写推导链。
- `[unverified]` —— 假设或转述，未在此复现；不得写成结论。

---

## 交付前自检

1. 每个 RVA/偏移是否绑定 SHA256 与版本？
2. 每个结论是否有两条独立证据？
3. 补丁是否有 manifest、回滚、前后哈希？
4. 是否删除了本机绝对路径、真实凭据、可反查产品名？
5. 限制与未验证项是否写清？

**失败判据**：任一节无法指向证据文件/命令 → 该节降级为「未验证」，不得写「已确认」。

**边界**：报告骨架不替代技术卷；判据、失败判据、补丁工程分别见 `01-criteria.md`、`02-failure-criteria.md`、`09-patch-engineering.md`。
