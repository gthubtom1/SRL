### 范式库补充 A —— 漏洞检测通用流程（四步法）

> 上述 A~J 十型回答“**怎么破**”，本节回答“**怎么找、找到几个、怎么复现**”——
> 三者合起来才构成一份可交付的 CWE-602 走查。

| 步 | 动作 | 判据 / 产物 |
| :--- | :--- | :--- |
| **D1 资产指纹基线** | 记录 MD5/SHA256 · ImageBase · 映像大小 · 签名状态 · 版本号 | 无此基线，后续所有偏移**不可复算**；换版本的产物不可比较 |
| **D2 攻击面枚举（八面）** | 沿 8 个面逐面扫：① 加载期（DLL 搜索顺序 / KnownDlls）② 内存期（可写可执行页 / 缓解策略）③ 调用期（函数入口完整性 / CFG）④ 存储期（注册表 / 配置 / 许可文件）⑤ 网络期（端点 / 心跳 / 黑名单）⑥ 壳期（熵剖面 + 指纹）⑦ VM期（VM stub 识别）⑧ .NET期（IL 加密 / 运行时注入） | 产出**脆弱面清单**（每面至少一条判据） |
| **D2.5 关键判据三问（决定 keygen vs patch）** | 在 D2 与 D3 之间必答：<br>**① 自引用校验？** 校验值是否在载荷自身内部（如 `sha384(p)==p["key_hash"]`）→ 命中则 keygen 死路<br>**② 公钥存储形式？** 明文 / 密文 / **可逆密文**（keystream 可推导）→ 可逆则可走公钥替换 Keygen<br>**③ RSA 模数可分解？** n<1024 弱但未必可分解（pollard rho/sympy factorint）→ 可分解才走算号 | 产出 **四分决策**：补丁 / 算号 / 公钥替换 / 不可行 |
| **D3 决策点收敛** | 从脆弱面下钻到具体 **RVA / 函数 / 字节序列**：<br>· 全局对象地图（状态对象 + 偏移）<br>· 鉴权链路 ASCII 流（输入 → 解密 → 校验 → 落地）<br>· 批量模板扫描（如同一 `mov dword ptr [rsi+120h], imm32` 会在多处出现） | 产出**补丁点候选表**（附原始字节） |
| **D4 可利用性判定（四分决策）** | 由 D2.5 三问导出：</br>· **patch 路线**——单点/多点补丁（VM不可逆/自引用/RSA不可分解）<br>· **算号路线**——可逆算法或可分解弱模<br>· **公钥替换 Keygen**——公钥可逆密文内嵌<br>· **不可行**——服务端权威+无本地判定点，明说 | 产出**路线决策** + 残差风险 |

**五面扫描的对应工具**：

| 面 | 工具 / 手段 | 典型发现 |
| :--- | :--- | :--- |
| 加载期 | 导入表 + 搜索顺序分析 | `version.dll` / `sentry.dll` 可劫持 |
| 内存期 | `Get-Process`/节区属性 + 缓解策略查询 | 未开 `ProcessDynamicCodePolicy` |
| 调用期 | IDA 反编译 + Inline Hook 探测 | 函数头无完整性校验 / 无 CFG |
| 存储期 | 注册表监控 / 配置文件对比 | 特权状态落地字段 |
| 网络期 | 字符串扫端点 + 抓包 | 心跳 / 黑名单 / 下发通道 |
| **壳期** | 节表熵剖面 + 壳指纹表 | MPRESS/UPX/Themida 等可脱/不可逆判定 |
| **VM期** | Ghidra headless + VM stub 识别（反编译为不可执行伪码） | EXECryptor/Themida VM 静态不可逆，需旁路 |
| **.NET期** | ilspycmd + Harmony `GetTokenFor` Hook + dnlib ildump | 方法体 IL 加密 / 运行时注入，需动态解壳 |
| **密码学期** | 字符串扫 `RSA1`/Ed25519 公钥 blob + 模数位宽检测 | 公钥明文/密文内嵌；n<1024 弱模待分解 |
| **自引用期** | 反编译校验函数，查校验值是否来自载荷字段 | `sha384(p)==p["key_hash"]` 类自引用 → keygen 死路 |

### 范式库补充 C —— 复现路径归档（九型）

> 复现的**最低标准**：静态结论可由命令复算，动态结论有可观测证据（屏幕 / 日志 / 哈希）。
> 仅有“注入成功”日志而没看屏幕，不算复现成功。

#### C-1 · 项目 A 型复现

```
【基线】记录目标 MD5/SHA256/版本号；备份原 EXE
【静态】IDA 加载 → 定位授权判定函数 → 确认唯一返回值出口
【补丁①】0x66FC95  原始 → 34 字节写入（全局状态字段 + 跳转）
【补丁②】0x66DB7B  原始 66 B8 xx xx → 66 B8 FF FF 90   (mov ax,0FFFFh; nop)
【载体】代理 version.dll + DllMain(DLL_PROCESS_ATTACH) → VirtualProtect → memcpy → 还原保护属性
【验证】启动 → 关于对话框展示期望授权信息（截图留证）
【反证】原版同条件启动仍显示未授权（对照）
【签名】宿主 EXE 磁盘哈希不变 → Authenticode 仍有效
```

#### C-2 · 项目 B 型复现（三条路径）

**路径甲：单文件 winhttp.dll 裸桩极简注入（⭐ 强烈推荐，终极形态，保签名，免改名）**
```
【基线】目标四大 EXE 指纹核验；备份
【载体】单一 winhttp.dll 放入主目录（原生 64 位裸汇编桩 jmp rax 桥接系统 92 个 API，免 _orig 附属文件）
【自动分流】DllMain 看门狗线程 GetModuleFileNameA 判定宿主：
        • Main (30点)    : 广告闸门 NOP(0x12ADA3) + 试用Banner跳转(0xCEF5DF) + 
                           网络响应6点(2099到期/VIP/5设备) + 缓存读写A/B(20点) + UI直返2点
        • Service (18点) : 缓存解析A/B(10点) + 序列化(5点) + is_valid_infos置真(2点) + 端点本地化
        • Remote (4点)   : 启动入口ret阻断推流双进程 + 短路isCurrentSessionRemoteSession
        • Updater        : 自动触发 ExitProcess(0) 安全自毁，截断云端静默升级与版本覆盖
【验证】免广告 + 永久 VIP (2099-12-31) + 无后台推流常驻 + 终结版本更新覆盖
```

**路径乙：双 DLL 传统转发路径（v12.0 早期方案）**
```
【载体】sentry.dll（169 个符号转发 → sentry_orig.dll）+ version.dll（17 个符号转发 → version_orig.dll）
【机制】重命名原版库，DllMain 跨进程判断加载补丁集
```

**路径丙：改 EXE 本体（52 点十六进制硬改，会破坏签名）**
```
Main 30 点 + Service 18 点 + Remote 4 点
每点先核对“原始字节” → 匹配才写入“修补字节”
```

#### C-3 · 项目 C 型复现

```
【基线】记录 MD5/SHA256；ImageBase 0x140000000；备份
【静态】定位三张全局表（状态对象 +0x120 / 注册凭据结构体 / 产品配置对象）
        复算版本号掩码：plain = ((2*(v & 0xD5555555)) | ((v>>1) & 0x55555555))
        验证 T(152)=100 ✔  T(980)=1000 ✔  T(6944)=10000 ✔
【补丁 A｜最小风险 4 字节】
        0x13175D  75 36 → 90 90    NOP 掉 PRO 比对中途退出
        0x13176B  75 28 → 90 90    NOP 掉 PRO 末位比对退出
        ⇒ 恒定走 0x13176D，state+0x120 = 0x3D4 ⇒ 解码 1000 Professional
【补丁 B｜升 Enterprise 12 字节】
        0x131773  D4 03 00 00 → 20 1B 00 00   落盘值 980 → 6944
【补丁 C｜放行注册 3 字节】
        0x1347E0  55 8B EC … → 31 C0 C3      xor eax,eax; ret ⇒ 黑名单恒定“未拦截”
【依赖】必须先保证授权库 DLL 可加载，否则进程早期 ExitProcess
【载体】代理 version.dll + version_patch.ini（文案外部可配）
【验证】① 主窗标题变更为企业版
        ② 注册提醒广告控件（plain==100 才显示）自动隐藏
        ③ 菜单栏出现企业版专属功能且无弹窗
        ④ Watchdog(+500ms) 轮询确认代码段未被二次篡改
【签名】宿主 EXE 与授权库 DLL 磁盘哈希均不变
```

#### C-4 · 项目 D 型复现（三策略合一）

| 来源 | 哈希状态 |

**处置**：以**实际目标 exe 现场实测哈希**为准，先确认属于哪个版本，再选用对应点位表。两份归档的哈希在此不列出，防止据哈希反查目标。

## 决策与统计使用失败判据

| 现象 | 判定 | 改走哪条 |
| :--- | :--- | :--- |
| 只查「可算号？」不看自引用/公钥/RSA | 漏掉 D2.5 三问 | 逐条回答自引用、公钥存储、模数可分解性 |
| 统计表当成漏洞评分 | 统计是经验分布，不是目标结论 | 回到单目标证据；统计只用于排序假设 |
| 复现路径只写「运行脚本」 | 缺输入/判据/证据 | 按 C-1..C-9 的命令+原始输出+哈希重写 |
| 归档哈希不一致仍混用 | 版本不明 | 以现场实测 SHA256 为准，先定版本再选点位 |

**边界**：统计与复现路径来自历史案例；换目标/换版本必须重跑判据。
