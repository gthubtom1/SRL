【分析顺序 · 硬门（违反 = 本轮作废）】
1. 旧报告 / 上一轮结论**只能当猜测**：读了别人的结论 ≠ 你验证过。
2. 报三行之前，必须自己实测这五项（缺一项就别报 GATE）：
   P1 进程能不能到**第一个窗口**（双击 与 程序拉起 分开测，结果可能不同）
   P2 运行时是否**动态**加载 winhttp / wininet / ws2_32 / bcrypt（看加载器，不看 import 表）
   P3 一次出站观测：有没有 DNS/TCP、几个请求、明文还是 TLS
   P4 断网对照：断网重跑，表现变化 = 服务端在场
   P5 关键资源与钥匙：文件里就有，还是授权成功后才产生
3. 每条结论后写证据编号（例：`GATE = 服务端权威 [P2,P3,P4]`）；没编号的一律是"待验"，不许当前提。
4. **M0 全貌没出来之前，不许产出任何交付物**：第一个写入的文件只能是事实账，不能是 build.py / 成品目录。
5. 每 20 分钟写一次进度账：`已证 N / 待验 M / 下一步 / ETA`；连续两次没有新增证据 → 停手重判型，并主动找一条**能推翻当前结论**的证据。

【自适配旁路形态 · 按 RUNTIME 选（选副作用最小的）】

【硬约束】
