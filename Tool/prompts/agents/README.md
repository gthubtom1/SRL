# 子代理定义（agents）

由 `setup/install-pi.ps1` 部署到 `~/.pi/agent/agents/*.md`。

| 角色 | 职责 | 为什么保留 |
| :-- | :-- | :-- |
| `seep-stage` | 按阶段契约只做一节任务，产物落盘、只回结构化回执 | 主对话负责判断与签字；写/改/跑这类活外包出去，避免污染主上下文 |
| `seep-verify` | 只跑判据给 proven/refuted；有 bash（要能跑判据）但无 write/edit/mcp | **验证者不能复用实施者**：同一个会话验自己写的东西 = 没验。原先没给 bash → 物理上跑不了任何判据，等于空角色（2026-10-25 修） |
| `seep-forensics` | 只做一次取证动作，只回路径与摘要 | 大 dump / 抓包不塞进主上下文 |

## 已退役（留档在 `_archived/`）

| 角色 | 为什么退役 |
| :-- | :-- |
| `seep-manager` | "读台账 / 派活 / 问人 / 判过不过"本就是**主对话**的职责；再套一层组长只会让一次任务多两次交接。其契约 `contracts/MANAGER-MODE.md` 早已归档（现在只剩 `contracts/_archived/` 那份），角色却仍指向 `contracts/MANAGER-MODE.md` = 死指针 |
| `seep-stage-shell` | 与 `seep-stage` 是同一角色两份（工具集相同、提示词几乎逐字相同），保留会造成"派给谁"的随机性 |

## 判定口径（以后要加角色时先过这一关）

一个角色只有在满足**下面任一条**时才有存在价值，否则用主对话或内置 `general-purpose`：

1. **隔绝上下文**：它会产生大量中间产物（dump、抓包、逐文件扫描），塞进主对话会挤掉判断力。
2. **独立性要求**：它必须与实施者**不共享会话**才知道真相（验证、复核）。
3. **权限收窄**：它需要比主对话更少的工具（如无 write / 无 mcp）才能真正只读。

不满足任何一条的"角色"，本质是"主对话换个名字"。
