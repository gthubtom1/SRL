# DECISION-LOOP —— 决策环契约（"像真人一样想"的可执行版）

> 这份文件不是"要求模型像专家一样思考"（那种话是第 80 条没人执行的规则）。
> 它定义**每一步必须留下什么痕迹**，以及**闸怎么检查它**。想不出来就过不了闸。

---

## 1. 四步环（每一步都有产物，缺一不算走完）

```
观察 ──► 假设 ──► 决策 ──► 验证 ──┐
  ▲                                │
  └────────────────────────────────┘
```

| 步 | 要回答的 | 产物 |
| :-- | :-- | :-- |
| **观察** | 我看到了什么？（命令 + 输出片段） | 证据条目（带 `how`） |
| **假设** | 这说明什么？有几种可能？ | 1–3 条候选解释，每条附"能验证它的最小观测" |
| **决策** | 我选哪条路？为什么不是别的？ | **路线 + 理由 + 被放弃的选项及放弃依据** |
| **验证** | 做了什么观测？结果支持还是推翻假设？ | 结果 + `proven / refuted / 仍待验` |

**硬要求**：`决策` 步没有"**被放弃的选项 + 放弃依据**" → 该阶段不过闸。这条是整份契约的核心。

---

## 2. 观测排序：判据是「信息增益 ÷ 风险」，不是"先静态后动态"

常见的错误顺序是"先静态，拿不到再动态"。真实判据是**同样的时间花在哪一步能拿到最多可验证信息，而且尽量可逆**。

| 档 | 观测 | 风险 | 什么时候最划算 |
| :-- | :-- | :-- | :-- |
| **O0 只读** | 文件类型 / 架构 / 节表与熵 / 导入表 / 字符串 / 资源 / 签名 / 版本信息 | 无（不执行目标） | 永远第一步 |
| **O1 元数据外扩** | 文件时间线、同目录依赖、安装包结构、配置默认值 | 无 | 判断"这软件是什么形态" |
| **O2 裸启动（只看现象）** | 双击 / explorer 启动，不挂任何东西：能不能到窗口、有没有报错码、活多久、退出码 | 低（但会在磁盘/注册表留痕） | O0 拿不到关键信息时（例如**磁盘侧全部 `RawSize=0`，静态没东西可看**）|
| **O3 外部观测** | 进程树、子进程、开出的文件句柄、出站连接、临时文件——**不修改目标** | 中（会改变时序但不改代码） | 想知道"它连了谁、写了什么" |
| **O4 附加/注入** | 调试器、Frida、IAT hook、断点、改内存 | 高（**会改变目标行为**） | 前三档都不足以定性时 |

**两个必须记住的事实（来自实测，不是理论）**：

1. **磁盘侧可能是空的**：有些壳让所有节 `RawSize=0`，磁盘上根本没有原始代码 → 此时 `O0/O1` 拿不到业务信息，**尽早进 `O2` 的信息增益最高**。别在静态上耗 20 分钟。
2. **早期附加会改变行为**：实测出现过"一 attach 它就不发网络请求"——那时你观察到的现象**本身就是假的**。所以 `O4` 之前的结论都要标"未受附加影响"，`O4` 之后要重跑一次 `O2` 对照。

## 3. "规避检测"的正确写法（它有反作用）

规避动作本身往往就是"改变行为"，很容易把你刚观察到的现象作废。规则：

1. **先观测不触发检测的层面**（O0–O2 通常不触发）；
2. 只有在"检测明确阻断了我需要的观测"时才对抗（O3–O4 层面）；
3. **每次对抗都要登记一行**：`我做了什么 → 目标的哪个行为变了 → 所以哪条结论要重验`。

不登记 = 后面所有基于它的推理都不可信。

## 3bis. 问人只有一种方式：对话内 A/B/C（D…），用户回字母

**不调用任何弹窗类工具**（`ask_user_question` 那类）。三个硬伤：

1. 选项只能 2–4 个、每项 ≤60 字 —— 四要素长卡塞不进去；
2. 把"等人"变成一次工具往返，往上下文里塞结构化噪声；
3. 用户要的就是"对话框里列 A/B/C，我回一个字母"。

### 标准格式（原样贴进对话）

```
【需要你选】<一句话：卡在哪>
  A  <具体动作>
  B  <具体动作>
  C  <具体动作>
直接回 A / B / C

我在做什么：<监控什么>
你操作期间我保证：不动鼠标键盘 / 不改系统设置 / 不主动联网
我拿到什么：<这一步产生什么证据>
```

### 机制保障（不是靠记）

| 环节 | 由谁保证 |
| :-- | :-- |
| 拦掉弹窗工具 | `cmd-guard` 对 `ask_user_question` 直接 block，并把上面的正确格式作为 reason 回给模型 |
| 卡落盘可复核 | `case_state.py ask --case <case> --stuck "..." --option "A ..." --option "B ..."` → 写 `case/ask/<ts>.md` |
| 等待态可恢复 | 同上，写 `state.awaiting_human`（含 since / card / options） |
| 回执 + 断点续跑 | `case_state.py ack --case <case> --ack A` → 记 `ack` 并写 `next_action` |

**验收判据**：进入等待后，`state.awaiting_human` 非空；用户回字母后 `ack` 落值，`next_action` 更新；
整个过程**没有一次 popup 工具调用**。

## 4. 决策日志（写进 `case/decisions.md`，闸会读）

每走完一次环，追加一段：

```markdown
### D07 · 2026-10-23 14:12 · 阶段 O2 后
- 观察：explorer 启动后 3 秒内进程退出，退出码 0x451B10；同一份文件用脚本拉起则弹出"文件已损坏"
- 假设：① 磁盘完整性自检（改过/被复制过就打掉）② 启动方式被父进程检测 ③ 两者都有
- 验证计划：用未改动的原件 + explorer 启动，看是否仍退出（区分 ①②）
- 决策：走"内存路线"作为主假设；**放弃"磁盘补丁"** —— 依据：任一位改动即被拦，且拦在校验阶段（早于业务代码）
- 结果：原件用 explorer 启动正常 → ①成立（改过的文件被打掉），②不成立
- 结论：F-003 proven（磁盘面被完整性监视）；下一步 O3 观测出站
```

**闸检查三件事**：`观察` 有证据 / `决策` 有"被放弃的选项 + 依据" / `结果` 写明了 `proven|refuted|待验`。

## 5. 快车道（简单项目不要走仪式）

一次环走完，如果满足下面全部条件，**直接进实施，不做多轮反思**：

- 画像卡六字段全部明确（没有 `?`）；
- 交付壁垒为空或已评估为"可绕"；
- 首选路线的失败判据已经预写。

否则才进"深入分析"的多轮环。**反思是用来防跑偏的，不是用来加戏的。**

## 6. 子代理切片契约（一节一节做，主对话回访）

| 项 | 规定 |
| :-- | :-- |
| 切法 | 一次只给**一节**任务，**≤10 次工具调用**；必带"产物路径 + 判据" |
| 不切的情况 | 整活 <5 次工具调用 → 主对话自己做，别派 |
| 回执 | 只回结构化摘要：结论 / 证据 ID / 产物路径 / 放弃的路 / 下一步 |
| 禁止 | 子代理**不得自行改路线**；发现路线不对 → 停下回执里写"建议换路 + 依据" |

### 主对话回访：固定四问（不是"看看有没有偏移"）

1. **你现在的结论是哪一条？证据 ID 是什么？**
2. **你放弃了哪些路，为什么放弃？**
3. **下一步是什么，预计几次动作？**
4. **有没有和我给的判据冲突？**

任一问答不上来 → 立刻收窄任务或换人，不要让它继续跑。

## 8. 管理型主对话（Manager Mode）—— 全程适用，不只分析阶段

### 8.1 一句话

主对话 = **组长**：只读、只判断、只派活、只问人。**它不干活。**
可机检的判据：主对话的工具调用里，**写盘类与执行类 = 0**。

> 为什么必须机检：靠「要求它别干」就是第 80 条规则；**把工具拿掉**才是机制。

### 8.2 主对话只允许四类动作

| # | 动作 | 用的东西 | 边界 |
| :-- | :-- | :-- | :-- |
| 1 | **读台账** | `case/facts.jsonl`、`case/decisions.md`、子代理回执 | 只读 `case/` 下的状态文件 |
| 2 | **写决策** | 追加一段 `decisions.md`、写一张 `ask/<ts>.md` | 只写这两类文件，不改源码、不改产物 |
| 3 | **派活** | 子代理（见 8.3） | 一节一任务，带产物路径 + 判据 |
| 4 | **问人** | 对话内 A/B/C | 见 §3 的 ASK 规格 |

**不开放给主对话的**：`bash`、写任意文件、`edit` 源码、直接调 MCP 工具。

### 8.3 三类子代理（profile，按需新建，不必是同一个）

| profile | 干什么 | 工具面 | 回执上限 |
| :-- | :-- | :-- | --: |
| **阶段执行器** | 按当前阶段契约做**一节** | 只给该阶段允许的工具 | ≤2KB |
| **取证器** | 单一取证动作（dump / 抓包 / 字符串 / 截图） | 只给该取证需要的 1–2 个工具 | ≤1KB + 产物路径 |
| **验证器** | 跑判据，给 `proven / refuted` | 只读 + 判据脚本 | ≤500B |

**子代理不得自行改路线。** 发现前提不成立 → 停下，回执写「建议换路 + 依据」。
**验证器不复用实施者**：自己验自己等于没验。

### 8.4 回执必须带「证据指针」

不能只有结论。每条结论都要给：产物路径 + 用了什么命令 + 行号或偏移。
原因：主对话看不到子代理的上下文，**只有指针才能抽查**。

> **主对话对每个回执至少抽 1 条证据复核**（真的打开文件看一眼）。不抽检 = 盖章。

### 8.5 切片纪律

- **顺序为主**：逆向类任务是强依赖（第 N 步靠第 N-1 步的结论），不并行。
- **只有互不依赖的取证件可并行**（例：同时抓包 + 读配置）。
- 一节 **≤10 次工具调用**；整活 **<5 次动作**就让主对话自己做（快车道，别浪费一整个前缀）。
- 一节结束必落 `decisions.md` 一段（四步环）。

### 8.6 成本真相（不要自我欺骗）

| 指标 | 单线程 | Manager 模式 |
| :-- | :-- | :-- |
| 主对话上下文峰值 | 168k（实测） | 目标 ≤40k |
| 压缩次数 | 13 次（实测） | 目标 ≤2 |
| **总 token** | — | **可能不降反升**（每个子代理都背一次基座 + 自己的探索） |
| 换来什么 | — | 不遗忘、可纠偏、失败可定位到某一节 |

**所以 Manager 模式的收益是「保真」，不是「省钱」。** 要省钱靠模型分层（判型用强模型、搬运用快模型），不靠切片。

### 8.7 四个已知失败模式（提前认领）

| 失败 | 对策 |
| :-- | :-- |
| 交接丢信息（回执太薄） | 固定 schema + 证据指针 + 抽检 1 条 |
| 串行变慢 | 只并行互不依赖的取证；一节任务不要切太碎 |
| 子代理漂移 | ≤10 动作 + 四问回访 + 前提不成立就停 |
| 主对话看不见无法核查 | 保留只读工具 + 每回执抽检 |

### 8.8 跳领域也成立吗：成立

变的只是 **阶段契约的内容** 和 **取证器用的工具**；不变的是四件事：
主对话四动作 / 回执 schema / 切片纪律 / 四问回访。
→ 所以 APK、网站、插件、固件、协议都能用同一套“组长 + 一节一节”的结构。
