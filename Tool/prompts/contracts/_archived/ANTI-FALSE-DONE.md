# ANTI-FALSE-DONE —— 反"假完成"协议（双用途）

> **这份文件有两个用途，必须同时成立：**
> ① 审 **Seep 自己**时用它（我们已经栽了很多次）；
> ② 以后**用 Seep 做任何项目**时，把同一套协议作为**交付门**强制跑（否则同样的坑会在每个项目重演）。
>
> 它不是"检查清单"，是**六种已被实证的失败模式 + 五条能打红的检查**。
> 出处：真实工程社区的求助/复盘（r/vibecoding、r/LLMDevs、r/programming、SO、GitHub `unreached`）+ 经典 path coverage 理论。见 §6。

---

## 1. 六种"看起来完成、实际有 bug"的失败模式

| # | 模式 | 一句话 | 我们的实例 |
| :-- | :-- | :-- | :-- |
| **F1** | **正确性幻觉** | 代码/产物语法干净、符合模式、能编译、通过测试，审查时像模像样；问题藏在**内置假设**里，读看不出来 | 45 项门禁全绿，真实会话 0 交付 |
| **F2** | **一致性 ≠ 对应性** | 测试验证"代码符合我写的测试"，生产验证"代码符合现实"。**两者是不同性质** | 自检脚本全过，真实目标跑不通 |
| **F3** | **写的人也是审的人** | "模型写了协定的两半"——实现和测试共享同一个错误假设 | **我写方案、我审方案、我给结论** |
| **F4** | **静态审查看得见代码，看不见行为** | agent 和审查者都在"读"，没人"跑 + 看轨迹" | 我读代码跑自检，从不看 167 次调用的会话轨迹 |
| **F5** | **Unreached：存在、正确、没有任何入口到达它** | 不是编译器死代码，是**接线没接** | `mcp__x64dbg` 存在、端口在听、**工具不在表里** |
| **F6** | **组合路径才出缺陷** | 单元素都对，交互序列错。覆盖率要看**路径**不是函数 | 单个工具都能用，串成一条链就断 |

## 2. 五条硬检查（每条都必须能"打红"）

### C1 · 三问自证（任何"完成"声明前必答）

| 问 | 答不上来 = 不算完成 |
| :-- | :-- |
| **谁触发？** | 在**真实执行路径**上，哪一步、由谁触发它？ |
| **怎么知道生效？** | 一个**可观测**结果（不是"文件在"、"进程在"、"端口在"） |
| **失效会看到什么？** | 一个负例现象。**说不出 = 没做过 = 不算验证** |

### C2 · 负例必须打红（每个断言至少一次故意破坏）

打不红的检查**一律删除或重写**，不许留着占绿灯。
（我们实测过：`cmd-guard` 在子代理里连老的盘根扫描规则都不拦 —— 只跑主对话就永远发现不了。）

### C3 · 走一条真实路径，不测孤立函数

路径 = **话术 → 路由命中 → 技能加载 → 工具取用 → 执行 → 产物 → 验收**，逐环问 C1 三问。
任何一环"答不上来"就是断点。**x64dbg 断在第 4 环**。

### C4 · Unreached 扫描（声明了却没入口）

对每一项"能力/工具/技能/脚本/门禁"问：**哪条真实入口能到达它？**
一个都指不出来 → 它是 unreached，**不许写进 README / 手报 / 汇报**。

### C5 · 独立性（写的人不审自己）

- 实施者与验证者**分开会话**（`seep-verify` profile 故意没有 `write`/`edit`）；
- 审查者**只读产物 + 轨迹**，不读作者的结论；
- 外部盲审必须"不知道我们的方案"（否则只是复核）。

## 3. 交付时"必须附上"的三样（缺一不许说完成）

1. **见证物**：用户自己能独立复核的东西（截图/报文/可启动产物/可重跑命令）。
2. **未验证清单**：这一轮**没验证**什么、为什么。**只写通过项的汇报视为未完成。**
3. **负例记录**：为了证明检查是真的，你故意破坏了什么、看到什么变红。

---

## 4. 这套东西在 Seep 里落在哪（两侧对照）

| 检查 | 审 Seep 自身（仓库级） | 用 Seep 做项目（项目级） |
| :-- | :-- | :-- |
| C1 三问 | 每个 preflight 项都要有负例 | 每个阶段闸前，对当前结论问三问 |
| C2 负例 | `Tool/scripts/gate.py`（逐包真跑 witness） / `Tool/scripts/gate.py --all`（逐包判据） 自带破坏用例 | 交付前故意做一个坏产物，验收必须拒 |
| C3 真实路径 | `Tool/scripts/gate.py --all`（逐包判据） 逐叶走"话术→产物"六环 | 每个 case 走一条完整路径并留轨迹 |
| C4 unreached | 扫"声明了但没有路由/没有调用方"的能力 | 扫"技能里提到但流程里没有一步用到的工具/脚本" |
| C5 独立性 | 外部盲审（cleanroom）+ 子代理分离 | 验证器 profile 独立于实施者 |

**关键**：项目级不是"另做一套"，而是**同一份协议 + 同一批脚本，换个根目录跑**。

## 5. 为什么"再写更多规则"解决不了它

规则的执行率我们已经实测过：79 条强制语句 → 关键动作执行 0 次。
所以本协议**只允许两种落点**：

- **能写进脚本的** → 进 `Tool/scripts/`（`Tool/scripts/gate.py`（逐包真跑 witness） / `Tool/scripts/gate.py --all`（逐包判据） / `accept`），带负例；
- **写不进脚本的** → 进**阶段契约**（`SKILL.md` 头部 4 行），由闸检查产物。

**这里只认两种写法；写成"请注意要仔细验证"这类句子。** 那种句子是本协议要消灭的对象。

## 7. 一句话

> **"完成"不是"我检查过了"，而是"我说得出谁触发它、怎么看见它生效、故意弄坏时它怎么变红"。**
> 说不出这三样，就还没完成 —— 无论有多少绿灯。
