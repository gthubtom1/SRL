# 模板 · final（交付与验收）

**这份模板用来干什么**：把「做完了」变成「能证明做完了」。上游闸只认两样东西：
**功能**是否全通，**验收**是否有可跑的判据。所以本模板先固定验收清单（每条一眼可判真伪），
再要求逐条贴实测输出；凡是没跑过的条目，一律标「未跑」，不许拿「没跑过也说得通」的口气顶替实测。

## 1 结论（≤3 行：结论等级 / 到哪一步 / 回执草稿）
- 结论等级：done / partial / blocked（按验收清单实际勾选数决定，不按感觉）；勾选数 X / 10
- 到哪一步：<只能看懂结构 | 能改到能用 | 能完全自己接管 | 现在做不了>
- 回执草稿：<三行内说清「交付了什么、怎么验的、还差什么」>；没跑过的条目一律标「未跑」

## 2 已确认（每条：客户能听懂的一句话 + 证据 ID + 强度：强 / 中 / 弱）
- <客户能听懂的那句话>（`E-001`；强：同输入同输出可复现，命令与输出都能贴）—— 实测回执见第 9 节同编号条目
- <客户能听懂的那句话>（`E-002`；强：两路独立验证一致，不只是重复跑）—— 实测回执见第 9 节同编号条目
- 勾了却没有实测那行的条目不算证据，写进第 3 段。

## 3 仍未知（每条：未知什么 + 为什么未知 + 缺什么才能知道）
- <未知什么>｜为什么未知：<环境限制 / 证据缺口 / 授权没给>｜还缺：<补什么才能知道>
- <未知什么>｜为什么未知：<同上>｜还缺：<同上>

## 4 下一步（省事路线 / 彻底路线 / 不建议做的事，各一条）

- 不建议做：<哪条路会白费或越界，为什么>
