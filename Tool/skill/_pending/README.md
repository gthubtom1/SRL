# _pending —— 已归档的子技能（17 个）

**状态：不索引、不预载、不路由。** 模型看不到这里的技能描述，所以**不会被触发**。

## 为什么在这里
S3 把技能索引从 32 压到 9（`route.py` 只认 9 个 `pack.json`），其余按路径归档，
保留内容但不参与路由，避免索引变吵、避免和主包抢触发。

## 里面是什么
`00-triage` / `00-analysis` / `01-gate-bypass` / `02-ui-rebrand` / `03-license-hookup` /
`04-version-migrate` 等——原"五阶段"打法（判型→旁路→改 UI→接授权→追版本）。

## 想复活某个子技能（三件事，缺一不可）
1. **改描述**：`description` 必须是**用户会说的原话 + 文件后缀**（参照 9 个主包的新写法；
   名词式描述（如「阶段零·分析透彻出可复现报告」）不会被选中）
2. **挂进路由**：在对应主包 `pack.json` 的 `skills[]` 里加上它，或给它单独建 `pack.json`
3. **加探针**：在 `Tool/config/trigger-probes.json` 加一句真实用户说法 + 期望命中的包，
   否则以后没人知道它能不能被触发

## 想弃用
把目录整体移到 `docs/history/` 或删除；**不要**留在 `_pending/` 里假装还能用。
