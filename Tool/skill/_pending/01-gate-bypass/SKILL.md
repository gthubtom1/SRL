# 01 · 旁路卡密，出「原版可用」成品

> **工具获取**：先核当前专用工具及等价通道；必要时 `python Tool/scripts/tool-acquire.py --tool <id> --start --json`。注册/启动不等于目标已验证；缺不可替代能力才问 A/B/C。临时脚本须说明已有能力为何无法回答当前问题及验证方法，不能为缺可替代工具强制停工。


> **通用性声明**：本技能与任何具体样本解耦。文中出现的**节名**（如 `.ace0`）、**错误码**（如 `0xC000023E`）、
> **功能名**（如"皮肤库"）都是**举例**，实际以目标为准；判据看"形状"，不要照搬数字。

> **本阶段唯一的成功标准**：原版（或打过补丁的原版）**双击 → 主界面出现 → 卡密不再拦 → 所有功能能用**。
> 无界面程序（游戏辅助类）：**启动宿主 → 注入 → 宿主内菜单出现 → 功能生效**。

## 2. 壳与「启动即自毁」处理（本阶段最大拦路虎）

症状识别：`0xC0000409`（FAST_FAIL）、`0xC0000005`、启动 60–90ms 无窗口退出、`abort()`、VEH 页面守卫、
`VirtualProtect` 返回 `err=87`、`.pdata` 或加密段（**段名随样本变，如 `.ace0`**）熵 > 7.5。

**先看阶段零的 I0 仪器结论**：`case_state.py show --case <case>` 里的"仪器（I0）"一栏就是你的可选手段。
- `x64dbg = blocked` → 别在调试器上耗时间，走 **Frida attach / 外部观测 / 网络层**；
- `frida-spawn = partial`（早期挂载会改变行为）→ 改成 **attach 到已运行进程**，等首个请求发出再挂钩子；
- 所有注入手段都被阻断 → 转 **网络层（冒充服务器）/ 外部观测**，不要硬上。

**路线（按顺序，失败两次即换下一条，按当前目标核实替代路线；必要能力均受限时明确未完成/blocked，写缺口与恢复条件）**：

| 路线 | 做法 | 何时用 |
|---|---|---|
| A 分支级修补 | 定位失败分支（`je → abort`），NOP/改条件；必要时把指向加密段的 `lea` 改到进程内 RWX 私有页（注意 ±2GB 偏移） | 自毁原因在单点判定 |
| B 抢先注册 VEH | 在壳注册前接管页面守卫，拦截 `STATUS_GUARD_PAGE_VIOLATION`，按需解密/放行 | 壳用 VEH 做逐页解密 |
| C 运行期注入 | 启动器 `CREATE_SUSPENDED` + 注入 DLL，在壳初始化前打桩 | 静态改不动 |
| D 脱壳 | 按 `unpack-loop`：OEP 定位 → dump → 修 IAT/段 → 重建 → 再打授权门 | 前三条都不行 |

**判据**：出现主窗口 / 主界面（或游戏内菜单）。没出现 = 本阶段未完成。

## 3. 判定权威（决定打法）

| 结论 | 依据 | 打法 |
|---|---|---|
| 客户端权威（CWE-602） | 关键判定与依赖经代码/对照证明均在客户端；无网络导入仅是线索 | 补丁字节改判定、改本地状态、伪造成立 |
| 服务端权威 | 代码/协议证明最终授权依赖服务端决定；网络库、错误码与票据字符串单独不足以证明 | 仅受控测试可模拟可验证的协议；不能伪造服务端私钥签名或服务端业务能力。缺服务器/授权接口时报告限制 |
| 混用 | 本地缓存 + 服务端二次校验 | 双验：断网与联网都要过 |

## 4. 旁路实施（四选一，选副作用最小的）

| 形态 | 产物 | 适用 |
|---|---|---|
| 字节补丁 | 补丁后二进制 + 补丁脚本（原件只读保留） | 未加壳、逻辑直接 |

| 重打包 | APK 重签名 / 安装包重打 | Android / 安装器类 |
| 注入器 + 菜单 | 启动器 + 注入器 + 内存功能模块 | 游戏辅助 / 需要进程内钩子 |

**每改一处**：记录 `位置 | 原始 | 改后 | 语义 | 副作用`，并单独回滚验证。

## 5. 交付分级（按阶段零裁定的上限，不许越级）

| 级 | 判据 | 用户能看见什么 |
|---|---|---|
| **M1 存活** | 原版能到第一个界面（注入型：宿主内菜单出现） | 截图 + 进程存活 + 窗口标题 |

## 5bis. 功能面验收（逐条打勾）

1. 双击（或一条命令）→ 原版主界面出现，贴退出码/窗口标题/截图
2. 卡密框不再出现；无"试用/到期/未授权"提示
3. FEATURES 逐项实测（**按目标实际枚举**，例：资源库、导出、批量操作、解锁数量 —— 不要照搬示例清单）
4. 重启 · 换目录 · 改系统时间 · 断网 · 联网 —— 均不回退
5. 原件未被修改（哈希一致）；修改仅在独立副本且清单可解释
6. 注入型：注入成功 → 菜单出现 → 开关生效 → 退出无残留、不触发反作弊自毁
