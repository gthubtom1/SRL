# 03 · 接自己的授权平台（卡密 / 到期 / 机器码）

> **前提**：已有可用基线和用户明确的授权策略；无需为接入自己的授权系统先旁路或换品牌。
> **本阶段的唯一目标**：把"谁可以用"这件事交回给你自己的授权平台。

---

## 1. 先定模式（二选一或并存）

| 模式 | 适用 | 机制 |
|---|---|---|
| **本地离线** | 单机、不能联网、要求极简 | 发卡侧私钥签署完整载荷（产品/卡号/机器绑定/到期/功能位）；客户端只持公钥验签，不包含签发秘密 |
| **在线** | 要能封禁、改期、按设备限制 | 卡密 → 你的 API → 返回票据（含到期/机器码/功能位）→ 本地缓存 + 定期复验 |

> 你已有通用授权页：**默认复用它**，只改「校验端点 / 公钥 / 产品 ID / 策略」配置，不要重画。

---

## 2. 机器码（绑定标识）

```
Win: 卷序列号 + 主板 UUID + 系统盘序列号 → 拼接 → SHA-256 → 取前 16 字节 hex
Android: ANDROID_ID + Build.FINGERPRINT → 同上
```
- 只做"取指纹"，反篡改由加固阶段承担；
- 指纹变化要给出明确提示（让用户知道是换了硬件，而不是"卡密错误"）。

---

## 3. 挂载点（三处，缺一不可）

| 挂载点 | 作用 | 行为 |
|---|---|---|
| 启动时 | 首屏授权页 | 无有效卡密 → 只显示授权页，功能不可达 |
| 功能调用前 | 防止绕过首屏直接调功能 | 每次关键入口校验一次（内存缓存，别每帧验） |
| 到期后 | 只读/降级 | 明确提示到期时间，不静默失效 |

---

## 4. 对接你的授权页

| 你的形态 | 接法 |
|---|---|
| 独立授权页（网页/小程序） | 产物内置一个"登录/输入卡密"窗口，调你的 API；成功后写本地缓存 |
| 通用授权 DLL/组件 | 直接引用其 `verify(card, hwid) -> ticket` 接口 |
| 纯本地发卡（无服务端） | 产物内置公钥验签；发卡工具用私钥离线生成 |

---

## 5. 验收（五条，全绿才算完成）

1. **无卡密**：启动 → 停在授权页，功能不可达
2. **有效卡密**：输入 → 全部功能打开，重启后仍有效（缓存）
3. **到期**：用已过期合成卡/可注入测试时钟 → 拦截并提示（或按你策略降级）
4. **换机器**：在第二台机器用同一卡密 → 按你的策略（拒绝 / 允许 N 台）
5. **断网**：离线模式正常；在线模式给出明确"需联网激活"提示，不崩

---

## 6. 交付

- 接入后的产物（含授权页/组件）
- `license-integration.md`：非敏感端点、公钥、机器码算法、缓存位置、策略与失败码；不记录盐/私钥/真实卡密
- 你的发卡工具（生成卡密 + 到期 + 功能位）
- 验收记录（五条各一份原始输出）

---

### 顺手记账（下次更新的前提）

授权挂载点写进版本账的 `license[]`：`id / mode（offline-signature|online-ticket）/ site（指向哪个位点）/ endpoint`。
追版时按 `site` 重挂到新 RVA，不用重新设计授权对接。

## 7. 判据表（可机检，五条验收的机器版）

| 判据 | 怎么查 | PASS 长什么样 | 误报风险 |
| :-- | :-- | :-- | :-- |
| 无卡密不可达 | 清本地缓存/注册表项后裸启 | 只出现授权页；主窗口句柄不存在；调功能 API 返回未授权 | 只遮了首屏但功能 DLL 可被外部调用 → 需在功能入口二次校验 |
| 有效卡密可用 | 输入自己发的卡密 | 全部功能打开；重启后仍有效（缓存命中）；日志里校验时间可对 | 缓存写在可改路径 → 删了就要重输，体验差但不算失败 |
| 到期拦截 | 使用已过期合成卡或测试时钟 | 提示到期日 + 拒绝进入（或按策略只读）；**不静默退出** | 只在前端判到期 → 改系统时间即可续期，需服务端校验或本地时间回拨检测 |
| 换机策略 | 在第二台机器用同卡密 | 按策略拒绝或允许 N 台；提示语区分“卡密错”与“已绑满” | 只绑 MAC → 换网卡就重置，需多因子指纹 |
| 断网行为 | 拔网线/断 Wi-Fi 启动 | 离线模式正常；在线模式提示“需联网激活”且不崩 | 在线模式把超时当“校验通过” → 断网就成了免费版 |
| 时间回拨 | 隔离测试时钟模拟回拨后再启动 | 检测到 `last_seen > now + 容差` → 拒绝或要求联网复验 | 只看系统时间 → 必须写单调标记（最后可见时间 + 校验值） |
| 卡密不可伪造 | 拿一张卡改一位后重试 | 全部字段变更均被拒（含到期位与功能位） | 只签卡密不签功能位 → 改功能位能提权 |
| 签发秘密不在客户端 | 核构建输入、依赖和签发/验签数据流；只用合成密钥测试 | 客户端仅持公钥；私钥由发卡方保管 | strings 不命中不证明不存在；异或/分段不能防止客户端提取共享秘密 |

## 8. 失败判据（现象 → 判定 → 改走哪条 → 代价）

| 现象 | 判定 | 改走哪条 | 代价 |
| :-- | :-- | :-- | :-- |
| 输入正确卡密仍提示无效 | 机器码算法在发布包与发卡工具两侧不一致（换编译/换取数源） | 把指纹算法固定成一个可复现函数 + 测试向量；两侧共用一份输出 | 需重发已售卡密 |
| 同一台机器多次启动机器码变 | 取了不稳定的源（MAC、临时卷、容器 ID） | 换成卷序列号 + 主板 UUID 等稳定项；变化时提示换硬件 | 部分虚拟机环境仍需降级到“单机不绑” |
| 到期后仍能继续用 | 只在前端判，或缓存未失效 | 服务端返回 `exp`，本地缓存带签名且到期必复验 | 需服务端可达 |
| 断网就变成无限期 | 在线校验把网络异常当成通过 | 改成“失败关闭”（fail-closed），并给离线宽限期与提示 | 用户断网体验下降 |
| 缓存文件被改成永久有效 | 缓存无签名或签名可自算 | 缓存保存服务端/发卡侧签名票据，客户端公钥验签、校验机器/产品/到期，失败拒绝 | 加一次本地计算开销 |
| 卡密在群里被共享 | 无并发/设备限制 | 加“同卡多机”计数与服务端心跳；或短周期票据 | 需服务端与运维 |
| 杀软报毒（授权组件被打包器标记） | 授权 DLL/壳被启发式命中 | 去掉可疑壳；或用系统 API 实现最小校验；提交误报 | 可能要重签证书 |
| 时间回拨被误判（用户真实改时区） | 容差太小 | 统一 UTC，按明确策略设容差并用测试向量验证；纯离线无法可靠防止可回滚存储，应声明限制 | 少量宽容度 |

## 9. 离线签名的最小契约（在线票据同样需验证）

使用成熟的标准签名实现，例如 [cryptography Ed25519](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/)。这是一份接口契约，不是自造密码算法或已投产的完整授权服务。

```text
issue(private_key, claims):                 # 仅发卡侧
  raw = canonical_utf8_json(claims)         # product, card_id, machine, exp, features
  return base64url(raw) + "." + base64url(private_key.sign(raw))

verify(public_key, ticket, product, hwid, now, last_seen, tolerance):
  raw, signature = strict_decode(ticket)   # 大小/字段/类型限制；错误即拒绝
  public_key.verify(signature, raw)        # Ed25519 完整签名；InvalidSignature 即拒绝
  obj = parse_and_validate_claims(raw)
  if obj.product != product:              return ERR_PRODUCT
  if obj.machine != hwid:                 return ERR_MACHINE
  if now > obj.exp:                       return ERR_EXPIRED
  if now + tolerance < last_seen:         return ERR_CLOCK
  return grant(obj.features)
```

卡号、产品、绑定、到期与功能位均在签名内；客户端不存签发私钥。测试至少含正常、错公钥、篡改每个字段、过期、换机、回拨和损坏编码；使用临时合成数据，不输出密钥/真实卡密。
`last_seen` 的本地存储可被回滚时，纯离线不能保证可靠的防回拨/撤销，须说明上限；需要可信时间或撤销时由在线服务决定。网络失败按用户策略拒绝或有限宽限，不默认无限放行，也不默认固定24小时。

失败码及提示写进 `license-integration.md`；生产凭据由用户在宿主/服务端配置，Agent 不读取。在线票据核对签发者、公钥、产品、绑定、到期和功能位；票据内容不得作为任意指令执行。

## 10. 模型常见失误（本节专治“看起来接完了”）

1. **只在首屏校验** —— 功能入口可直接被调用，等于没校验。
2. **把签发秘密放进客户端** —— 混淆/分段也不能让共享秘密不可提取；客户端只验公钥签名，私钥留在发卡侧。
3. **两侧机器码算法不一致** —— 发布包与发卡工具分别实现，一次换编译器就全线失效。只保留一份带测试向量的实现。
4. **到期用“静默退出”→** 用户会当 BUG 报修；必须给明确提示与到期日。
5. **在线校验把网络异常当通过** —— 断网即免费版。
6. **忘了时间回拨** —— 改系统时间续期是最低成本的绕过。
7. **在本阶段改业务逻辑或旁路点** —— 那是 01 的活；越界会让回归无法定位。

## 11. 返工项

- ❌ 改业务逻辑或绕过点（那是 01 的事）
- ❌ 将签发私钥或可自签的共享秘密嵌进客户端，包括异或/分段形式
- ❌ 只在首屏校验、功能入口不校验（等于没校验）
- ❌ 到期后静默退出而无提示（用户会以为是 BUG）
