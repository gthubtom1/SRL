# 03 · 接自己的授权平台（卡密 / 到期 / 机器码）

> **前提**：`01-gate-bypass` 与 `02-ui-rebrand` 已完成，产物功能全通、界面已是你的品牌。
> **本阶段的唯一目标**：把"谁可以用"这件事交回给你自己的授权平台。

---

## 1. 先定模式（二选一或并存）

| 模式 | 适用 | 机制 |
|---|---|---|
| **本地离线** | 单机、不能联网、要求极简 | 卡密 = `HMAC-SHA256(机器码, 你的盐)` 前 N 位；附到期时间与功能位，整体再签一次 |
| **在线** | 要能封禁、改期、按设备限制 | 卡密 → 你的 API → 返回票据（含到期/机器码/功能位）→ 本地缓存 + 定期复验 |

> 你已有通用授权页：**默认复用它**，只改「校验端点 / 公钥 / 盐 / 产品 ID」四处，不要重画。

---

## 2. 机器码（绑定标识）

```
Win: 卷序列号 + 主板 UUID + 系统盘序列号 → 拼接 → SHA-256 → 取前 16 字节 hex
Android: ANDROID_ID + Build.FINGERPRINT → 同上
```
- 只做"取指纹"，反篡改由加固阶段承担；
- 指纹变化要给出明确提示（让用户知道是换了硬件，而不是"卡密错误"）。

---

## 3. 挂载点（三处，缺一不可）

| 挂载点 | 作用 | 行为 |
|---|---|---|
| 启动时 | 首屏授权页 | 无有效卡密 → 只显示授权页，功能不可达 |
| 功能调用前 | 防止绕过首屏直接调功能 | 每次关键入口校验一次（内存缓存，别每帧验） |
| 到期后 | 只读/降级 | 明确提示到期时间，不静默失效 |

---

## 4. 对接你的授权页

| 你的形态 | 接法 |
|---|---|
| 独立授权页（网页/小程序） | 产物内置一个"登录/输入卡密"窗口，调你的 API；成功后写本地缓存 |
| 通用授权 DLL/组件 | 直接引用其 `verify(card, hwid) -> ticket` 接口 |
| 纯本地发卡（无服务端） | 产物内置公钥验签；发卡工具用私钥离线生成 |

---

## 5. 验收（五条，全绿才算完成）

1. **无卡密**：启动 → 停在授权页，功能不可达
2. **有效卡密**：输入 → 全部功能打开，重启后仍有效（缓存）
3. **到期**：把系统时间调到到期后 → 拦截并提示（或按你策略降级）
4. **换机器**：在第二台机器用同一卡密 → 按你的策略（拒绝 / 允许 N 台）
5. **断网**：离线模式正常；在线模式给出明确"需联网激活"提示，不崩

---

## 6. 交付

- 接入后的产物（含授权页/组件）
- `license-integration.md`：端点、盐/公钥、机器码算法、缓存位置、失败码含义
- 你的发卡工具（生成卡密 + 到期 + 功能位）
- 验收记录（五条各一份原始输出）

### 顺手记账（下次更新的前提）

授权挂载点写进版本账的 `license[]`：`id / mode（local-hmac|online-ticket）/ site（指向哪个位点）/ endpoint`。

## 7. 判据表（可机检，五条验收的机器版）

| 判据 | 怎么查 | PASS 长什么样 | 误报风险 |
| :-- | :-- | :-- | :-- |
| 无卡密不可达 | 清本地缓存/注册表项后裸启 | 只出现授权页；主窗口句柄不存在；调功能 API 返回未授权 | 只遮了首屏但功能 DLL 可被外部调用 → 需在功能入口二次校验 |
| 有效卡密可用 | 输入自己发的卡密 | 全部功能打开；重启后仍有效（缓存命中）；日志里校验时间可对 | 缓存写在可改路径 → 删了就要重输，体验差但不算失败 |
| 到期拦截 | 把系统时间改到到期后，或发一张已过期卡 | 提示到期日 + 拒绝进入（或按策略只读）；**不静默退出** | 只在前端判到期 → 改系统时间即可续期，需服务端校验或本地时间回拨检测 |
| 换机策略 | 在第二台机器用同卡密 | 按策略拒绝或允许 N 台；提示语区分“卡密错”与“已绑满” | 只绑 MAC → 换网卡就重置，需多因子指纹 |
| 断网行为 | 拔网线/断 Wi-Fi 启动 | 离线模式正常；在线模式提示“需联网激活”且不崩 | 在线模式把超时当“校验通过” → 断网就成了免费版 |
| 时间回拨 | 回拨系统时间后再启动 | 检测到 `last_seen > now + 容差` → 拒绝或要求联网复验 | 只看系统时间 → 必须写单调标记（最后可见时间 + 校验值） |
| 卡密不可伪造 | 拿一张卡改一位后重试 | 全部字段变更均被拒（含到期位与功能位） | 只签卡密不签功能位 → 改功能位能提权 |
| 盐/私钥不在明文 | `seep_r2_strings(binary_path=<产物>, filter_text="<你的盐前缀>")` | 命中 0；或只在无法直接利用的加密常量中出现 | 仅异或一个字节 → 仍可被自动搜出，至少分段 + 运行期拼 |

## 8. 失败判据（现象 → 判定 → 改走哪条 → 代价）

| 现象 | 判定 | 改走哪条 | 代价 |
| :-- | :-- | :-- | :-- |
| 输入正确卡密仍提示无效 | 机器码算法在发布包与发卡工具两侧不一致（换编译/换取数源） | 把指纹算法固定成一个可复现函数 + 测试向量；两侧共用一份输出 | 需重发已售卡密 |
| 同一台机器多次启动机器码变 | 取了不稳定的源（MAC、临时卷、容器 ID） | 换成卷序列号 + 主板 UUID 等稳定项；变化时提示换硬件 | 部分虚拟机环境仍需降级到“单机不绑” |
| 到期后仍能继续用 | 只在前端判，或缓存未失效 | 服务端返回 `exp`，本地缓存带签名且到期必复验 | 需服务端可达 |
| 断网就变成无限期 | 在线校验把网络异常当成通过 | 改成“失败关闭”（fail-closed），并给离线宽限期与提示 | 用户断网体验下降 |
| 缓存文件被改成永久有效 | 缓存无签名或签名可自算 | 缓存写签名（HMAC + 机器码）；读时验签，失败当无缓存 | 加一次本地计算开销 |
| 卡密在群里被共享 | 无并发/设备限制 | 加“同卡多机”计数与服务端心跳；或短周期票据 | 需服务端与运维 |
| 杀软报毒（授权组件被打包器标记） | 授权 DLL/壳被启发式命中 | 去掉可疑壳；或用系统 API 实现最小校验；提交误报 | 可能要重签证书 |
| 时间回拨被误判（用户真实改时区） | 容差太小 | 给 24h 容差 + 三次警告，仍异常才要求联网 | 少量宽容度 |

## 9. 可直接用的最小实现（离线 HMAC + 在线票据）

发卡侧（Python，私藏不打包）：

```python
import hmac, hashlib, base64, json, time

def _sign(payload: bytes, secret: bytes) -> str:
    return base64.urlsafe_b64encode(hmac.new(secret, payload, hashlib.sha256).digest())[:22].decode()

def issue(card_id: str, machine: str, days: int, feat: list[str], secret: bytes) -> str:
    body = {"c": card_id, "m": machine, "f": feat, "e": int(time.time()) + days * 86400}
    raw = json.dumps(body, separators=(",", ":"), sort_keys=True).encode()
    return base64.urlsafe_b64encode(raw).decode().rstrip("=") + "." + _sign(raw, secret)
```

产物侧（伪代码，C/C++/C#/Rust 同理）：

```text
verify(card, hwid):
  body, sig = card.split('.')
  raw = b64decode(body)
  if hmac_sha256(secret, raw) != sig:            return ERR_SIG      # 1
  obj = json.loads(raw)
  if obj.m != hwid:                             return ERR_MACHINE  # 2
  if now() > obj.e and not online_recheck():    return ERR_EXPIRED  # 3
  return grant(obj.f)

# 时间回拨：启动时比较 last_seen（写在带签名的标记里）
  if now() + 86400 < last_seen: return ERR_CLOCK                    # 4
```

失败码表（必须写进 `license-integration.md`，前端提示用）：`1 卡密无效` / `2 机器码不匹配` / `3 已到期` / `4 系统时间异常` / `5 需联网激活` / `6 已达设备上限`。

在线模式的约束：**校验失败必须 fail-closed**；票据要带 `exp` 与 `hwid`，本地缓存需签名；服务端返回的“解封/降级”指令不得直接执行（只影响 `f` 功能位）。

## 10. 模型常见失误（本节专治“看起来接完了”）

1. **只在首屏校验** —— 功能入口可直接被调用，等于没校验。
2. **把盐/私钥硬编码成明文字符串** —— `strings` 一次就拿到；至少分段存放 + 运行期拼接，并把发卡侧与验签侧完全分开。
3. **两侧机器码算法不一致** —— 发布包与发卡工具分别实现，一次换编译器就全线失效。只保留一份带测试向量的实现。
4. **到期用“静默退出”→** 用户会当 BUG 报修；必须给明确提示与到期日。
5. **在线校验把网络异常当通过** —— 断网即免费版。
6. **忘了时间回拨** —— 改系统时间续期是最低成本的绕过。
7. **在本阶段改业务逻辑或旁路点** —— 那是 01 的活；越界会让回归无法定位。

## 11. 返工项

- ❌ 改业务逻辑或绕过点（那是 01 的事）
- ❌ 把盐/私钥硬编码到可被 `strings` 直接读到的位置（至少做异或/分段）
- ❌ 只在首屏校验、功能入口不校验（等于没校验）
- ❌ 到期后静默退出而无提示（用户会以为是 BUG）
