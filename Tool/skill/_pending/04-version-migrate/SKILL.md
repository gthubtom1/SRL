# 04 · 跨版本追版（新版一出来，半小时出成品）

> **本阶段唯一的成功标准**：新版 + 旧版三张资产清单（位点 / UI / 授权）→
> **双击进主界面、功能全通、UI 是你的、授权走你的平台**，且**没有重新读一遍反汇编**。

> **通用性声明**：文中出现的 RVA、AOB、节名都是示例；判据看"形状"，实际以目标为准。

---

## 0. 阶段边界

| 本阶段做 | 本阶段移交 |
|---|---|
| 指纹比对、位点对齐、UI/授权迁移、重建、回归 | 第一次旁路卡密 → `01-gate-bypass` |
| 版本账 / 迁移包 / 差异报告 | 重做 UI 设计 → `02-ui-rebrand` |
| 命中失败时的兜底定位 | 新建授权对接 → `03-license-hookup` |
| 追版后刷新版本账 | 换壳重写业务逻辑 |

**前提**：旧版本必须留有 `versions/<旧版本>/manifest.json`。没有账 → 先补账（回到 01/02/03 的交付物里找）。

## 1. 开局四问（先答，再动手）

1. **新版壳变了吗**？`migrate.py fingerprint <新版exe>` → `packer_hint`
   变了（节表新增/熵 > 7.5/可疑节名）→ **停**，先按 `01` 的 A–D 过壳，再回来追版。
2. **旧账在哪**？`versions/<旧版本>/manifest.json` 的 `sites[]` 有几条、`self_check` 是否 unique。
3. **这次要迁什么**？卡密位点 / UI 素材 / 授权挂载点 —— 三张清单各自的状态。
4. **验收怎么算过**？`acceptance[]` 是否够具体（窗口标题、功能项、授权页）。不够就先补。

## 2. 七步流水线（每步有判据，失败不许往下走）

### ① 指纹比对

```bash
python （`migrate` 已不存在：按上面的替代路径走） fingerprint "<新版exe>"
```

判据：`format/machine` 与旧版一致；`packer_hint` 无新增告警。
壳变了 → 停，回过壳；壳没变 → 继续。

### ② 位点对齐

```bash
python （`migrate` 已不存在：按上面的替代路径走） align --case <case目录> --old 6.8 --new "<新版exe>" --new-version 6.9
```

判据：输出 `N/N 唯一命中`。
- `multi`（多处命中）：AOB 太短 → 加长 `--window`（24→32），或加相邻唯一字节重记；
- `miss`：走第 4 节「兜底三重」。

### ③ UI 资产重定位

按 `manifest.ui[]` 的 `container`（`RCDATA#N` / zip 条目 / 目录文件）在新版里找对应槽位：

| 情况 | 动作 |
|---|---|
| 容器格式与槽位编号未变 | 直接贴（素材可 100% 复用） |
| 槽位编号变了 | 按容器内条目顺序/哈希匹配，记 `old→new` 对照 |
| 容器格式变了（zstd→别的） | 标人工，附旧/新结构 diff，**不许硬塞** |

### ④ 授权挂载点重挂

`manifest.license[]` 的 `site` 指向 ② 得到的新 RVA。挂上后**必须走一遍真实授权页**
（卡密 → 到期 → 机器码绑定），不是"能编译就算完"。

### ⑤ 构建

```bash
powershell -File versions/6.9/build.ps1     # 或 01/02/03 阶段留下的构建脚本
```

判据：产物能从原件一条命令复现；原件哈希未被改动，或改动可被补丁清单完全解释。

### ⑥ 回归验收

`acceptance[]` 逐条跑：

1. 双击 → 主界面出现（贴退出码/窗口标题/截图）
2. 无卡密框、无"试用/到期"提示
3. 功能面逐项实测（按目标实际枚举）
4. UI 是自家品牌、原作者信息不在
5. 授权走自己的平台（断网/联网都验）
6. 重启 · 换目录 · 改系统时间 —— 不回退

### ⑦ 差异报告 + 刷新版本账

```bash
python （`migrate` 已不存在：按上面的替代路径走） report --case <case目录> --old 6.8 --new-version 6.9
```

报告必须含：旧 RVA → 新 RVA 对照、命中率 N/M、需人工 K 处。
**然后**把新版本重新 `init` + `add-site`（用 ② 得到的新 RVA），这样下一次更新有账可追。

## 3. 常见漂移模式（知道往哪看，比全量比较快十倍）

| 现象 | 原因 | 对策 |
|---|---|---|
| 位点整体平移几百字节 | 函数顺序/对齐变化 | AOB 滑窗自动搞定，不用管 |
| `call` 目标变了 | 重编译后内联/拆分 | 掩掉 rel32 即可；若函数被内联，改在调用点打补丁 |
| 判定逻辑被改写成 `setcc` | 优化等级变化 | 语义没变 → 在 `setcc` 后打跳转；语义变了 → 回 `01` 重新判权威 |
| 资源容器变大 | UI 素材变多 | 贴图前先确认槽位编号，不要按"第 N 个"硬猜 |
| 授权接口字段变 | 服务端升级 | 改 `license[].endpoint` 参数，不要改客户端判定 |

## 4. 对齐失败时的「兜底三重」

1. **唯一字符串锚**：报错文案 / 注册表键 / URL / 卡密提示 → 新版搜字符串 → 取 xref；
2. **xref 回溯**：引用该字符串的函数，比对函数开头 8–16 字节与调用序列；
3. **反编译特征**：`seep_decompile_auto` 取新旧伪代码，比常量、调用顺序、分支数。

三条都失败 → 标 `need_manual` 并写清"看哪个字符串、哪个函数"，**不许假装命中**。

## 5. 返工项（出现即返工）

- ❌ 命中率不到 100% 却说"追版完成"
- ❌ 因为新版"看起来一样"就跳过验收，直接交
- ❌ 重新从零逆向一遍（那是没读版本账，不是追版）
- ❌ 重画 UI / 重新设计授权页（01/02/03 的资产应当复用）
- ❌ 壳变了还硬追（先回过壳，否则一切对齐都是假的）
- ❌ 问"要不要继续" / 甩 A/B/C 选择题（路线自己定，写进报告）
