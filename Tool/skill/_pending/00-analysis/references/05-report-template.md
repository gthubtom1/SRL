# 05 · 一页可复用报告模板：从「结论」到「别人能照着复现」

> 配套：`../SKILL.md` 的 §3 报告结构（8 节）、§4 可行性裁定、§5 交付物（`analysis-report.md` / `facts.jsonl` / `gaps.json` / `plan.json`）。
> 本篇只给**一页能贴进工单的报告骨架** + **逐字段判据** + **「证据不足」反例清单**，不重复阶段闸规则。
> 一句话判据：报告的价值不在「我发现了什么」，而在「**别人只拿这份文件、拿同一个样本，能不能复现同一条结论**」。

---

## 1. 用哪张表

| 你要做的事 | 看本篇哪节 | 不要写什么 |
|---|---|---|
| 出阶段零报告（8 节齐） | §2 全模板 + §3 逐字段 | 还没测就写「应该是」 |
| 给某条结论定性（进 `facts.jsonl`） | §3.4 证据分级 | 只有 `proven` 没有 `how` |
| 写复现步骤 / 贴原始报文 | §3.3 | 只写「登录后访问接口」 |
| 写影响面 / 严重度 | §3.2 | CIA 三件套（机密性/完整性/可用性） |
| 交付前自检 | §4 60 秒清单 | —— |
| 判断「这条到底算不算证据」 | §5 反例清单 | 用形容词代替数字 |

---

## 2. 一页模板（复制即用）

```markdown
# <对象> · <缺陷/现象> · <后果一句话>

- 报告编号 / 版本 / 日期（UTC）：
- 目标：<文件 sha256 前 12 位 / URL / 包名+版本 / 容器镜像 digest>
- 授权依据：<工单号 / scope 声明 / 客户授权邮件时间>
- 环境：<OS+版本 / 设备型号 / 网络位置 / 工具版本>
- 裁定：**可赢 / 部分可赢 / 不可赢**（一句话理由 + 依据证据编号）

## 1. 影响面
- 谁能利用：<权限前提 / 网络可达性 / 是否需要交互>
- 拿到什么：<数据类别 + 量级 / 权限 / 可用性影响>
- 业务后果：<钱 / 合规 / 声誉，能换算就换算>
- 不夸大声明：<做不到的部分，一句话写清>

## 2. 复现步骤
> 别人照着做，15 分钟内能到同一条结论；每步带命令与原始报文（凭据/个人信息打码）。

### 2.1 前置
- 账号 / 角色 / 样本 / 依赖安装：
- 起始状态（哈希、时间、版本）：

### 2.2 步骤
1. `<命令原文>`
   ```text
   <关键输出（截断到能证明结论的那几行）>
   ```
2. `<命令原文>` → 期望：<可判定的现象>
3. 对照实验（必做其一）：<断网 / 换目录 / 换账号 / 改系统时间> 后重跑，结果：<变 / 不变>

## 3. 证据与分级
| 编号 | 结论（一句话） | 分级 | 证据（工具+命令+关键输出） | 失效条件 |
|---|---|---|---|---|
| C01 | | proven | | |
| C02 | | hypothesis | | |

## 4. 受影响资产与归属
| 资产 | 类型 | 归属（谁的系统/账号） | 是否在授权范围 | 证据编号 |
|---|---|---|---|---|

## 5. 修复建议
1. **修根因**：<具体改动：代码位置 / 配置项 / 版本>
2. **纵深**：<第二道控制>
3. **检测**：<哪条日志/规则能看见这次利用>
4. **复测方法**：<发什么请求、期望什么响应>

## 6. 时间线（UTC）
| 时间 | 事件 | 来源（工具/日志） | 备注（时区/时钟偏差） |
|---|---|---|---|

## 7. 未闭环项
- 未验证的假设 + 怎么验 + 影响哪个决策（对应 `facts.jsonl` 的 hypothesis）
- 缺件（`gaps.json`）与它对裁定的影响
```

**长度纪律**：主体一页；证据与报文进附录，正文只留「能证明结论的那几行」。读者顺序是「裁定 → 影响面 → 复现 → 证据」，写成别的顺序等于没写。

---

## 3. 逐字段判据

### 3.1 标题

- **必须**：对象 + 现象 + 后果，三件事都在标题里；能被搜索到（含样本名/接口名/事件 ID）。
- **判据**：把标题单独发给没参与的人，他能说出「什么东西、出了什么事」。
- 好：`AppReadiness.evtx 记录数为 0 且 EventRecordID 从 1 重来 —— 日志在 2026-10-20T03:22Z 后被清除`
- 差：`日志分析`、`发现一个高危问题`、`关于 XX 的进一步分析`

### 3.2 影响面

- **必须**：谁能利用（前提）+ 拿到什么（数据类别与量级）+ 业务后果（钱/合规/声誉）。
- **判据**：出现具体数字或具体数据类别；没有就写「量级未测」。
- 好：`任意已登录低权用户可读取 247,000 条客户记录（含手机号、地址），对应《个保法》第 51 条与 72 小时通报义务`。
- 差：`可能导致数据泄露，影响机密性`（CIA 三件套，等于没写）。
- 禁止词：`可能`、`或许`、`理论上`、`存在风险` —— 要么给证据，要么写进「未闭环项」。

### 3.3 复现步骤

- **必须**：编号步骤 + 命令原文 + 原始报文/输出片段 + 起始状态（哈希/版本/时间）+ 一个对照实验。
- **判据**：第三方从零开始 ≤15 分钟到同一条结论；命令能直接复制粘贴跑。
- 报文只贴关键行，但要**完整到能判真伪**：请求行、关键头（打码后的 Cookie/Token）、状态码、响应体的判定字段。
- 凭据/个人信息打码规则：`<REDACTED-PASSWORD>`、`<TOKEN-A1>`、邮箱换 `<user1@example.com>`；截图裁到相关区域并剥 EXIF（`exiftool -all=`）。
- 只读纪律：取证类步骤必须写清「原件只读、分析在副本」，并给出 `sha256sum` 输出；对目标系统的写操作要单列并说明已恢复。

### 3.4 证据分级（本仓口径，与 `facts.jsonl` 同源）

| 分级 | 定义 | 进报告的位置 | 机检要求 |
|---|---|---|---|
| `proven` | 本会话**跑过**，有命令 + 输出 + 可复算 | 结论段 | 必须有 `how` 与 `evidence[]`；`case_state.py gate` 会拦「无证据的 proven」 |
| `hypothesis` | 有迹象、没跑通/没对照 | 未闭环项 | 必须写「怎么验」 |
| `refuted` | 被哪条证据推翻（旧结论保留，不删） | 附录「结论变更」 | 写 `refuted_by` |
| `stale` | 曾经 proven，但前提变了（换 exe/换域名/服务下线） | 复验前不得引用 | `prove` 复验后才复活 |

- 交叉口径：只读观测写 `observed`，推断写 `inferred`，没测写 `unverified`；**三种不许混行**。
- 平台侧映射（客户/漏洞平台）：`proven` ≈ Confirmed；`hypothesis` ≈ Suspected (1 signal)；
  只有 `hypothesis` 的条目**不要提交**（见 §5 第 2 行）。

### 3.5 受影响资产与归属

- **必须**：资产清单（域名/IP/主机名/账号/租户）+ **归属**（谁的系统）+ 是否在 `scope` 内 + 证据编号。
- **判据**：任一资产说不出归属，或归属不在授权范围 → 该资产的所有结论降为 `hypothesis`，并立即停手确认。
- 共享基础设施（CDN、云函数、公共 DNS）要写明「共享，非目标专属」，否则影响面会被高估。
- 跨租户/多账号结论必须写清「验证了哪几个 ID、是否只读」。

### 3.6 修复建议

- **必须**：三层 —— 修根因 / 纵深 / 检测；每条给**可验证的完成标准**。
- **判据**：开发看完能直接改；改完能按「复测方法」判真假。
- 好：`在 /api/orders 的服务端按 tenant_id 过滤（不只是前端隐藏）；复测：A 账号请求 B 的订单号应返回 403 而非 200`。
- 差：`建议加强安全防护`、`建议遵循最小权限原则`（无法验收）。

### 3.7 时间线

- **必须**：统一 UTC（ISO 8601），保留原时区与时钟偏差；同一事件多来源要并列；写清 `timestamp_basis`。
- **判据**：任意两条能排序；跨源冲突不取「看起来合理」的那个，而是并列并标注来源。
- 差：`昨天下午`、`约 3 点左右`、本地时间与 UTC 混排、Chromium `visit_time` 当 FILETIME 换算（会得到 1643 年）。

### 3.8 未闭环项

- **必须**：一条假设一行：假设 → 怎么验 → 影响哪个决策（路由/裁定/交付档位）。
- **判据**：`plan.json` 的失败判据能对上这里的某一条；对不上的说明「为什么可以不验」。

## 4. 提交前 60 秒清单

- [ ] 标题含对象+现象+后果；裁定一句话说得出。
- [ ] 每条 `proven` 都有命令/输出/时间三件套；没有就改回 `hypothesis`。
- [ ] 复现步骤从零可跑：命令能复制、报文能判真伪、打了码。
- [ ] 影响面有数字或数据类别；没有就写「未测」，不写「可能」。
- [ ] 资产有归属且都在授权范围内；超范围的一律降级。
- [ ] 修复建议能验收：有复测请求 + 期望响应。
- [ ] 时间线全 UTC，含时区/偏差说明。
- [ ] 未闭环项与 `gaps.json` / `plan.json` 对得上。
- [ ] 报告里没有「旧报告这么写」——旧结论只能作为 `hypothesis` 引用。
- [ ] 附件里无明文凭据、无真实个人信息、无 EXIF。

## 5. 「什么叫证据不足」反例清单

| 写法 | 为什么不足 | 补到什么程度才算 |
|---|---|---|
| `经分析发现服务端鉴权薄弱` | 无对象、无命令、无输出，任何人无法复算 | 给出请求/响应原文 + 对照账号 + 时间 |
| `疑似存在注入点` | 只有报错页或只有参数名，未证明可控 | 用布尔/时间对照证明可控，或降为 `hypothesis` 并写明下一步 |
| `根据上一轮报告，这里应该是服务端权威` | 旧结论当证据（阶段零第一因） | 自己跑一次出站观测（进程+五元组+时间）再引用 |
| `抓包看到 token，说明可越权` | 没说哪个请求、是谁的 token、是否自己账号 | 两个账号 + 两次请求 + 响应差异，写清 ID 归属 |
| `影响：可导致数据泄露` | 无数据类别、无量级、无前提 | 数据字段清单 + 记录条数 + 所需权限 |
| `复现：登录后访问接口` | 缺前置、缺参数、缺期望结果 | 前置账号/样本 + 命令原文 + 期望响应 |
| `高危（CVSS 9.8）` | 向量没逐项说明，分数当结论 | 每个 metric 一句理由，再给业务影响调整段 |
| `已修复`（自己宣布） | 没有复测请求与响应，修复方也没确认 | 复测请求 + 期望响应 + 时间戳；否则写「待复测」 |
| `工具输出如下` + 截图 | 无命令、无版本、无时间，别人复现不了 | 命令 + 工具版本 + 时间 + 关键输出文本 |
| `多个资产受影响` | 资产归属不明、未列清单，可能含越界资产 | 资产表（归属 + 是否在 scope + 证据编号） |
| `概率 0.8，可以赢` | 没有 `gaps.json` / `plan.json` 支撑，纯拍脑袋 | 路线菜单 ≥2 条 + 缺件折损 + 失败判据 |
| `删掉日志就没痕迹了` | 清理动作本身有自证痕迹（1102/104、`UsnJournalID` 变化） | 写出「自证痕迹 + 一个独立源」的核对结果 |
| `时间线：昨天下午发生` | 无 UTC、无时区、无法排序 | UTC 时间 + 原时区/偏差 + `timestamp_basis` |
| `未解说明不存在` | 解不开/没权限 ≠ 没有 | 写 `blocked_at: tool-missing / permission` 与降级路线 |

**一句话规则**：**没有证据的结论不进正文**；宁可交「未闭环」，也不要交「看起来完整」。
