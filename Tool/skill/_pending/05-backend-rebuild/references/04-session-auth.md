# 会话与鉴权：重算得出"被接受"，不是绕过

> 判据只有一句：**用客户端的算法，重算出服务端接受的请求**。
> 拿不到这个，说明算法/key 归属还没摸清，后端复刻停在猜。

## 1. 会话形态的四层

| 层 | 载体 | 客户端可见 | 复刻要点 |
|---|---|---|---|
| Cookie | `Set-Cookie` / `Cookie` | 是（HttpOnly 也能被浏览器带） | 过期、`SameSite`、签名 cookie 的密钥 |
| Token | `Authorization: Bearer` / 自定义头 | 是 | 签发格式、刷新、吊销 |
| 本地存储 | `localStorage`/`sessionStorage`/IndexedDB | 是 | 只做"客户端状态镜像"，不能当服务端真相 |
| 服务端 session | session id → 库/内存 | 只有 id | 必须自己实现，且能做顶号/过期 |

复刻顺序：先让客户端**拿到**会话（login/join），再让后续请求**带上**它，最后补过期/吊销。

## 2. 签名与加密：先定位，再重算

定位手段（按成本排序）：

1. 静态：搜 `sign`、`hmac`、`sha256`、`md5`、`AES`、`RSA`、`encrypt`、`nonce`、`timestamp`、
   `X-Sign`、`X-Timestamp` 等常量与头名。
2. 抓包对照：同参数改一个字节，看哪个头/字段变化 → 定位参与签名的字段。
3. 运行时 hook（授权范围内）：在加密函数入口打印入参/出参，或替换实现做"同输入同输出"验证。
4. 二进制/容器侧：字符串池、常量表、初始化函数交叉引用（`dl/`、`.iec`、`.dex` 等）。

重算验收：

```text
客户端算法 + 抓包原参数 → 本地算出签名 → 与原抓包签名逐字节一致
→ 把该请求发到本地 mock（校验逻辑与服务端一致）→ 被接受
```

只做到"本地一致"不够：还要有一条**被服务端接受**的请求（真实服务端或忠实复刻端）。

## 3. Key 归属表（报告必写）

| 问题 | 答案写法 | 影响 |
|---|---|---|
| 签名 key 在客户端吗？ | 在（常量/派生/白盒） | 可以忠实复算；换自家 key 后客户端要同步改 |
| key 是服务端下发吗？ | 是（登录响应/配置接口） | 复刻 = 重实现 + **换自家 key**，不是"破解出别人的 key" |
| 有非对称吗？ | RSA/ECC 公钥在客户端、私钥在服务端 | 客户端只能验签/加密，签发必须在自家后端 |
| 有设备指纹吗？ | 是（IMEI/机器码/安装 id） | 需要设备注册表 + 绑定策略 |

写成三列表：`密钥/算法 | 位置（客户端/服务端/下发） | 复刻动作（保留/替换/重签）`。

## 4. 401 与 404 必须分开

真实事故里最常见的调试陷阱：

- 客户端请求路径被截断（`/v1/chat/c`），服务端没有该路由 → 落到默认鉴权分支 → 返回 **401「登录已过期」**；
- 调试者以为是会话问题，反复重登，实际是**路由没注册**。

规则：

1. 未注册路径 → `404 {"error":"not_implemented", ...}`，带 `path`/`method`/`snapshot`。
2. 方法不对 → `405 {"error":"method_not_allowed", "allowed":[...]}`。
3. 会话无效/过期 → `401 {"error":"session_expired"}`（或业务约定的错误码），**只在路由命中后**返回。
4. 权限不足 → `403 {"error":"forbidden"}`，与 401 分开。
5. 参数缺失 → `400 {"error":"validation_failed","missing":[...]}`（`--strict` 模式）。

`backend-scaffold.py` 生成的 `server.py` 固化了这套顺序，`switch-verify.py` 的错误码路径专门验证 4xx+JSON error。

## 5. 心跳 / 轮询语义

心跳不是"随便回 200"：

| 参数 | 必须定义 | 缺失后果 |
|---|---|---|
| 频率 | 客户端每 N 秒一次（抓包量出来） | 太快打爆后端，太慢被判离线 |
| 超时 | 客户端等待阈值 | 超时后客户端行为要与原厂一致 |
| 错误计数 | 连续失败几次触发下线/退出 | 一次失败就退出 = 体验事故 |
| 超限行为 | 停服时是"重试"还是"提示后退出" | 死循环重连 = 与原厂不一致 |
| 响应体 | 至少 `{"ok":true,"alive":true}` 或等价 | 客户端解析失败会当断网 |

演练案例里，`/info/country` 是唯一的只读轮询型接口，role 记为 `heartbeat`；真正的长连接心跳要按抓包补。

## 6. 单设备在线 / 顶号

若原厂有（抓包出现 `device_id`、`kick`、`other_login` 等）：

- 会话表加 `device_id`、`last_seen`；同账号新设备登录时把旧会话标 `kicked`。
- 旧客户端下一次请求返回约定错误码（如 `401 session_kicked`），并验证客户端表现与原厂一致。
- 顶号策略写进报告：允许几端同时在线、踢旧还是拒新。

## 7. 演练映射（site-clone-drill01）

| 证据 | 复刻动作 | 验证 |
|---|---|---|
| `/player/name` 页面需 user/player 会话 | 生成 `POST /api/player`（join，role=login） | switch-verify normal 2xx |
| `/find` 需 code 查测验 | `GET /api/quiz/lookup?code=` | 列表路径 2xx |
| `/user/share` 需 user 数据 | `GET /api/share?code=` | 列表路径 2xx |
| `/info/country` 跨域 | `GET /info/country`（role=heartbeat） | 超时/错误码路径 |
| 无录制会话样本 | mock 返回 `scaffold-stub`，明确不是录制 | `source` 字段可查 |

本案没有真实登录样本，所以"会话可用"只能到 L3（结构通、契约对），
不能宣称"登录态 1:1"——这正是交付口径要写清的地方。

## 8. 验收判据

| # | 判据 | 机检 |
|---|---|---|
| 1 | 重算被接受 | 客户端算法算出的签名 → 本地后端接受（日志留 request_sha256） |
| 2 | key 归属表完整 | 每个密钥一行，位置/动作明确 |
| 3 | 401/404/405/400 可分 | `switch-verify` 错误码路径 + 未注册路径探针 |
| 4 | 过期可测 | 把 `expires_at` 调到过去，请求返回 401，客户端不崩 |
| 5 | 心跳可解释 | 频率/超时/错误计数/超限行为四项都有值 |
| 6 | 停服一致 | 关掉后端，客户端表现与原厂停服一致（不是崩、不是死循环） |

## 9. 失败判据

- 只会"改 hosts + 返回 200"：会话没实现，后续写接口一定穿帮。
- 签名"本地能算"但服务端拒：参与字段/排序/编码（URL encode、大小写、时间窗）没对齐。
- 用 401 掩盖所有失败：调试被误导，先查路由注册（见 §4）。
- 把服务端 key 写成"已破解"：key 归属表里应写"重实现 + 换自家 key"。
- 心跳回包与客户端解析不匹配：抓包对照响应体字段，不要自创 envelope。
