# 00a · 快筛（S0）：20 分钟出「目标画像卡」

> **工具获取**：本阶段要用的工具先跑 `python Tool/scripts/tool-acquire.py --tool <id> --start`（L0 探活 → L1 启动 → L2 连上 → L3 装 → L4 求助）。**L4 必须发 ASK 卡**，不许静默改用手搓脚本；手搓要用 `Tool/prompts/contracts/TOOL-LADDER.md` §2 的判据并在 decisions.md 留痕。


> **陷阱库**：`Tool/prompts/contracts/TRAP-LIBRARY.md`（14 条实测坑，按「信号」自查，命中才用 —— 提示不是规则）。

> **唯一的成功标准**：20 分钟内产出一张**别人拿着同一份样本能核对**的画像卡。
> 出不全没关系 —— 把"未知"写清、并说明卡在哪，本身就是结论。
> **本档不做**：动态调试、内存 dump、断点、写补丁、抓包长时间观察。那些是 `00-analysis` 的 D1–D7。

## 阶段契约
- **怎么想**：本阶段的每一次判断都要按 `Tool/prompts/contracts/DECISION-LOOP.md` 的四步环留痕（观察→假设→决策→验证），决策步必须写「被放弃的选项 + 依据」。


- **进入**：拿到目标文件/目录/URL；`case_state.py init` 已建案。
- **退出**：`report/triage.md`（≤50 行）+ 画像卡六字段齐（未知的标 `?` 并写一句为什么）。
- **硬闸**：`python Tool/scripts/case_state.py gate --stage 0a --case <case>`
- **ASK**：需要人提供凭据/口令/登录态才看得下去时 → 按"对话内 ABC"格式发（见 §5）。

## 1. 只做这六件事（按载体查表，10–20 分钟）

| 载体 | 快筛动作（每条 ≤3 分钟） |
| :-- | :-- |
| **PE / ELF** | ① 类型/架构/子系统 ② 节表与熵（`RawSize=0` 或高熵节＝运行时解密）③ 壳签名排除（UPX/Themida/VMProtect/Enigma/自定义）④ 导入表关键 API（`WinHttp*`/`GetAdaptersInfo`/`VirtualProtect`/`CreateFileW` 打自身）⑤ 字符串抽样（URL/端点/`card_code`/`File corrupted` 类）⑥ 签名与清单 |
| **APK / IPA** | ① 包名与入口 Activity ② 加固与壳（DEX 加密/VMP/整体加固）③ `AndroidManifest` 权限与导出组件 ④ 网络栈与 pinning 迹象 ⑤ 是否有 native `.so` 校验 |
| **Web / API** | ① 指纹与框架 ② 鉴权形态（Cookie/JWT/OAuth/Session）③ 前端路由与接口清单（从 JS 抽）④ **鉴权在服务端还是客户端** ⑤ 报文有无签名/时间戳 |
| **浏览器插件** | ① `manifest` 版本与 permissions ② `content_scripts` 注入面 ③ `background`/`service_worker` 通信 ④ 是否有 native host ⑤ 商店签名要求 |
| **固件 / IoT** | ① 文件系统类型 ② 启动脚本与监听服务 ③ 默认凭据 ④ 升级校验方式 |
| **未知/自研** | 先做"文件类型 + 熵 + 字符串三条"，再用 `seep_tool_discover` 找工具，不要硬套上面任何一行 |

**取证要求**：每条结论都要能指向"命令 + 输出片段"。没跑过的写 `?`。

## 2. 产出：目标画像卡（六字段，全系统通用）

```markdown
| 字段 | 值 | 依据（命令/输出） |
|---|---|---|
| 1 载体 | PE64 / 自定义壳 / Qt+ImGui | `rabin2 -I` + 节表 |
| 2 保护 | 节 RawSize=0 / 磁盘完整性自检? / 标题随机化 | 熵 7.35；`File corrupted` 弹框 |
| 3 授权权威 | 服务端（/login /heartbeat + 卡密） | 字符串 + 交叉引用 |
| 4 改动面 | 待定（受 2、3 影响） | 见 §3 |
| 5 检测器 | 完整性哈希、反调试、机器码 | 导入表 + 行为 |
| 6 交付壁垒 | 加密资源 20MB、心跳+本地计时 | 目录清单 |
```

## 3. 六字段不是结论，是**推理输入**（三问交叉）

| 问 | 取值 |
| :-- | :-- |
| **Q1 权威在哪？** | 磁盘文件 / 运行期内存 / 服务端 / UI 层 / 无 |
| **Q2 我的改动在哪个面可见？** | 文件字节 / 进程内存 / 网络请求 / UI 树 |
| **Q3 那个面上谁在看着？** | 完整性哈希或签名 / 反调试反注入 / pinning 或报文签名 / 自动化检测 / 没人看 |

**改动面 = 由 Q1×Q3 推出**，不要凭习惯选"内存"。
推出来的结论要写成"**路线 + 理由 + 被淘汰的路线及依据**"（阶段一要用）。

> 两条已知陷阱（**只作提示，不作规则**）：
> - 有**磁盘完整性自检**时，文件面被哈希监视 → 改文件通常在装载前就被打掉（实测：改一位 `DllCharacteristics` 即弹 `File corrupted!`）。
> - **dump 会保留运行时基址**（实测 `0x7ff65e140000` vs 原 `0x140000000`）→ 后续一切地址换算都要先对齐基址，否则白跑。

## 4. 20 分钟怎么算

- 每 5 分钟自检一次："卡里还有几个 `?`？"；
- 20 分钟到点**无论齐不齐都要出卡**，并在 §2 下方写"未解项 + 下一步该问什么"；
- 超时仍要深入 → 明确写"转 `00-analysis` D1–D7"，不要在快筛里偷偷做动态。

## 5. 需要人时怎么问（对话内 ABC，不用弹窗）

```
【需要你选】A 你自己双击启动目标（我不动鼠标）
           B 我用 explorer.exe 拉起（父进程=explorer，等价双击）
           C 先跳过，继续静态（15 分钟后我重问）
直接回 A / B / C
```

同时把完整四要素（几步 / 我监控什么 / 我保证不动什么 / 我拿到什么）写到 `case/ask/<ts>.md`；你回字母后执行 `case_state.py ask --ack A`。

## 6. 交接给 `00-analysis`

出卡后**只交接三样**：`report/triage.md`、画像卡、`case/` 目录。
`00-analysis` 只对卡里的 `?` 和"壁垒"字段花时间，不做全量重扫。
