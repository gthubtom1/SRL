# 失败判据表：看到这个现象就换路

> 范围：所有逆向任务。它不回答「怎么继续」，只回答「现在这条路是不是已经错了」。
> 用法：先在左列找现象，再看「判定」是否成立；成立就按「改走哪条」执行，不要在原路加码。
> **失败不是丢人，静默失败才是。** 每次换路必须写：旧路线为什么不通、新证据是什么、新路线凭什么更可能通。

---

## 1. 主表

| 现象 | 判定 | 改走哪条 | 代价 |
| :--- | :--- | :--- | :--- |
| 改完补丁目标立刻崩（0xC0000005/0xC0000374） | 等长/重定位/栈平衡被破坏，或改到了非标量函数 | 先做字节级反汇编确认指令槽；改走 **trampoline（代码洞 + jmp rel32）** 或只改条件跳转，不整体 `ret` | 需要额外 5–14 字节代码洞与重定位表；验证周期 +1 轮 |
| 补丁后进程活几秒到几十秒才崩 | 跳过了必要初始化/守护线程复检/延迟析构 | 改走 **只改判据分支**（`cmp`/`je`）或改全局状态字；保留原函数体 | 需要定位延迟崩溃点；可能放弃「最小字节」方案 |
| 字符串全是乱码/只能看到少量明文 | 加密/压缩未解，或 dump 的不是解密后的内存 | 先 **脱壳/等 OEP/在解密完成后 dump**；再谈字符串与算法 | 脱壳时间不可控；可能遇到 VM 保护 |
| 反编译只有 dispatcher / 大量间接跳转，没有业务语义 | VM 虚拟化或强控制流平坦化 | 不硬逆 VM；改走 **运行期内存取功能/取载荷**，或 patch 判定点 | 静态结论缺失；只能交付行为级证据 |
| 断网后功能立刻失效，联网又恢复 | 权威在服务端，或本地缓存被心跳覆盖 | 改走 **协议层**：抓包、会话分析、中继/端点接管；不要继续改本地内存 | 需要网络与证书处理；可能只能中继不能伪造 |
| 改本地授权后 UI 亮一下又退回 | 后台 Service/Updater/心跳把状态回写 | 改走 **多进程链路**：同时改 UI 读取点与服务端下发解析；必要时阻断 Updater | 需要枚举全部进程与 IPC；漏一个就回滚 |
| 只改 `license_type`/会员字段，功能仍不可用 | 该字段不是激活判据，只是分类/呈现字段 | 找 **真正的状态字/分支**（如授权状态字、`is_valid` 返回值），用交叉引用反查消费者 | 需要重建对象地图；旧补丁全部作废 |
| 只改 UI 文案/控件，重启后恢复 | 显示层从状态对象/配置/网络重新渲染 | 改走 **状态源** 或 IAT Hook 最终输出 API；不要改模板中间层 | 需要运行时控件实测；可能引入 ABI 风险 |
| 补丁后文件能启动，但签名/校验和报错 | 未重算 PE checksum、未更新 Authenticode、触发完整性自检 | 改走 **补丁清单 + checksum 重算 + 签名策略**；或改内存/代理 DLL 保持磁盘哈希 | 签名剥离会改变信任状态；代理 DLL 需要导出转发 |
| 补丁写入成功但目标行为不变 | 打错版本/打错基址/补丁被覆盖/代码未执行 | 回读目标字节；核对 SHA256 与模块基址；在补丁点下断点确认命中 | 需要重新做版本指纹；可能白改一轮 |
| 代码洞跳过去就崩，或跳回后寄存器不对 | 代码洞破坏了标志位/被调用者保存寄存器/栈对齐 | 用 **pushfq/popfq + 保存 volatile 寄存器** 的 trampoline；确认 16 字节栈对齐 | 代码洞变长；需要逐指令验证 |
| `jmp rel32` 编译报越界/运行跳飞 | 目标超出 ±2GB，或 `disp` 按错误基址计算 | 改走 **`mov rax,imm64; jmp rax`**（12 字节）或近跳板；ARM64 用 `ldr x16,#8; br x16` | 需要更大代码洞；可能破坏 CFG |
| `call [rip+disp32]` 调用到错误地址 | `disp32` 相对**下一条指令**，不是当前指令 | 重算 `disp = target - (addr + 6)`；用反汇编器复核 | 需要重写整条指令；容易连带改坏后续字节 |
| 注入器返回成功，但目标无模块/无行为 | DLL 位数不匹配、依赖缺失、DllMain 失败、被反注入 | 查目标位数与依赖；改用 **手动映射/APC/早启动**；先验证一个空 DLL 能否加载 | 可能触发反作弊/EDR；需要更早的加载点 |
| 驱动加载失败（0x577/0x241） | 签名/测试签名/安全启动/内核版本不匹配 | 改走 **测试签名环境/WHQL 签名/用户态替代**；不要在生产机反复试 | 需要重启与证书；可能不可行 |
| ARM64 上按 x64 约定读参数，结果全错 | 调用约定套错（X0–X7 vs RCX/RDX/R8/R9） | 重新按 **AAPCS64** 读 X0–X7、X29/X30；注意第 9 参数在栈上 | 需要重做全部函数签名；反编译缓存失效 |
| Mach-O 改了代码签名失效，进程被 kill | hardened runtime / codesign 校验 / library validation | 改走 **重签（ad-hoc 或自签）**、关闭 SIP 的测试机，或 DYLD 注入需 entitlement | 需要签名链与权限；分发场景不可用 |
| ELF patch 后 `Text file busy` 或段权限错误 | 运行中替换、RELRO/PIE、缺少可写段 | 停进程再改；或改走 **LD_PRELOAD/Frida** 运行期注入 | 需要重启服务；可能影响生产 |
| 时间差反调试导致单步就退出 | `rdtsc`/`QPC`/`GetTickCount` 检测到调试器 | 改走 **硬件断点/VEH 隐藏/时间函数 hook**；不要在反调试未过时继续单步 | 需要额外插件；可能被二次检测 |
| 一 attach 就被杀，换调试器也一样 | 反调试在 TLS callback/驱动/父进程检查层 | 先过 **反调试决策表**（见 `10-anti-debug.md`），再 attach；或改走纯静态 + 内存 dump | 每次 attach 成本高；可能触发自毁 |
| 算法还原后 keygen 生成的码被拒 | 输入归一化/字符集/校验位/签名链不一致 | 用 **独立实现逐字符对照**；检查 CRLF、大小写、Base 编码、尾部填充 | 需要重做算法；可能发现自引用校验 |
| 同源 Generate/Verify 互验通过，客户端仍拒绝 | 自洽测试掩盖了移植错误，或客户端还有第二道校验 | 用 **客户端真实输入输出**做黑盒测试；定位第二校验点 | 需要动态追踪；可能需要放弃 keygen 转 patch |
| 公钥替换后旧签名仍通过 | 公钥有多份副本/运行时解密/哈希校验 | 找全部副本与解密函数；或在 **验签返回值** 上打补丁 | 需要全量扫描；可能触发完整性自检 |
| 端点接管后请求全落到旧进程/旧日志 | `SO_REUSEADDR` 双绑、旧监听器未退、日志句柄未释放 | 换端口/换日志名/先杀旧进程；绑 `0.0.0.0` 而非 `127.0.0.1` | 需要清理环境；可能丢一轮抓包 |
| 回放金样后客户端静默退出 | 会话绑定/时间戳/封送体不匹配 | 改走 **透明中继**；不要继续猜字段 | 只能完成握手，不能伪造成立；结论措辞要降级 |
| 补丁清单里偏移对、字节对，但 `sha256` 不对 | 补丁前后文件被其他步骤改动，或清单未更新 | 以 **实际文件** 重算哈希；把清单版本化；回滚后重打 | 需要重建基线；旧证据作废 |

## 2. 三条熔断规则

1. **单条路径 ≤3 轮无确定性进展** → 挂起，换正交路线（静态→动态→内存→协议→资源）。
2. **内存补丁累计崩 2 次** → 停手，转协议层/代理 DLL/文件级补丁；第三次裸试改为换手法。
3. **动态 attach 被反调试打掉 2 次** → 先过反调试；第三次改纯静态或外部观测。

## 3. 换路记录模板

```text
[换路] 2026-10-21 14:05
旧路线：在 0x401290 改 je -> jmp
现象：主窗口 5 秒后自杀，事件日志 0xC0000005
判定：跳过了登录后的初始化；不是等长问题
新证据：调用栈显示 0x4012F0 读取未初始化对象
新路线：保留 je，只改 cmp 的操作数/全局状态字
代价：需要重建对象地图，预计 +2 小时
```

## 4. 失败判据（本表自身的）

- 只写「失败了」不写现象 → 无法匹配，重写。
- 换了路线但没写旧路线为什么不通 → 视为无效换路，回到原路补证据。
- 同一现象重复出现三次仍不换 → 违反熔断规则，停止并上报卡点。

---

## 5. 边界

- 本表是**决策表**，不是穷举表；新现象应追加行，不要硬套。
- 「代价」是相对估算，不是承诺；实际工时以现场为准。
- 任何换路都要保留旧证据，失败记录一律留档。

**通过长什么样**：本页给的是方法/边界，没有固定期望输出；执行后按末尾「这一篇算用对了」逐条自检，任何一条不成立就说明这一步没做对。
