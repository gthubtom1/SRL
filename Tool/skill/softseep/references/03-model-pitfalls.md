# 模型常见失误：逆向域 20 条

> 范围：使用本技能做 PE/.NET/ELF/Mach-O/ARM64 逆向、补丁、脱壳、授权分析时。
> 写法：每条固定「错误动作 → 为什么错 → 正确动作」。
> 用法：动手前扫一遍；卡住时按现象反查；复盘时把新失误追加到末尾。
> **这些不是风格问题，是会直接把证据链做废的技术错误。**

---

### 1. 把 x64 前 4 个参数当成栈传

**错误动作**：看到 `call` 前有 `push`，就认为参数都在栈上，按 `[rsp+8]`、`[rsp+0x10]` 读第 1、2 个参数。
**为什么错**：Win64 前 4 个整数/指针参数在 `RCX/RDX/R8/R9`，浮点在 `XMM0–XMM3`；第 5 个起才在栈上。栈上那 32 字节是**影子空间**，不是参数本体。
**正确动作**：先看函数入口是否把 `RCX/RDX/R8/R9` 存入影子空间；按寄存器读前 4 个参数，第 5 个起按 `[rsp+0x28]` 读。ARM64 则读 `X0–X7`。

### 2. 把 `mov rax,[rcx]` 当成虚表调用

**错误动作**：看到 `mov rax,[rcx]; call qword ptr [rax+0x18]` 就断言 `rcx` 是对象、`[rcx]` 是 vtable。
**为什么错**：`[rcx]` 可能只是结构体第一个字段（例如 `std::string` 的 data 指针、Qt 的 d 指针、COM 的接口指针）。vtable 调用通常有 `mov rax,[rcx]` 后接 `call [rax+offset]`，但也可能是函数指针表、回调表、IAT 槽。
**正确动作**：交叉验证：该对象是否由构造函数初始化、`[obj]` 指向的地址是否落在 `.rdata`、是否有 RTTI/`type_info`、同一偏移是否在多处被调用。用动态断点看 `rax` 指向的页属性。

### 3. 在 DllMain 里跨堆写 BSTR

**错误动作**：在 `DLL_PROCESS_ATTACH` 里直接 `SysAllocString`/跨模块堆分配，或调用 `LoadLibrary`/`GetProcAddress` 之外的复杂 CRT 函数。
**为什么错**：DllMain 持有 loader lock；跨堆分配、等待线程、调用已卸载模块的堆函数都可能触发 `0xC0000374`（堆损坏）或死锁。twinBASIC/VB6 运行时尤其敏感。
**正确动作**：DllMain 只做 `DisableThreadLibraryCalls` + `CreateThread`；把分配、Hook、字符串写入放到工作线程，等宿主初始化完成后再做。

### 4. 只改 UI 不改 license_type / 状态字

**错误动作**：把「试用版」标题或关于框文案改掉，就认为授权已完成。
**为什么错**：UI 只是消费者；真正的判据可能是 `license_type`、授权状态字、`is_valid` 返回值、服务端下发的 `member_status`。只改 UI 会在重启/心跳/重新渲染后回退。
**正确动作**：画「输入 → 解密 → 校验 → 状态落地 → 消费者」链路；先找状态源，再找消费者。项目 A 的实测是：只写 `license_type=5` 仍显示试用，真正开关是 `0x230CDEA` 授权状态字。

### 5. 补丁后不重算校验和 / 不处理签名

**错误动作**：写完字节就交付，`PE Checksum`、Authenticode、自带完整性自检都不管。
**为什么错**：PE 校验和、签名目录、尾部签名数据、程序自带的 CRC/SHA 自检都可能让补丁版被拒或静默退出；签名剥离还会改变信任状态。
**正确动作**：补丁清单里同时记录 `offset/original/new/sha256_before/sha256_after`；重算 PE checksum；明确签名策略（保留/剥离/重签/改内存）；跑一次完整性自检。

### 6. 把「能运行」当成「壳已脱掉」

**错误动作**：目标能启动、能看到窗口，就认为脱壳完成，直接开始静态分析。
**为什么错**：壳可以在运行期解密代码，磁盘仍是密文；内存 dump 也可能节表错位、IAT 未修复。能运行只证明加载器工作，不证明代码可读。
**正确动作**：看磁盘节熵、内存节名、OEP 是否落在原 `.text`、IAT 是否可解析、字符串是否明文；四项至少两项成立才算脱掉。

### 7. 在反调试未过时反复裸 attach

**错误动作**：第一次 attach 被杀，换 x64dbg/Frida/IDA 再试，连续三五次。
**为什么错**：反调试可能在 TLS callback、父进程检查、驱动、时间差、硬件断点层；每次裸 attach 都可能触发自毁/清场，污染证据。
**正确动作**：先按 `10-anti-debug.md` 做识别与决策；用 ScyllaHide/插件/外部观测；两次失败就停，改纯静态或内存 dump。

### 8. 把 `jmp rel32` 的位移算错

**错误动作**：`disp = target - patch_addr`，或忘记 `jmp rel32` 占 5 字节。
**为什么错**：rel32 相对**下一条指令**（`patch_addr + 5`）；`call [rip+disp32]` 相对 `addr + 6`。算错 5 字节就会跳飞到隔壁指令中间。
**正确动作**：`disp = target - (addr + insn_len)`；用反汇编器复核；跨 ±2GB 时改 `mov rax,imm64; jmp rax` 或近跳板。

### 9. 用绝对 VA 写补丁，忽略 ASLR/基址

**错误动作**：把 `0x140123456` 直接写进补丁，或在脚本里硬编码模块基址。
**为什么错**：ASLR 开启时每次加载基址不同；不同版本 ImageBase 也可能变。绝对地址只在「无 ASLR + 固定基址」时成立。
**正确动作**：文件补丁用 RVA/文件偏移；内存补丁用 `module_base + RVA`；记录 `DllCharacteristics` 的 `DYNAMIC_BASE`；代码洞跳转用相对位移或运行时重定位。

### 10. 把 `ret` 当万能补丁

**错误动作**：看到授权函数就写 `C3`，或 `mov eax,1; ret`。
**为什么错**：函数可能有初始化、栈平衡、返回值类型（字节集/文本/对象）、延迟析构、调用方约定。整体 `ret` 常导致几秒到几十秒后的访问违例。
**正确动作**：优先改条件跳转/比较/全局状态；只在确认是纯标量读取函数时改返回值；需要绕过整段逻辑时用 trampoline 保留原函数。

### 11. 在 x64 上写 `mov eax,1; ret` 却破坏栈对齐

**错误动作**：在函数入口直接覆写 6 字节，没看原指令长度和栈帧。
**为什么错**：覆写可能切断 `sub rsp,0x28`/`push` 序列，导致调用方 16 字节栈对齐被破坏；SSE 指令可能崩溃。
**正确动作**：先反汇编入口 ≥10 条指令，确认指令边界；优先用 `mov al,1; ret`（3 字节）或只改比较；必要时在代码洞恢复被覆盖指令。

### 12. 把 Qt 容器当裸指针读

**错误动作**：Frida 里直接 `ptr.add(8).readPointer()` 当 `QByteArray` 的 data，或按 `std::string` 的 24/32 字节布局读 Qt `QString`。
**为什么错**：Qt5/Qt6 的 `QByteArray/QString` 是隐式共享 d-pointer：对象本身在栈上，数据布局随版本/构建变化；读错偏移会得到长度、capacity 或垃圾。
**正确动作**：先确认 Qt 版本与构建；用运行时 `data()`/`size()` 调用或调试符号；至少用两个不同字符串验证偏移；不要只凭一个样本下结论。

### 13. 用同源 Generate/Verify 证明算法正确

**错误动作**：自己写的生成器和校验器互相通过，就宣布 keygen 可用。
**为什么错**：同源实现会共享同一个错误（字节序、字符集、移位 mod 64、填充），互相验证等于自证；客户端可能还有第二道校验/归一化。
**正确动作**：用客户端真实接受/拒绝做黑盒测试；用独立语言/独立实现逐字符对照；覆盖边界输入（空、超长、非 ASCII、CRLF）。

### 14. 把「验签调用存在」当成「真验签」

**错误动作**：导入表里有 `CryptVerifySignature` 就写「有签名校验」，或改了签名仍通过就写「无签名」。
**为什么错**：很多客户端「验了但不看返回」；签名可能只覆盖部分字段；也可能有第二处校验或服务端复核。
**正确动作**：改 1 字节签名看行为；patch 验签返回值看功能是否仍受签名影响；断点看比较结果落点；两路都做才下结论。

### 15. 只测联网态，不测断网/换目录/改时间

**错误动作**：联网跑通就认为结论成立。
**为什么错**：本地缓存、DNS、代理、系统时间、工作目录都会改变行为；服务端权威在断网时才暴露。
**正确动作**：D4 对照实验：断网、换目录、改时间、换用户、清缓存，各跑一次；记录窗口标题/功能/进程存活/请求差异。

### 16. 把随机 nonce 当会话绑定

**错误动作**：看到每次响应 token 不同，就断言「会话绑定，不能回放」。
**为什么错**：token 可能只是随机 nonce，不参与校验；真正的绑定要看服务端是否回填时间戳、响应体是否随会话封送、旧 token 是否被拒。
**正确动作**：做金样回放；如果静默退出，再用两个会话交叉替换 token/时间戳，定位到底哪个字段被校验。

### 17. 补丁清单只写「改了什么」，不写「怎么回滚」

**错误动作**：manifest 只有 offset/new，没有 original、before/after 哈希、版本、工具版本。
**为什么错**：无法验证、无法回滚、无法跨版本迁移；下一次补丁会覆盖上一次，证据链断裂。
**正确动作**：manifest 至少含 `target_sha256/version/patches[{offset,original,new,note}]/result_sha256/tool_version/rollback`；每次补丁前后复算哈希；保留 `.bak`。

### 18. 在 ARM64 上套用 x64 的栈帧/返回地址假设

**错误动作**：在 ARM64 反汇编里找 `push rbp; mov rbp,rsp`，或把 `LR` 当普通寄存器覆盖。
**为什么错**：ARM64 用 `STP X29,X30,[SP,#-N]!` 建帧，返回地址在 `X30(LR)`；叶子函数可能不建帧；`BL` 会把返回地址写入 LR，`BLR` 是间接调用；还有 PAC/BTI。
**正确动作**：按 AAPCS64 读 `X0–X7` 参数、`X0` 返回值、`X29` 帧指针、`X30` 返回地址；识别 `STP/LDP`、`SUB SP`、`BL/BLR/RET`；注意 PAC 签名与 BTI  landing pad。

### 19. `patch-verify` 只用原文件回滚，不建独立 backup

**错误动作**：manifest 只有 `patches[]`，回滚靠「把 original 字节逆写回当前文件」，或直接把原文件当备份源（`rollback.backup` 缺省）。
**为什么错**：原文件一旦被覆盖（`--out` 写成同名）、叠了第二次补丁、或被别的工具原地改写，就不存在「干净态」；按 original 逆写只能回到「上一次补丁后」的混合态，哈希与证据链全部对不上，也没法证明回滚是干净的。
**正确动作**：manifest 强制 `rollback.backup`（独立备份路径）+ `rollback.backup_sha256`；打补丁前先落备份并复算哈希，回滚**只从 backup 恢复**，恢复后复算 `sha256 == target_sha256` 才写 `ok`。`patch-verify.py` 已按此实现：没有 backup 直接 `{"ok": false, "blocked_at": "rollback-source"}` rc=2，拒绝拿当前文件冒充备份。

### 20. 把 `.symtab` 存在当「符号可用」

**错误动作**：`readelf -SW` 看到 `.symtab`，就断言「函数名齐全，可直接定位业务函数」。
**为什么错**：`.symtab` 可能只剩 LOCAL/文件名，或被 `strip --strip-debug` 保留但业务符号已删；多数发行版二进制只有 `.dynsym`（导出/导入），内部函数仍是 `sub_xxx`；Mach-O 的 `nsyms>0` 也可能是极小符号表。
**正确动作**：用 `readelf -sW`/`nm --defined-only` 统计 `FUNC` 数量与命名空间；只有 `.dynsym` 时按 `08-symbol-recovery.md` §8 走导出名 + `.eh_frame`/bind opcodes，并把「内部符号不可用」写进证据表。

## 附：三条通用自检

1. 我的结论能不能用一条命令复算？不能就降级为 `[inferred]`。
2. 我的证据有没有反证？没有反证的经验判断，最多写「疑似」。
3. 我的补丁有没有回滚？没有回滚的交付，不算工程交付。

## 失败判据与边界

- 失败判据：同一条失误在同一任务出现两次 → 停下来重写方法，不要继续堆补丁。
- 边界：本清单面向客户端逆向；服务端漏洞、密码学证明、硬件侧信道不在内。
- 版本：偏移/指令只对记录的 SHA256 成立；换版本先重跑判据。
