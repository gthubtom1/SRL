# Windows PE 脱壳与重建

接收当前构建的 PE、目标功能及可用的调试环境。先判保护层与交付目标：结构报告、运行期代码片段、重建 PE 的验收不同。许可权威在服务端、硬件或虚拟机解释器时，dump 不能自动消除这些依赖。

先读 [保护分类](../exe-reverse/references/protectors-and-packers.md)，闭环由 [unpack-loop](../../../unpack-loop/SKILL.md) 维护；按需读其 [OEP](../../../unpack-loop/references/oep-locate.md)、[转储重建](../../../unpack-loop/references/dump-and-rebuild.md) 和 [IAT](../../../unpack-loop/references/iat-repair.md)。这些是方法资料，不能作为本机动态能力已验证的证明。

## 判型与路线

从源码根执行只读入口（文件是位置参数，没有 `--binary`）：

```bash
python Tool/skill/unpack-loop/scripts/unpack-triage.py work/input/app.exe --json
```

记录 SHA256、架构、节/段映射、入口、导入、重定位、TLS 与签名。高熵、节名和壳签名是分类线索；压缩资源也会高熵。标准 UPX 可在副本上使用当前工具支持的解包方式，未知/修改壳转动态验证。运行客户目标前必须满足已有运行确认与隔离条件，工具可用不代表目标可运行。

压缩壳常在解压后跳入原代码；尾部跳转、栈恢复和写后执行可帮助定位。加密/按页解密可能只恢复执行过的路径。VMP/Themida 类保护可能始终以字节码解释执行：可以分析解释器或局部语义，不能承诺找到一个 OEP 就提纯全部逻辑。

## OEP 是交叉结论

为每个候选记录模块、VA/RVA、到达路径、触发输入和内存权限变化。核对：

- 控制流是否从解包/初始化转入业务或运行库初始化；TLS、异常回调、多个入口是否仍有壳依赖。
- 该地址附近代码及其调用目标是否语义连贯；从入口能否解释目标功能，而非仅能反汇编。
- 导入解析、延迟导入、API 转发与重定位是否就绪；残留跳板是否仍依赖保护模块。

`.text`、固定函数序言、某个 IAT 调用和“连续 20 条指令”均不是必要或充分条件。优化、尾调用、无栈帧函数及自定义节合法；随机数据也可能解成指令。

## Dump 与重建

在合适暂停点保存获准范围内的代码/映像区域及地址映射，避开凭据与私钥内存。保留原件，用独立产物记录基址、OEP RVA、区域来源与哈希。内存布局不能直接当文件布局：核对每节 VirtualAddress/VirtualSize 与 PointerToRawData/SizeOfRawData、对齐、SizeOfImage、重定位、TLS 和异常目录。不要仅修改两个头字段就称修复完成。

Scylla 等工具按实际版本和目标位数使用：候选 IAT 的边界由调用引用、导入描述符和实际 API 地址交叉确认，不能只扫连续指针直到零。处理 API-set、forwarder、延迟导入和壳跳板；保留未解析项，不伪造“全解析”。修复后的文件重新解析，再在允许的环境验证加载与原功能。

## 正反例与失败边界

正例：无经典序言、节名自定义的候选，在控制流和导入证据下成立，重建副本重启后仍完成约定功能。反例：反汇编正常但仍跳入未转储的壳页，或 IAT 指向上一次进程地址；只能交付局部分析镜像。缺重定位时一次固定基址启动不证明 ASLR 场景可用。

交付分别写“候选 OEP 已确认到什么范围”“哪些区域可分析”“独立运行是否实测”。原件哈希不变，修改清单可回读/回滚；功能回归必须覆盖约定行为。缺运行环境或关键路径未触发时保留 unknown。同形失败两次重判路线。

JNI/算法可请 softseep，判恶可请 malware-analysis；交接携带输入哈希、地址映射、问题与原输出，返回同一 project/version/run，旧构建 dump 不混用。
