# 客户端许可、激活与卡密校验审计专家战册 (License Bypass & Validation Audit)

> **核心四问（开测即答，通用所有客户端）**：
> ① **权威在哪** —— 校验是服务器审核，还是纯本地判定（离线许可/签名验证）？
> ② **本地能否完成握手** —— 能**伪造成立**，还是**只能中继**上游？
> ③ **有无捷径** —— 后门/调试开关/环境变量/隐藏参数？
> ④ **功能是否与校验分离** —— 真功能能否脱离校验单取即用（载荷/DLL/脚本/资源）？

| **G5 载荷判定** | 服务器下发载荷：导出表为空？仅导入基础运行库？无自校验/不联网？ | 成立 ⇒ **取载荷即用（Payload Carving）**，性价比最高 | 载荷有校验 ⇒ 提取密钥或协议中继 |
| **G6 交付** | 结论分级（确认利用/未闭环现象）+ 证据路径 + 载荷指纹 + 厂商侧防护清单 | 归档交付 | — |

## 1. 静态解剖（多运行时分流）

- **原生 PE 壳**：PE 头与节表解析 → 熵分析定密文段 → 明文导入表定角色；入口点在密文段内说明运行期自解密，静态字符串空属正常，直接转动态观测。
- **.NET / Mono**：元数据根 `BSJB`，直倾 `#Strings`/`#US`/`#Blob`；无混淆用 ILSpy/dnSpyEx 反编译 C#；混淆后读 CIL 指令流；自解压程序盯 `%TEMP%\\.net\\<App>\\<hash>\\`。
- **Electron / Node**：提取 `app.asar`，全局搜索 `license/activate/verify/machineId`；纯 JS 逻辑直接做离线修改；native addon (`.node`) 转原生 PE 逆向。
- **JVM (Java/Kotlin)**：解包 JAR/APK，反编译关键校验类；查找非对称签名比对函数与网络回连点。
- **Python / Go / Rust 冻结**：PyInstaller 解包提取 `.pyc` 反编译；Go 依靠 `gopclntab` 符号表还原函数名；Rust 靠 panic 路径回溯。

## 2. 端点接管与金样回放

### 2.1 等长替换合法值规则
内存补丁改写 C2 IP/域名时，值必须合法：
- IPv4 不能有前导零，不能含空字节或空格；
- 位宽不足使用 `127.100.100.10` 等同长度回环地址；
- 补丁数量阈值：一次打 **2~3 处** 安全；若一次盲打几十处极易损坏堆栈导致进程崩溃。

### 2.2 提权回环接管
```powershell
# 将远程 C2 IP 绑定到本地回环（流量直达本地监听器）
netsh interface ipv4 add address 1 <c2_ip> 255.255.255.255
# 收尾必须执行还原命令：
netsh interface ipv4 delete address 1 <c2_ip>
```

### 2.3 金样回放（Golden Sample Replay）
1. 本地监听器捕获有效请求与应答数据包；
2. 构造本地 Mock 响应服务器，向目标客户端注入已确认的通过字段；
3. 验证主界面是否唤醒、功能是否完全解除限制。

## 3. 取载荷（Payload Carving，性价比最高路径）

当加载器仅做鉴权、核心业务功能由服务端加密下发时：
1. 内存定点扫描 committed readable 内存段，寻找 `MZ` 标志与 PE 头；
2. 命中后直接从内存转储载荷二进制；
3. 若载荷导出表为空、仅导入基础运行库且无二次回连，可直接剥离独立使用，达成无须解密上游通信的成果交付。

## 4. 厂商侧防护清单（交付闭环）

1. **凭据避免明文上行**：使用动态时间戳 + 随机数计算请求签名；
2. **强制全链路 HTTPS 与证书绑定（Certificate Pinning）**；
3. **响应增加服务端会话绑定**：回填时间戳与临时 Token，防御静态回放；
4. **功能与校验不可物理分离**：核心业务算法应与鉴权逻辑强混淆，避免无校验脱壳。
先报三行：`RUNTIME / GATE / DELIVERY`，再动手。

## 2. 壳与「启动即自毁」处理（本阶段最大拦路虎）

症状识别：`0xC0000409`（FAST_FAIL）、`0xC0000005`、启动 60–90ms 无窗口退出、`abort()`、VEH 页面守卫、
`VirtualProtect` 返回 `err=87`、`.pdata` 或加密段（**段名随样本变，如 `.ace0`**）熵 > 7.5。

**先看阶段零的 I0 仪器结论**：`case_state.py show --case <case>` 里的"仪器（I0）"一栏就是你的可选手段。
- `x64dbg = blocked` → 别在调试器上耗时间，走 **Frida attach / 外部观测 / 网络层**；
- `frida-spawn = partial`（早期挂载会改变行为）→ 改成 **attach 到已运行进程**，等首个请求发出再挂钩子；
- 所有注入手段都被阻断 → 转 **网络层（冒充服务器）/ 外部观测**，不要硬上。

**路线（按顺序，失败两次即换下一条，按当前目标核实替代路线；必要能力均受限时明确未完成/blocked，写缺口与恢复条件）**：

| 路线 | 做法 | 何时用 |
|---|---|---|
| A 分支级修补 | 定位失败分支（`je → abort`），NOP/改条件；必要时把指向加密段的 `lea` 改到进程内 RWX 私有页（注意 ±2GB 偏移） | 自毁原因在单点判定 |
| B 抢先注册 VEH | 在壳注册前接管页面守卫，拦截 `STATUS_GUARD_PAGE_VIOLATION`，按需解密/放行 | 壳用 VEH 做逐页解密 |
| C 运行期注入 | 启动器 `CREATE_SUSPENDED` + 注入 DLL，在壳初始化前打桩 | 静态改不动 |
| D 脱壳 | 按 `unpack-loop`：OEP 定位 → dump → 修 IAT/段 → 重建 → 再打授权门 | 前三条都不行 |

**判据**：出现主窗口 / 主界面（或游戏内菜单）。没出现 = 本阶段未完成。

## 3. 判定权威（决定打法）

| 结论 | 依据 | 打法 |
|---|---|---|
| 客户端权威（CWE-602） | 关键判定与依赖经代码/对照证明均在客户端；无网络导入仅是线索 | 补丁字节改判定、改本地状态、伪造成立 |
| 服务端权威 | 代码/协议证明最终授权依赖服务端决定；网络库、错误码与票据字符串单独不足以证明 | 仅受控测试可模拟可验证的协议；不能伪造服务端私钥签名或服务端业务能力。缺服务器/授权接口时报告限制 |
| 混用 | 本地缓存 + 服务端二次校验 | 双验：断网与联网都要过 |

1. 双击（或一条命令）→ 原版主界面出现，贴退出码/窗口标题/截图
