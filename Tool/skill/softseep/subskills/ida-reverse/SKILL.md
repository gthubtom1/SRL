# IDA 定向分析

本技能补充 softseep/apkseep/firmware/malware 主域，不接管项目路由，不保证当前机器有 IDA 商业许可、所有架构反编译器或固定版本插件。

## 连接与目标核对

1. 先用宿主现有 IDA MCP；需要探测/启动时从仓库根执行 `python Tool/scripts/tool-acquire.py --tool ida --start --json`。未就绪时按 `MANUAL/IDA-PRO.md` 的正式安装/许可路径处理，不扫描整盘、不默认安装最新 main。
2. 用当前宿主 MCP 的发现/工具列表读真实 schema；不要把裸 JSON-RPC 的 `get_metadata` 当 MCP initialize/tools/list 握手，不假定固定工具前缀、端口、HTTP 路由或工具数量。
3. 核当前会话绑定的文件路径、架构、哈希及数据库身份，与项目当前资产一致，再做专业分析。服务可达/工具数不代表正确目标已打开。headless 等价通道优先；缺许可证/反编译器时可按目标改走 r2/反汇编，无法回答就保留 unknown。
4. 新数据库和输出放工作副本目录。打开/自动分析需有界等待，核后端状态再决定继续，不能因超时反复开同一大文件；不杀未知进程、不删已有数据库、不自动修宿主全局配置。

## 按问题取证

- 先概览格式/段/入口/导入；再从目标字符串、导入、符号或调用者定位相关函数，不全库反编译。
- 用反汇编校对伪代码的类型、符号扩展、调用约定和边界；缺反编译不能凭伪代码模板编造实现。
- 跟踪输入来源→关键判断/变换→输出，读调用者/被调者验证参数和返回值。记录地址属于 VA/RVA/文件偏移中的哪种，跨版本重新核。
- 需要重命名/注释/类型恢复时只改本项目数据库副本；补丁只在用户要求修改时做，保留原字节、语义、回滚与功能对照。
- 动态调试按已有客户目标运行许可和隔离要求；静态分析不默认启动目标。

## 返回主域

交回当前资产/版本/run、相关函数与调用关系、实际工具调用和输出、已证/推导/未知及下一项最小实验。有符号或反编译输出不等于机制已验证；结果登记到同一项目，不另造一套进度。工具不可用时说明受影响结论、替代观测及恢复条件，不承诺 r2 能等价完成任何 IDA 任务。
