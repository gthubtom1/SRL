# 01 · 旁路卡密，出「原版可用」成品

> **通用性声明**：本技能与任何具体样本解耦。文中出现的**节名**（如 `.ace0`）、**错误码**（如 `0xC000023E`）、
> **功能名**（如"皮肤库"）都是**举例**，实际以目标为准；判据看"形状"，不要照搬数字。

> **本阶段唯一的成功标准**：原版（或打过补丁的原版）**双击 → 主界面出现 → 卡密不再拦 → 所有功能能用**。
> 无界面程序（游戏辅助类）：**启动宿主 → 注入 → 宿主内菜单出现 → 功能生效**。

---

| 本阶段做 | 本阶段**不做** |
|---|---|
| 判壳、处理自毁、旁路卡密、让原版能跑、功能验收 | 改 UI / 换品牌 / 去作者信息 → 用 `02-ui-rebrand` |
| 交付补丁或注入器 + 补丁清单 + 工装 | 接自己的授权平台 / 卡密 / 到期 → 用 `03-license-hookup` |
| 保留原版界面与交互 | **绝不自己重画一套 UI**、绝不交"复刻体/仿制品" |

## 1. 开工四道门（不做就动手 = 违规）

1. 读 `softseep/SKILL.md` + 本技能 + 需要的子技能（`unpack-loop` / `ida-reverse` / `client-license-validation-bypass`）
2. `seep_auto_triage(binary_path=目标)`
3. `seep_packer_detect(binary_path=目标)`
4. `seep_kb_search("<壳名 / 自毁 / VEH / 授权>")`

先报三行：`RUNTIME / GATE / DELIVERY`，再动手。

---

## 2. 壳与「启动即自毁」处理（本阶段最大拦路虎）

症状识别：`0xC0000409`（FAST_FAIL）、`0xC0000005`、启动 60–90ms 无窗口退出、`abort()`、VEH 页面守卫、
`VirtualProtect` 返回 `err=87`、`.pdata` 或加密段（**段名随样本变，如 `.ace0`**）熵 > 7.5。

**路线（按顺序，失败两次即换下一条，但不许以"壳阻塞"结案）**：

| 路线 | 做法 | 何时用 |
|---|---|---|
| A 分支级修补 | 定位失败分支（`je → abort`），NOP/改条件；必要时把指向加密段的 `lea` 改到进程内 RWX 私有页（注意 ±2GB 偏移） | 自毁原因在单点判定 |
| B 抢先注册 VEH | 在壳注册前接管页面守卫，拦截 `STATUS_GUARD_PAGE_VIOLATION`，按需解密/放行 | 壳用 VEH 做逐页解密 |
| C 运行期注入 | 启动器 `CREATE_SUSPENDED` + 注入 DLL，在壳初始化前打桩 | 静态改不动 |
| D 脱壳 | 按 `unpack-loop`：OEP 定位 → dump → 修 IAT/段 → 重建 → 再打授权门 | 前三条都不行 |

**判据**：出现主窗口 / 主界面（或游戏内菜单）。没出现 = 本阶段未完成。

---

## 3. 判定权威（决定打法）

| 结论 | 依据 | 打法 |
|---|---|---|
| 客户端权威（CWE-602） | 无网络库 / 状态在本地文件 / 判定分支在本进程 | 补丁字节改判定、改本地状态、伪造成立 |
| 服务端权威 | 动态加载 `winhttp/wininet`、票据下发、服务端握手被中断的错误码（**如 `0xC000023E`**） | 本地票据构造 / 响应模拟（改客户端无效就别硬改） |
| 混用 | 本地缓存 + 服务端二次校验 | 双验：断网与联网都要过 |

---

## 4. 旁路实施（四选一，选副作用最小的）

| 形态 | 产物 | 适用 |
|---|---|---|
| 字节补丁 | 补丁后二进制 + 补丁脚本（原件可丢） | 未加壳、逻辑直接 |
| 代理 DLL | `version.dll` 等 + 原件（不改原件） | 原版有导入表可劫持 |
| 重打包 | APK 重签名 / 安装包重打 | Android / 安装器类 |
| 注入器 + 菜单 | 启动器 + 注入器 + 内存功能模块 | 游戏辅助 / 需要进程内钩子 |

**每改一处**：记录 `位置 | 原始 | 改后 | 语义 | 副作用`，并单独回滚验证。

---

## 5. 功能面验收（逐条打勾）

1. 双击（或一条命令）→ 原版主界面出现，贴退出码/窗口标题/截图
2. 卡密框不再出现；无"试用/到期/未授权"提示
3. FEATURES 逐项实测（**按目标实际枚举**，例：资源库、导出、批量操作、解锁数量 —— 不要照搬示例清单）
4. 重启 · 换目录 · 改系统时间 · 断网 · 联网 —— 均不回退
5. 原件未被修改（哈希一致）或改动可被补丁清单完全解释
6. 注入型：注入成功 → 菜单出现 → 开关生效 → 退出无残留、不触发反作弊自毁

---

## 6. 交付物

- **D1 可用产物**：补丁后二进制 / 代理 DLL + 原件 / 重签 APK / 启动器 + 注入器
- **D2 工装**：一条命令从原件复现 D1 的脚本
- **D3 补丁清单**（位置/原始/改后/语义/副作用/回滚）
- **D4 验收原始 stdout**
- **D5 三段式报告**（原理 → 复现 → 纵深防御），D3/D4 作附件

### 顺手记账（下次更新的前提，别省）

本阶段每改一处，立刻记账到版本账（`Tool/docs/MIGRATION.md`）：

```bash
python Tool/scripts/migrate.py init --case <case目录> --exe "<本次原件>" --version <版本号>
python Tool/scripts/migrate.py add-site --case <case目录> --version <版本号>     --id <短名> --sem "<一句话语义>" --rva 0x<位点RVA> --window 24 --wildcard-rel --orig "<原字节>" --new "<新字节>"
```

**没有账 = 原作者一更新就得从头再来**；有账，下一版用 `04-version-migrate` 半小时迁完。
