# 文档卫生（防止旧文档把下一个模型带偏）

> **要解决的问题**：同一个仓库被多轮对话反复增补，文档会按三种方式腐化——
> ① 数字过期（门禁 41 项写成 38 项）② 结论反转（"待做"其实做完了）③ 入口重复（两份 ROADMAP、两份 HANDOFF）。
> 结果：一个没有上下文的模型"读取当前项目状态"，读到的是三个月前的状态，然后写出一份错误的审查报告。
>
> **本技能的判据只有一条**：*让一个冷启动的读者，在 5 分钟内拿到与实际一致的项目状态。*

---

## 1. 什么时候用

- 用户说：整理文档 / 清理文档 / 文档太多 / 交接 / 换模型来审 / 新会话读项目 / 又出现旧数字了
- 一轮工作产生 **≥3 篇**新文档，或修改了门禁条数、版本号、能力清单
- 交接前（把仓库交给别人或另一个模型）
- 发现两篇文档对同一件事给出不同答案

## 2. 三分法（先分类，再动手）

| 类别 | 判据 | 处置 | 例子 |
| :-- | :-- | :-- | :-- |
| **权威** | 描述当下状态，且被门禁/脚本引用 | 就地改到与实测一致 | `README` 现状卡、`FORK-BRIEF`、`RELEASE` 台账、`DEFERRALS`、`DOMAIN-SPEC` |
| **历史** | 记录某天的判断与数字 | 移入 `docs/history/`，加横幅，登记到该目录 README；**不改里面的数字** | 旧审计台账、旧交接、旧优化清单 |
| **本地** | 运行产物 / 规划草稿 | 不进版本库（gitignore），文档里声明"不作现状" | `work/`、`.pi/`、`evidence/` |

## 3. 六步流程（每步都有命令）

1. **盘点**（先看报告，不靠记忆）：
   ```bash
   python Tool/skill/doc-hygiene/scripts/doc-hygiene-check.py --fix-hints
   ```
   输出 7 项体检：现状卡 / 索引分区 / 归档横幅 / 过期门禁数字 / 死路径 / 重复入口 / 预算漂移。
2. **分类**：对每处违规判定是「权威→改数字」「历史→归档」「重复→删其一」「本地→加 ignore」。
3. **处置**：
   - 权威：改到实测值（门禁数字只认 `Tool/config/gate-counts.json`，first-party 只认 `check-budget.py`）
   - 历史：`git mv <f> docs/history/<f>` → 首行加「> 历史快照（非现状）…」→ 在 `docs/history/README.md` 登记
   - 重复：保留一份权威，其余删除或改成一行指针（不要留"两份都在更新"）
4. **对齐计数**（新增/删除文件会动 first-party）：
   ```bash
   python Tool/scripts/check-budget.py            # 取实测 first-party
   # 改 MANUAL/BASELINE-FREEZE.md 与 README×3、gate-counts 里的相关数字
   ```
5. **冷启动演练**（自己当那个"没有上下文的模型"，只读文档回答 5 问）：
   ① 版本是多少？② 门禁几项、当前绿不绿？③ 先读哪两份？④ 哪些文档是历史、不能当现状？⑤ 外部审查该怎么走（只读还是可改）？
   答不上来或答错 → 回到 1。
6. **过门禁 + 提交**：
   ```bash
   python Tool/skill/doc-hygiene/scripts/doc-hygiene-check.py   # 0 违规
   python Tool/scripts/preflight.py --fast                      # 全绿
   python Tool/scripts/preflight.py                             # 全绿
   git add -A && git commit -m "docs: <改了什么/为什么>"
   ```

## 4. 判据表（可机检，脚本已实现）

| 判据 | 检查什么 | PASS 长什么样 | 误报风险 |
| :-- | :-- | :-- | :-- |
| C1 现状卡 | `README.md` / `README.zh.md` / `README.en.md` 首屏有「现状卡 / Status card」，含版本与门禁数字 | 版本 == `VERSION`；`preflight N/N` 的 N == `gate-counts.preflight_full` | 卡里只写"最新版"没写数字 → 判缺失 |
| C2 索引分区 | `docs/README.md` 分出「现状 / 审查 / 历史」 | 三个分区关键词都在 | 用同义词（"当前状态"）时需同步关键词表 |
| C3 归档横幅 | `docs/history/**/*.md` 前 15 行有「历史 / 非现状 / 归档」 | 每篇都有 | 横幅写在第 20 行会被判缺失（放在标题下一行） |
| C4 过期门禁数字 | 全仓文档声明的 `preflight N/N` 与 `gate-counts` 一致（`--fast` 口径单独放行） | 0 处不一致 | 引用历史数字做对比时需放进 `history/` |
| C5 死路径 | 不引用已搬迁/已删路径（旧 audit 目录、旧 HANDOFF 交接件、重复的 MCP 说明等） | 0 处 | 新增搬迁时同步更新这份模式表 |
| C6 重复入口 | 同一主题（ROADMAP / HANDOFF / AUDIT / README_MCP）只有一处 | 每主题 1 处 | 多语言 README 不算重复 |
| C7 预算漂移 | `BASELINE-FREEZE` first-party == `check-budget.py` 实测 | 相等 | 新增文件未提交时口径不同（先提交再看） |

## 5. 失败判据（现象 → 判定 → 改走哪条 → 代价）

| 现象 | 判定 | 改走哪条 | 代价 |
| :-- | :-- | :-- | :-- |
| C4 报某文档写 38/38 | 该文档描述的是过去 | 是历史 → 归档；是现状 → 改数字 | 归档要改引用它的链接 |
| C6 报两份 ROADMAP | 两份都在更新，必然漂移 | 留一份权威，另一份改成一行指针 | 读者多点一次 |
| C3 报归档缺横幅 | 归档会冒充现状 | 标题下一行补横幅 | 无 |
| C7 报 BASELINE 漂移 | 新增/删除文件未同步 | 先 commit，再按实测改 BASELINE | 多一次提交 |
| C1 报版本不符 | 改版本时漏改 README | 三份 README 一起改（含徽章） | 无 |
| 冷启动演练答错第 ④ 问 | 权威与历史混在一起 | 做三分法，历史全部搬走 | 一次集中搬移 |
| 用户说"别再加文档了" | 文档数量失控 | 改现有文件，不新建；新知识进案例/配方 | 需要先找到该改哪份 |

## 6. 模型常见失误（专治"看起来整理了"）

1. **只加横幅不搬走** —— 横幅在第 40 行等于没有；归档必须离开权威目录。
2. **把历史数字改成新数字** —— 那是伪造历史；历史保持原样，新结论写进权威文档。
3. **新增"新版说明"而不改旧版** —— 两份并存必然再漂移；先改旧的。
4. **删了文件不改引用** —— 死路径比旧数字更坑（模型会去读不存在的文件）。
5. **改 `gate-counts.json` / `BASELINE` 让门禁变绿** —— 数字必须来自实测；顺序是"改代码→跑实测→改基线"。
6. **把 `work/` 里的产物当交付物写进文档** —— 本地产物 gitignore，文档里只写路径约定。
7. **三份 README 只改一份** —— 冷启动读者可能看的正是没改的那份。
8. **整理完不跑门禁** —— 归档会改变 first-party 计数、链接图、措辞 lint（历史文件可能含敏感措辞，需要被扫描排除）。

## 7. 交付物

- 0 违规的 `doc-hygiene-check.py` 输出（贴进报告）
- `docs/history/README.md` 的归档登记表（新增了哪些、为什么）
- README 现状卡（版本 / 门禁 / 先读哪份 / 历史在哪）
- 一次冷启动演练记录（5 问 + 答案 + 依据文件）

## 8. 边界

- 不重写历史内容：归档文件只动「路径引用」与「首行横幅」。
- 不删用户本地规划笔记（`work/plans/`）；它们本就不进版本库。
- 不把归档塞回权威目录"临时放一下"。
- 本技能只管文档；代码/能力的判据归各域 `domain-gate`。
