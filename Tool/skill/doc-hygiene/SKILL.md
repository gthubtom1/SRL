# 文档治理：深清理 · 整理 · 遗留盘点

> **本技能不绑项目**。它只依赖两件事：一个「入口文档」（一般是 README），和一份可选的配置文件（说明哪些是历史、哪些目录不扫）。
> 没有配置也能跑：脚本会自动探测入口/索引/历史目录，并把不确定的项标成 info 让你确认。

**它要解决的不是"文件太多"，而是三个具体病症：**

| 病症 | 表现 | 后果 |
| :-- | :-- | :-- |
| **过期** | 文档写着旧版本号/旧数量/旧结论（"待做"其实做完了） | 新来的人（或 AI）按旧信息做判断，写出错误报告 |
| **重复** | 两份 README/ROADMAP/HANDOFF，各写一半 | 改一份、另一份不动，必然互相矛盾 |
| **半成品** | 文档里到处是 TODO/待补/占位/"后续再加" | 没人知道哪些是真没做、哪些是早做完了；需求与实现脱节 |

---

## 1. 三个动作，三种判据

| 动作 | 判据（做完长什么样） | 不做什么 |
| :-- | :-- | :-- |
| **清理** | 死链=0；同主题只有一份；历史文档都在归档区且带横幅；入口能直达现状 | 不删用户本地草稿（`work/`、`.scratch/` 之类） |
| **整理** | 有唯一入口；目录按职责分层（入口/规格/手册/报告/历史）；索引覆盖同层全部文档 | 不为"更好看"重排全部目录 |
| **遗留盘点** | 每个 TODO/待补/占位都被判定为四类之一（仍需要/已完成/已放弃/待确认），仍需要的汇总成**单一 backlog** | 不把遗留清单散落在 20 个文档里 |

## 2. 先跑审计（只读，不改任何文件）

```bash
python scripts/doc-audit.py --root . \
  --config .doc-hygiene.json \
  --report docs-audit.md            # 报告写到仓库外或 docs/ 都行
```

无配置也能跑（自动探测）：

```bash
python scripts/doc-audit.py --root . --json | head -40
```

输出七类发现：

| 规则 | 查什么 | 级别 |
| :-- | :-- | :-- |
| DG01 | 找不到入口文档 | error |
| DG02 | Markdown 链接指向不存在的文件（死链） | error |
| DG03 | 正文反引号里写的仓库路径不存在（搬迁后没改引用） | warn |
| DG04 | 孤儿文档：没有任何文档引用它 | warn |
| DG05 | 重复的一级标题（同一主题两份） | warn |
| DG06 | 章节高度重叠（疑似同一文档的两个版本） | warn |
| DG08 | 归档/历史目录里的文档缺「历史/非现状」横幅 | warn |
| DG09/DG12 | 长期未改动 / 内容过少（只剩指针价值） | info |
| DG10 | 同目录有文档没进索引 | warn |
| DG11 | 声明的"当前版本"与 `VERSION` 不一致 | warn |
| **DG07** | **遗留盘点：TODO/待补/占位/后续/未实现…逐行提取** | info（但必须处理） |

## 3. 配置（一份 JSON，任何项目通用）

```json
{
  "entry_docs": ["README.md"],
  "index_docs": ["docs/README.md"],
  "history_dirs": ["docs/history"],
  "ignore": ["node_modules", "vendor", "dist", "work", ".git"],
  "quiet_dirs": ["assets/docs"],
  "version_file": "VERSION",
  "history_markers": ["历史", "非现状", "归档", "historical"],
  "leftover_scope": ["docs/", "ROADMAP.md", "BACKLOG.md"],
  "leftover_strong": ["TODO", "FIXME", "待补", "待办", "占位", "未实现", "TBD"],
  "leftover_weak": ["后续", "下一步", "遗留"],
  "leftover_skip_files": ["CHANGELOG.md", "docs/history/"],
  "leftover_checkbox_files": ["ROADMAP.md", "BACKLOG.md", "TODO.md"],
  "dead_path_allow": ["examples/"],
  "orphan_allow": ["CHANGELOG.md"],
  "link_sources": ["package.json", "docs/index.json"],
  "stale_days": 365
}
```

- `link_sources`：**机器引用源**。有些文档是被代码/配置引用的（如技能清单、路由表），不是被别的文档链接——把它们列进来，避免误报"孤儿"。
- `quiet_dirs`：只检查归档横幅，其他规则跳过（适合素材库、自动生成的索引）。
- `dead_path_allow` / `orphan_allow`：已知的合理例外，写进来避免每次都人工排除。

## 4. 七步流程

1. **盘点**：跑 §2 的审计，拿报告（先看「遗留台账」与「error」两节）。
2. **分类**：把每篇文档归到 入口 / 索引 / 规格 / 手册 / 报告 / 草稿 / 历史 七类之一。
   - 判不准就看它有没有入链、有没有被代码引用、最后一次改动时间。
3. **遗留盘点**（见 §5）：把 DG07 的每一行判成四类，仍需要的进单一 backlog。
4. **合并重复**（DG05/DG06）：保留较新较全的一份，其余**改成一行指针**或删除。
5. **归档历史**（DG08/DG09）：移到 `history/` 目录 → 标题下一行加横幅 → 在归档 README 登记。
6. **清场**：死链修掉（DG02/DG03）；空壳（DG12）合并或删除；孤儿（DG04）挂进索引或归档。
7. **冷启动验收**（见 §7）+ 出报告。

## 5. 遗留盘点：四分类（本技能的核心）

**先划范围（很重要）**：遗留只从**规划文档区**取——根目录文件（README/ROADMAP/BACKLOG…）+ `docs/`。
技能文档、知识库、插件说明、判据表里的 `TODO/占位/后续` 是**技术术语或示例**，不是项目待办，扫进来只会制造噪音。
配置项 `leftover_scope` 显式声明范围；`leftover_skip_files` 用来排除 CHANGELOG 这类"按时间记录、天然含旧词"的文件。

**强弱两级标记**：
- 强标记（直接算遗留）：`TODO / FIXME / 待办 / 待补 / 待做 / 待实现 / 未实现 / 占位 / TBD`
- 弱标记（只在像清单时才算法）：`后续 / 下一步 / 遗留 / 暂不`——必须出现在 `-`/`*` 列表行或以「：」结尾，散文里的同词不算
- 另有：`- [ ]` 未勾选清单项，**只在待办类文档**（`ROADMAP/BACKLOG/TODO/plan*`，由 `leftover_checkbox_files` 指定）里才算遗留；规格、风格、评审模板里的清单是判据，不算

对 DG07 提取出的每一条，按这个判定表处理，**不许留"以后再说"**：

| 判定 | 依据 | 动作 |
| :-- | :-- | :-- |
| **仍需要** | 用户/需求文档里还能找到对应诉求；或它挡住某个已知场景 | 抄进**单一 backlog**（一个文件、带来源行号、带验收判据），原处删除或改成指针 |
| **已完成** | 代码里已有实现 / 已有测试 / 已在 CHANGELOG 记录 | 把"待做"改成"已做 + 证据（文件/命令）"，或直接删掉这句 |
| **已放弃** | 与项目方向冲突、成本高于收益、外部条件不具备 | 写成一行「不做，原因：…」，留在原处或 backlog 的"不做"区 |
| **待确认** | 无法从仓库判断（需要 owner 决策） | 标 `待确认` + 写明需要谁回答什么；**不许猜** |

backlog 格式（建议 `BACKLOG.md`）：

```
| id | 事项 | 来源 | 仍需要的理由 | 验收判据 | 优先级 |
| B-01 | … | docs/x.md:42 | … | 跑 … 看到 … | P1 |
```

**判定纪律**：
- 一条遗留只能落一个分类；同时出现多个就拆成多条。
- "待确认"超过两周没人回答 → 降级为"已放弃（无决策）"，写清原因。
- backlog 里每条都必须有**验收判据**，否则它只是愿望。

## 6. 合并 / 归档 / 删除的判定

| 情况 | 处置 | 反例 |
| :-- | :-- | :-- |
| 两个文档讲同一件事，内容互补 | 合并成一份，另一份变成一行指针 | 两份都留着"各改一半" |
| 旧版本说明 vs 新版本说明 | 旧的进 `history/`，新的改成不带版本号的权威文档 | 用 `v2.md` 命名，导致 v3 时又要 `v3.md` |
| 一次性排查记录 / 会议纪要 | 进 `history/` 或直接删（有价值的部分抽成结论进权威文档） | 把排查过程当规格留在主目录 |
| 自动生成的文件（索引/工具表） | 保留但加"自动生成，勿手改"；`quiet_dirs` 里只查横幅 | 手改生成物，下次生成被覆盖 |
| 只对外部有效的文档（供应商说明） | 放 `vendor/` 或 `references/external/`，标注来源与日期 | 与自家规格混放 |

## 7. 冷启动验收（五问，必须能只靠文档回答）

1. 这个项目是什么、**现在**处于什么状态？答案在哪份文件？
2. 新人第一步读哪三篇？顺序是什么？
3. 哪些文档是**历史**、不能当现状？（能不能一句话说出依据）
4. 现在**还有什么没做完**？答案在 backlog 的哪里？
5. 想动手改之前必须守哪些约定？写在哪份文件？

五问里任何一个答不上来 → 回到第 2 步（分类）或第 5 步（归档）返工。

## 8. 失败判据（现象 → 判定 → 改走哪条 → 代价）

| 现象 | 判定 | 改走哪条 | 代价 |
| :-- | :-- | :-- | :-- |
| 审计报 error 全是死链 | 目录搬过家但引用没改 | 先批量改引用（脚本给的是精确 file:line），再谈归档 | 一轮批量替换 |
| DG06 报两份文档 80% 重叠 | 历史上分叉过两个版本 | 选新的一份做权威，另一份抽差异补进去后删除 | 需要人工读一遍差异 |
| 遗留台账 200+ 条，无法逐条判 | 项目没有 backlog 习惯 | 先只处理"挡住当前工作"的 10 条，其余按文件分组标"未判定" | 分阶段，不能一次清完 |
| 归档后仍有文档引用旧路径 | 搬迁时漏改 | 把旧路径写成死链由 DG03 报出来，逐条改 | 一轮修 |
| 用户不想删任何东西 | 害怕丢信息 | 用"移入 history/ + 一行指针"代替删除 | 目录变深一层 |
| 每次整理完很快又乱 | 缺少入口与索引纪律 | 固定"新文档必须挂进索引"，否则下次审计会报 DG10 | 需要长期约束 |

## 9. 模型常见失误（专治"看起来整理过了"）

1. **只加横幅不搬走** —— 归档必须离开权威目录；横幅放在第 30 行等于没有。
2. **把历史里的旧数字改成新数字** —— 那是伪造历史；历史保持原样，新结论写进权威文档。
3. **遗留盘点只列清单不判定** —— 清单本身没用，四分类 + backlog 才有用。
4. **删文件不改引用** —— 死链比旧数字更坑：读者会去打开不存在的文件。
5. **新增"新版说明"而不改旧的** —— 两份并存必然再漂移；先改旧的，改不动才新建并标废弃。
6. **改版本号只改一处** —— 入口、包清单、文档标题要一起改（脚本 DG11 会抓）。
7. **把本地产物（work/、.cache/）当交付文档** —— 加进 ignore，并在入口说明"这些不是交付物"。
8. **整理完不跑审计** —— 归档/删除会改变入链、索引、版本引用，必须复跑一次到 0 error。

## 10. 交付物

- `docs-audit.md`（脚本生成：概览 + 遗留台账 + 发现清单 + 五问）
- `BACKLOG.md`（遗留四分类后的单一待办，每条带验收判据）
- 入口文档的「现状卡」（版本 / 当前状态 / 先读三篇 / 历史在哪 / 怎么自检）
- 归档 README（哪些进了历史、为什么、原路径）
- 一次冷启动验收记录（五问 + 答案 + 依据文件）

## 11. 适用范围与边界

- **适用**：任何有 Markdown 文档的仓库（代码库、写作项目、知识库、产品文档）。
- **不适合**：纯二进制资产库、自动生成的 API 文档（应交给生成器管）。
- **边界**：本技能只出**建议与报告**；是否删除/移动，由 owner 决定。涉及法务/合规文档时，归档而不删除。
