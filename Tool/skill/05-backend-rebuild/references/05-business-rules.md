# 业务规则：把"能返回 JSON"变成"行为对得上"

> API 面告诉你**有哪些接口**，数据模型告诉你**存什么**，
> 业务规则决定**什么算成功、什么算失败、重复调用会怎样**。三者缺一，回归只能测通不通。

## 1. 规则从哪来

| 来源 | 能定的规则 | 不能定的 |
|---|---|---|
| 抓包（多组样本） | 状态码、错误码、字段取值范围、分页参数 | 未触发的分支（并发、越权、过期） |
| 客户端代码/容器 | 状态机跳转、前端校验、错误文案 | 服务端兜底逻辑 |
| 页面文案/交互 | 用户可见的成功/失败路径 | 幂等、限流、计费 |
| 原厂文档/客服话术 | 业务口径（如"同一测验最多 N 人"） | 实现细节 |

规则写进报告时用**可判定的句子**："同一 `player_id + question_id` 只计一次分"，
而不是"提交要防重复"。前者能写测试，后者不能。

## 2. 演练案例的业务闭环（模板）

> 下面是 site-clone-drill01 从录制与页面推断出的闭环，属于**待验证假设**，
> 不是原厂文档；实现前先用抓包/文案逐条确认。

```text
创建测验 (POST /api/quiz)
   └─ 得到 quiz.code（分享码）
        ├─ 玩家加入 (POST /api/player, code) → player_id + 会话
        │     └─ 拉题 (GET /api/player/quiz) → 题目列表（不含答案）
        │           └─ 提交作答 (POST /api/player/answer) → 对/错 + 进度
        │                 └─ 完成页 (/player/completed)
        ├─ 成绩榜 (GET /api/scoreboard?quiz_id=)
        │     └─ 逐题答案 (GET /api/scoreboard/answers)
        └─ 分享落地页 (GET /api/share?code=)
国家/旗帜 (GET /info/country) —— 只读轮询，失败可回退默认值
```

状态机（最小集）：

| 状态 | 进入条件 | 允许动作 |
|---|---|---|
| `created` | 创建成功 | 分享、加入、查看榜单（空） |
| `playing` | 至少一名玩家加入 | 拉题、提交、榜单增长 |
| `completed` | 玩家提交完最后一题 | 只读榜单/答案/分享 |
| `expired` | 超过有效期（若原厂有） | 加入/提交返回业务错误码 |

## 3. 不变量（invariant）

写成"任何时候都成立"的断言：

1. 同一 `quiz.code` 唯一；重复创建不产生两个可用 code。
2. 玩家答案只属于一个 `player_id`；跨玩家读写要 403。
3. 分数 = 该玩家所有已判题得分之和（或原厂定义的公式），不因重算漂移。
4. 榜单排序稳定：分数降序 + 完成时间升序 + id 兜底（否则同分抖动）。
5. 未开始的测验不能提交答案；已结束的测验不能新增玩家（按原厂口径）。
6. 分享页只读，不泄露他人逐题答案。

## 4. 幂等与重试

| 接口类型 | 幂等键 | 重复调用期望 |
|---|---|---|
| 创建测验 | 客户端请求 id / 业务唯一键 | 返回同一个 `quiz_id`，不新建 |
| 玩家加入 | `code + 设备/昵称`（按原厂） | 返回同一 `player_id` 或明确"已在局内" |
| 提交作答 | `player_id + question_id` | 第一次为准，后续返回同结果（或 409） |
| 心跳 | `client_id + 时间窗` | 覆盖最近一次心跳，不追加行 |

实现位置：唯一索引 + `INSERT ... ON CONFLICT`（SQLite）或 `upsert`（PG）。
验收：同一请求连发 3 次，库里行数不变，响应一致。

## 5. 并发

| 场景 | 风险 | 处理 |
|---|---|---|
| 两名玩家同时提交最后一题 | 榜单重复/覆盖 | 事务内更新 + `version` 乐观锁 |
| 创建者重复点"创建" | 多份测验 | 幂等键 + 前端禁用（双保险） |
| 心跳与提交并发 | 会话被误踢 | 心跳只更新 `last_seen`，只更新会话行 |
| 榜单分页同时有新提交 | 重复/漏项 | 按 `(score, finished_at, id)` 稳定排序 + 游标 |

并发验收不要求压测，要求**可解释**：给出并发下期望结果，并有一条脚本能复现。

## 6. 边界值

每个数值/字符串字段至少测四类：

| 类型 | 边界 |
|---|---|
| 整数（分数/题数） | 0、1、最大值、负数、超大数 |
| 字符串（昵称/code） | 空、1 字符、最大长度、超长、Unicode/emoji、前后空格 |
| 时间 | 过去、当前、未来、时区跨日、epoch 秒/毫秒混用 |
| 列表 | 空列表、1 项、分页边界（page=0、page=最后一页+1） |
| 枚举 | 合法值、未知值、大小写变体 |

边界行为必须写进 mock/后端：`--strict` 模式下缺字段回 400，非法枚举回 400 而不是 500。

## 7. 错误码约定（与 switch-verify 对齐）

| 场景 | 码 | body |
|---|---|---|
| 路由未注册 | 404 | `{"error":"not_implemented","path":...}` |
| 方法不对 | 405 | `{"error":"method_not_allowed","allowed":[...]}` |
| 会话缺失/过期 | 401 | `{"error":"session_expired"}` |
| 无权限 | 403 | `{"error":"forbidden"}` |
| 参数缺失/非法 | 400 | `{"error":"validation_failed","missing":[...]}` |
| 业务冲突（重复/已结束） | 409 | `{"error":"conflict","reason":...}` |
| 上游失败 | 502/504 | `{"error":"upstream_failed"}` |

四类探针只验证"4xx + JSON error"，具体码由业务定；但**同一场景码固定**，不能这次 401 下次 400。

## 8. 验收判据

| # | 判据 | 机检/证据 |
|---|---|---|
| 1 | 闭环可走 | 创建→加入→拉题→提交→榜单→分享，每步有请求/响应日志 |
| 2 | 不变量有测试 | 每条不变量一个断言（脚本或 SQL 查询） |
| 3 | 幂等成立 | 同请求 ×3，行数与响应一致 |
| 4 | 错误码稳定 | 同一场景重复触发 3 次，码与 body 一致 |
| 5 | 边界可解释 | §6 每类至少一条用例，结果写报告 |
| 6 | 与录制一致 | 同输入下响应字段集合/类型与录制样本一致（值可不同） |

## 9. 失败判据

- 只实现 happy path：`switch-verify` 的错误码路径全绿也说明不了业务对。
- 榜单排序不稳定：同分玩家顺序抖动 → 前端"名次跳变"投诉。
- 重复提交产生多条答案：幂等没做，成绩会重复计。
- 用 200 掩盖业务失败：客户端会把失败当成功，后续状态全乱。
- 规则只写在代码里：报告里没有可判定句子，交接后没人能复算。
