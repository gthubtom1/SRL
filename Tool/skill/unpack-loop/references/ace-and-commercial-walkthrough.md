# ACE / 商业加固壳实战走查：从"判型"到"写清上限"的固定路径

> 加载时机：`packers-quickref.md` 已判为 **D 类（反作弊加固）** 或 **C 类（商业虚拟机保护）**，
> 你需要一份"按阶段走、每阶段有判据、失败也知道停在哪"的走查表。
> 分工：判"是什么壳"看 `packers-quickref.md`；找 OEP 看 `oep-locate.md`。本页只回答
> **"D/C 类到底能走到哪一步、走到哪必须停、停了怎么写"**。
>
> 铁律：D 类往往带**内核驱动**。装/卸/禁用驱动属于 L3 副作用，**先问用户**，默认不做。

## 0. 这类目标和普通壳的根本差别

| 维度 | 普通压缩/加密壳 | D 类反作弊加固 / C 类商业保护 |
| :-- | :-- | :-- |
| 保护位置 | 用户态 stub | 用户态 stub + 内核驱动 + 服务 |
| 检测强度 | 反调试/反 VM | 反调试 + 反注入 + 完整性 + 行为监控 + 服务端风控 |
| 脱壳收益 | 拿到可分析 PE | 常拿到"能跑但关键函数仍在 VM 里"的 PE |
| 失败代价 | 目标退出 | 驱动拦截、蓝屏、账号/机器被标记、服务端封禁 |
| 默认结论 | A 类可脱 | **M1（只做静态判型）** 起步，逐级申请上限 |

**判据**：如果你在报告里写不出"我做的是 M几"，就说明这份走查没开始。

## 1. 上限分级：先写清"我申请到哪一级"

| 级别 | 允许的动作 | 需要谁的许可 | 产出 |
| :-: | :-- | :-- | :-- |
| M1 | 只读静态：节表/导入/字符串/签名/驱动名 | 不需要额外许可 | 判型 + 能力清单 |
| M2 | 隔离 VM 内启动样本，抓进程/文件/网络（不加调试器） | 用户同意（隔离环境） | 行为面 + 环境差异 |
| M3 | 调试器附加 / 注入 / 内存 dump | 用户明确同意（可能触发反作弊） | 内存镜像、OEP 候选 |
| M4 | 内核层观测 / 驱动卸载 / 测试签名 | **必须单独确认**（L3） | 内核侧证据 |

规则：

1. 从 M1 开始，**每升一级只做一件新动作**，并记录"升级前后行为差异"；
2. 任一阶段出现"目标被驱动拦截/强制退出/机器异常"→ 立即停在该级，写 `blocked_at`；
3. 需要先确认"因为 M3 没效果，就直接上 M4"；中间必须有"为什么 M3 不够"的具体现象。

## 2. 阶段 0：判型（M1，只读，10 分钟）

```bash
# 节名/入口/导入（只读）
rabin2 -S target.exe | head -24
rabin2 -e target.exe
rabin2 -i target.exe | wc -l
# 加固/反作弊特征串
strings -a target.exe | grep -Ei 'ACE-|SGuard|TenProtect|nProtect|XignCode|EasyAntiCheat|BattlEye|Vanguard|vgk' | head
strings -a -el target.exe | grep -Ei 'ACE-|SGuard|TenProtect|nProtect|XignCode' | head
# 随包分发的驱动/服务（只看文件，不装）
ls -l drivers/ 2>/dev/null; file drivers/* 2>/dev/null
```

**通过长什么样 / 期望输出**：

```text
  idx  name      vaddr      vsize   paddr      physsz
    0  .text     0x1000     0x8a000 0x400      0x8a000
    1  .ace0     0x8b000    0x1c000 0x8a400    0x1c000
    2  .ace1     0xa7000    0x9000  0xa6400    0x9000
entry: 0x8b120        imports: 41
ACE-BASE.sys
SGuard
```

判读（三条同时成立才算 D 类定案）：

| # | 判据 | 本例 | 说明 |
| :-: | :-- | :-- | :-- |
| 1 | 出现加固专用节（`.ace0`/`.ace1`/`.tps`/`.npk`） | ✅ | 普通壳不会用这些名字 |
| 2 | 字符串/导入命中反作弊组件名 | ✅ | `ACE-BASE`、`SGuard` |
| 3 | 包内或运行目录存在对应 `.sys` 驱动 | ✅ | 有驱动 = 默认 M1 起步 |

**失败判据（别硬套 D 类）**：

- 只有 `.text` + `.rsrc`，导入正常，字符串只有"ACE"三个字母（可能是缩写/品牌名）→ 不是加固壳；
- 有 `.ace0` 节但没有驱动、字符串也不命中 → 更可能是**自研加密壳**（按 B 类走）；
- 命中反作弊名字但是**游戏启动器/更新器**（它只是调用反作弊客户端）→ 判"相邻组件"，不按 D 类定案。

## 3. 阶段 1：静态能拿到什么（M1 的产出上限）

| 问题 | 静态能不能答 | 证据形态 |
| :-- | :-: | :-- |
| 壳族/组件名 | ✅ | 节名 + 字符串 + 驱动名 |
| 是否 CLR / 是否 32 位 | ✅ | `rabin2 -I` 的 `lang`/`bits` |
| 关键逻辑是否被虚拟化 | ⚠️ 部分 | VM 节 + handler 跳转表（`vm-bytecode.md`） |
| OEP 在哪 | ❌ | 必须动态（`oep-locate.md`） |
| IAT 能否重建 | ❌ | 必须 dump 后看 |
| 鉴权判定在本地还是服务端 | ⚠️ 线索 | 网络字符串 + 导入（`WinHttp/WS2_32`）+ 服务端点 |
| 是否有完整自校验 | ⚠️ 线索 | `CryptHashData/CRC` 导入 + `.ace` 节内的校验函数 |

**判据**：M1 报告里允许出现的结论只有"组件名 + 能力清单 + 值得脱/不值得脱的判断"；
出现"已脱壳/已绕过"就是越级写结论。

## 4. 阶段 2：动态尝试（M2/M3），每次一个动作

| 尝试 | 前置 | 判据（怎么算这次做了） | 失败判据（看到即停） | 代价 |
| :-- | :-- | :-- | :-- | :-- |
| T2-1 裸启动 | 隔离 VM + 快照 | 进程存活 ≥30s，记录窗口/子进程/网络 | 启动即退/蓝屏/驱动加载失败 | 5 min |
| T2-2 驱动枚举（不加载） | M2 | `sc query`/`driverquery` 能列出对应服务状态 | 驱动已加载且拒绝查询 | 5 min |
| T2-3 调试器附加 | M3 许可 | 附加成功且目标继续运行 ≥10s | 目标退出/掉线/驱动报"检测到调试器" | 15 min |
| T2-4 内存 dump | T2-3 成功 | 能拿到主模块镜像且熵 <7.0 | 读内存被拒/目标自毁 | 20 min |
| T2-5 OEP 定位 | T2-4 | 按 `oep-locate.md` §2 核地址/到达路径、控制流语义与依赖，独立运行另验 | 两次尝试无候选 → 熔断 | 1–2 h |
| T2-6 关闭驱动后重试 | **M4 许可** | 目标仍能启动到主逻辑 | 蓝屏/系统不稳定/违反许可 | 不可估 |

```bash
# T2-1 + T2-2 的采集（Windows 侧，只读；驱动不加载/不卸载）
sc query type= driver | grep -iE 'ace|sguard|vgk|easyanti|bedaisy' 
driverquery /v | grep -iE 'ace|sguard|vgk'
tasklist /m /fi "imagename eq target.exe"
```

**通过长什么样 / 期望输出**：

```text
SERVICE_NAME: ACE-BASE
        TYPE               : 1  KERNEL_DRIVER
        STATE              : 4  RUNNING
tasklist: target.exe  4321  Console  1  128,344 K  ACE-BASE.sys
```

判读：驱动 `RUNNING` 且被目标进程加载 → 后续任何"注入/读内存"都会被内核层看见，
T2-3 失败的可解释性建立；此时报告应写"上限 M2，未申请 M3"。

## 5. 阶段 3：失败判据编号表（AC-n，引用时写编号）

| # | 现象 | 判定 | 动作 |
| :-: | :-- | :-- | :-- |
| AC-1 | 目标进程启动后 <5s 静默消失，无退出码 | 环境/驱动拦截 | 记录驱动状态；M1/M2 结论；不反复重试 |
| AC-2 | 调试器附加即被踢出（目标继续运行但掉线/退出） | 反附加生效 | 转外部观测；最多两次（熔断） |
| AC-3 | `ReadProcessMemory` 返回拒绝访问 | 内核保护 | 写 `blocked_at=protected-process`，不在本机硬绕 |
| AC-4 | dump 出的模块熵仍 >7.0 且无导入 | 未到交接点 | 回 `oep-locate.md`；两次无果即熔断 |
| AC-5 | 只在 VM 里异常、裸机正常（或反之） | 环境检测 | 做环境对照实验，标"环境相关" |
| AC-6 | 目标功能正常但关键判定不出现（无网络请求） | 判定在服务端/需交互 | 转协议层（`seep_pcap_extract`），不硬脱 |
| AC-7 | 关闭驱动后系统不稳定/蓝屏 | M4 越界或不可行 | 立即回滚快照；写"不可绕" |
| AC-8 | 每次运行关键地址/节内容不同 | 服务端下发/多态 | 记录多态证据，结论降为"行为级" |

**规则**：AC-1/AC-2/AC-3 任一命中，**该轮最多再试一次**（换手法），第二次仍命中 → 停。
这是 SKILL 两条熔断在 D 类上的具体化。

## 6. 值不值得继续：决策表（写给阶段零看）

| 条件 | 建议 | 理由 |
| :-- | :-- | :-- |
| 判定逻辑在服务端（登录/授权响应） | 停止脱壳 | 脱了也看不到判定（转协议层） |
| 关键函数在 VM 里，且只用于"反作弊积分" | 停止 | 与你的分析目标无关 |
| 关键函数在 VM 里，且是你要审计的校验点 | 做函数级（C 类） | `vm-bytecode.md` §10 的判据 |
| 只想要"它干了什么" | 走 M2 行为面 | 比脱壳便宜一个数量级 |
| 需要"离线复现算法" | 才值得上 M3/M4 | 且必须写清风险 |

**判据**：每条"继续"的决定都要能回答"拿到这个 dump 之后我要做的下一步是什么"；
答不出 → 这一步就是自嗨。

## 3bis. C 类（商业虚拟机保护）与 D 类的处置差异

| 维度 | C 类（Themida/VMProtect/Enigma） | D 类（反作弊加固） |
| :-- | :-- | :-- |
| 主要障碍 | 代码被虚拟化，dump 后语义不可读 | 内核监控 + 行为风控，操作会被看见 |
| 有效手段 | 函数级还原（`vm-bytecode.md`） | 行为面（M2）+ 协议层 |
| 无用手段 | 追求“完整 devirtualise” | 用户态 patch（内核层会拦） |
| 交付形态 | “函数输入→输出等价” | “行为时间线 + 协议结论” |
| 典型失败 | dump 成功但看不到逻辑 | 驱动拦截/掉线 |

**判据**：先按这张表选路线，再选工具；选反了就会在“脱壳”上白花一天。

## 4bis. T2-3 的三种附加方式：按侵入性排序

| 方式 | 做什么 | 判据 | 何时用 |
| :-- | :-- | :-- | :-- |
| 外部读 + 行为对照 | 只用 `ReadProcessMemory`/Procmon，不附加调试器 | 目标行为与基线一致 | 默认首选（M2/M3 之间） |
| 调试器附加 | x64dbg attach 到已启动进程 | 能停下且目标不掉线 | 需要 OEP/断点时 |
| 远程调试/内核调试 | 双机调试（网络/串口） | 目标不知道调试器存在 | 反调试只看本机进程时 |

**约束**：远程/内核调试属 M4 前置，需要双机环境与用户许可；不要在单机上“模拟”双机。

## 5bis. M4 前的可见性清单（只看，不动）

```bash
# 【占位符】把 <...> 换成你的真实路径/端口/参数后再执行
# 只读：驱动/服务/回调的存在性（不加载、不卸载、不改启动项）
sc query type= driver state= all | grep -iE 'ace|sguard|vgk|bedaisy|easyanti' -A2
driverquery /v | awk 'NR<3 || /ace|sguard|vgk/i'
fltmc filters 2>/dev/null | head -20          # 文件系统微过滤器
```

**通过长什么样 / 期望输出**：

```text
SERVICE_NAME: SGuard
        STATE              : 4  RUNNING
Filter Name                     Num Instances    Altitude    Frame
ACE-BASE                        3               328000      0
```

判读：能看到驱动 + 微过滤器 → M4 的任何动作都会被内核看见；
报告里要把“存在性”写清（这本身就是静态结论），而不是“我猜它装了驱动”。

## 6bis. 时间预算（防止在 D 类上无底洞）

| 阶段 | 预算 | 超了怎么办 |
| :-- | :-- | :-- |
| M1 判型 | 10–20 min | 判不出 → 写 `family=unknown`，转 B 类流程 |
| M2 行为面 | 30–60 min | 行为全静默 → AC-6，转协议层 |
| M3 附加 + dump | 1–2 h | 两次失败 → 熔断，停 |
| C 类函数级还原 | 2–4 h/函数 | 超时 → 只交“接口级结论” |

**判据**：每阶段结束时写下“我拿到了什么、还缺什么”；两者都空就是该停。

## 7. 报告片段（D/C 类专用，照抄改数字）

```markdown
## 加固/保护判型
- 组件：ACE 系（.ace0/.ace1 + ACE-BASE.sys + SGuard 串）
- 驱动状态：ACE-BASE RUNNING；被目标进程加载（tasklist /m）
- 上限：申请到 M2（用户同意隔离 VM 启动）；未申请 M3/M4
- 走查：T2-1 ✅ / T2-2 ✅ / T2-3 未做（无 M3 许可）
- 失败判据：无命中 AC-1..AC-8；AC-3 未触发（未尝试读内存）
- 结论：判 D 类成立；**不做脱壳**，建议走 M2 行为面 + 协议层
- 未做与原因：内核层观测需 M4 且风险不可控；关键判定疑似在服务端（配置里有 /api/v2/verify）
```

## 8. 这一类目标的三个常见误判

| 误判 | 真相 | 排除方式 |
| :-- | :-- | :-- |
| "有反作弊 = 壳，脱了就能看逻辑" | 反作弊多是**监控**，不是压缩；脱壳拿不到什么 | 看关键逻辑是否在 VM/服务端 |
| "驱动加载 = 我必须卸载它" | 卸载属于 M4 且高风险 | 默认不卸；先评估"不卸能不能出结论" |
| "VM 里跑不起来 = 样本有问题" | 多半是环境检测 | 做环境对照（AC-5），别判样本"无效" |
| "不装驱动就不算反作弊" | 驱动可延迟加载/按游戏启动 | 看服务启动类型 + 目标运行后的驱动状态差异 |
| "dump 到内存就能静态看逻辑" | C 类关键函数仍在 VM 里 | 先确认关键函数是否落在 VM handler 调用链上 |

## 9. 失败判据：走查本身失败的信号

- 说不清"当前是 M几" → 走查没开始；
- 记录里只有"试了 x64dbg，不行" → 缺现象/缺驱动状态/缺判据；
- M2 没做就直接写"M3 不可行" → 结论无证据；
- 出现 AC-7 还继续试 → 违反熔断与安全边界，立即停并回滚。

## 附：一页纸走查顺序（贴在工位上）

```text
1. 跑 §2 三条命令 → 节名/字符串/驱动三件套，定 D 还是 C（还是都不是）
2. 写下本次上限 M几 + 谁许可的（没写就不动手）
3. M1 结报告：组件名 + 能力清单 + 值不值得脱
4. 需要行为 → M2（隔离 VM，裸启动，记驱动状态）
5. 需要 OEP/dump → M3（先试外部读，再附加调试器）
6. 命中 AC-n → 记编号；同一手法第二次失败 → 停
7. 内核层（M4）只在“不卸驱动就得不到结论”时才提，并单独许可
```

判据：七步里任何一步“跳着做”，报告就不能引用本页的结论。
