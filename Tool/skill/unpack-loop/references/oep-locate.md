# OEP 定位：五种方法的适用条件与判据

> 加载时机：判定为 **B/C 类壳**（加密/虚拟化），需要"到解密完成的那一刻"。
> 铁律：**没有 OEP → 不要 dump**。dump 错点拿到的镜像，IAT 一定是坏的，后面全白做。

## 0. 先明确"到 OEP"是什么意思

OEP（Original Entry Point）= **壳把控制权交还给原始程序**的那条指令。

| 阶段 | 内存里的状态 | 能不能 dump |
| :-- | :-- | :-: |
| 壳 stub 正在解密 | 代码段还在逐段解密 | ❌ 拿到半成品 |
| 解密完成、准备跳回 | 原始代码已在内存，但 IAT 还没填 | ❌ IAT 坏 |
| **跳到 OEP 后、IAT 已填** | 原始代码 + 正常导入 | ✅ 这才是 dump 点 |

**判据底线**：dump 前必须能看到"导入表已可解析"（哪怕是部分）——否则说明还没到点。

## 1. 五法（按"成本从低到高"排，命中即停）

| # | 方法 | 适用 | 怎么做（示例，按本机版本确认命令） | 通过判据 |
| :-: | :-- | :-- | :-- | :-- |
| **1** | **尾部跳转特征扫描** | 大多数压缩壳（A 类） | 在壳 stub 尾部找 `jmp [esp]` / `pop reg; jmp reg` / `push addr; ret` | 跳转目标落在可执行节且**不是**壳自己的节 |
| **2** | **栈回溯（ESP 定律）** | B 类加密壳 | 在壳代码上单步到"返回前"，看栈顶下一个地址 | 该地址落在**原始代码节**、且前后指令像编译器生成（prologue `push rbp/mov rbp,rsp`） |
| **3** | **内存访问断点（区段写后读）** | B 类，代码段被解密 | 对 `.(D6` 类大节下"访问/执行"断点，命中后往前找跳到原始节的转移 | 断点命中次数很少（1–3 次），之后出现大段可执行代码 |
| **4** | **硬件断点（dr0–dr3）** | 方法 3 被反调试干扰时 | x64dbg：`bph`（硬件断点）设在目标节首；或设"执行"断点 | 命中时 `EIP/RIP` 在原始节内，且 IAT 已部分可解析 |
| **5** | **入口点回溯（反汇编向上）** | stub 较短 | 从 EP 向上反汇编，找 `call` 到"返回即跳走"的位置 | 能连续反汇编出合理指令（不是垃圾字节） |

**两击熔断**：同一方法连试两次不出结果 → 换方法（不要在同一方法上第 3 次）。这是 `AGENTS` 的纪律，也是 `seep-circuit` 在守的。

## 2. 判定"这是不是 OEP"的四条硬判据

| 判据 | 怎么看 | 不满足说明 |
| :-- | :-- | :-- |
| ① 在**可执行且非壳节** | 地址所属节名不是 `UPX1`/`.vmp*`/`.(D6` 这类 | 还在壳里 |
| ② 前面是**编译器 prologue** | `push rbp; mov rbp,rsp; sub rsp,X`（x64 常见 `sub rsp,28h` 等） | 可能是壳自己的跳板 |
| ③ **IAT 已可解析** | `rabin2 -i` 或 Scylla 的自动搜索能列出导入 | 还没到点 |
| ④ 能**连续反汇编** ≥ 20 条正常指令 | 不是 `ret 0x2d5a` 这种垃圾 | 数据未解密 |

**四条都满足才算 OEP**；只满足 ①② → 只能说"疑似"，要继续确认 ③④。

## 3. 反调试干扰怎么办（不清除也能过）

| 干扰 | 症状 | 不改系统的过法 |
| :-- | :-- | :-- |
| `IsDebuggerPresent` / `PEB->BeingDebugged` | 单步就崩、走到一半退出 | 在调试器里把 PEB 的该字节改 0（**内存补丁**，不改磁盘） |
| `NtQueryInformationProcess` | 返回调试端口非 0 | hook 该函数返回正常值（进程内） |
| `rdtsc` 时间差 | 单步很慢时崩 | 改用"跑一段再断"（用硬件断点代替单步） |
| 硬件断点检测（dr0–dr3） | 设硬件断点后行为异常 | 改用内存断点（方法 3），或单步到目标后立即清除 |
| 父进程检测 | 直接拒绝启动 | 用 `launch-gui.ps1 -Mode shell`（explorer 父进程） |

> 详细判据见 `references/anti-debug.md`（本技能已有 333 行）。本节只列"脱壳场景下最常见五种"。

```text
# OEP 四条硬判据的执行顺序（在调试器里逐条确认）
1) 该地址所属节不是 UPX1/.vmp*/.XXXX 这类壳节            → Sections 面板
2) 前 3-6 条指令是编译器 prologue（push rbp; mov rbp,rsp） → 反汇编窗口
3) rabin2 -i dump.bin 已能列出导入（哪怕部分）           → 命令行
4) 从该地址能连续反汇编 ≥20 条正常指令（不是垃圾字节）    → 反汇编窗口
```
