# 本域踩坑台账（UL-n）：现象 → 判据 → 动作 → 约束

> 加载时机：你正准备"再试一次"，或者复盘发现"这一步做过但没留下证据"。
> 用法：按**现象**检索编号，命中就照"动作"做；"约束"是这一条不成立的情形，**不读约束等于没读**。
> 编号规则：`UL-n`，只追加不重排（其它页/账本可能引用）。
> 与 `anti-debug-matrix.md` 的分工：那边是**目标的反调试编号（AD/AV）**，这边是**我方的流程编号（UL）**。

## 六、复盘用的检索命令（把"感觉"变成台账）

> 复盘不是写感想，是把历史工作目录里的证据重新算一遍。下面四条能生成一份"哪一步没留证据"的清单。

```bash
# 1) 每个任务目录：有没有原件/副本/回滚点/清单
for d in work/*/; do
  printf '%-40s orig=%s copy=%s rb=%s manifest=%s\n' "$d" \
    "$([ -d "$d/orig" ] && echo y || echo n)" \
    "$([ -d "$d/copy" ] && echo y || echo n)" \
    "$([ -d "$d/rb" ] && echo y || echo n)" \
    "$([ -f "$d/evid/manifest.sha256" ] && echo y || echo n)"
done

# 2) 清单是否还能校验通过（被工具悄悄改过的会出现在输出里）
for d in work/*/; do
  [ -f "$d/evid/manifest.sha256" ] && ( cd "$d" && sha256sum -c evid/manifest.sha256 2>&1 | grep -v ': OK$' )
done

# 3) 有没有"记录了口径"的 OEP/判型文件
grep -rl '"oep_rva"' work/*/evid 2>/dev/null | wc -l

# 4) 有没有"探针矩阵"结果
ls work/*/probe.json 2>/dev/null | wc -l
```

**通过长什么样 / 期望输出**：

```text
work/unpack-20260301-1015/   orig=y copy=y rb=y manifest=y
work/unpack-20260302-0902/   orig=y copy=y rb=n manifest=n     ← 缺回滚点与台账
0        ← 三段都被 grep 掉了，说明哈希全 OK（没有被悄悄改过的文件）
3
4
```

判据（可判定其"复盘合格"）：

| 输出 | 含义 | 动作 |
| :-- | :-- | :-- |
| 某任务 `rb=n` 或 `manifest=n` | 该任务不可回滚/不可校验 | 补建；补不回来就标"该任务结论仅 E1" |
| 第 2 段有输出行 | 有文件被改过且未记录 | 查明哪一步，写进台账 |
| 第 3 段计数 < 任务数 | 有任务没记 `oep_rva` | 该任务的 OEP 结论不可复验 |
| 第 4 段计数 < 任务数 | 没做探针矩阵 | 补"为什么某种仪器不能用" |

**约束**：这套命令只做只读统计；不要为了"让输出好看"去补空目录——台账的价值在于真实。

## 八、“假进展”识别：看起来前进了，其实没有

| 假进展 | 为什么是假的 | 怎么识别 |
| :-- | :-- | :-- |
| “断点命中了 100 次” | 命中热循环，没有信息量 | 看命中地址分布是否单一 |
| “dump 出来了，能打开” | 能打开 ≠ 是 OEP 后的镜像 | 熵/导入/节属性三项体检 |
| “导入修好了，条数对” | 条数对 ≠ 地址对 | `orphans=0` 校验 |
| “干净机器能跑”（同一台带调试器的 VM） | 不是干净机器 | 无调试器/无注入/无 ScyllaHide |
| “改了之后没崩” | 可能没走到校验点 | 走完整路径（首个请求/退出） |
| “反调试绕过了” | 只绕了一处，另一处静默生效 | 网络/行为对照 |
| “脱完了，但功能不全” | 可能是延迟导入/资源未恢复 | 与原件行为逐项对比 |
| “工具报 blocked，所以做不了” | 只有一种工具不行 | 换外部/ETW/网络层 |
| “哈希对得上，所以文件没改” | 工具可能只改了内存/时间戳 | 看 mtime/内部字段，不只看 sha256 |
| “样例跑通了，所以全系通用” | 单样本证明力有限 | 至少两份变体或两份密文交叉 |

**判据**：每条“进展”必须能指向一个**可复算的输出**（命令 + 结果），否则归为假进展。

## 九、复盘模板（一次失败写 6 行就够）

```text
[UL-n] 现象：<一句话，可观察>

```

**通过长什么样 / 期望输出**：

```text
[UL-2] 现象：dump 件 rabin2 -i 输出为空
证据：rabin2 -i work/dump.bin | wc -l => 0；熵 .text=7.88
根因：dump 发生在 IAT 填充之前（先于 OEP）
动作：回 oep-locate.md 用熵时间序列重定位；不修 IAT

```

判据：六行里“证据”行没有命令与输出 → 这条复盘不合格，不能进 `lessons`。

## 十、每个阶段的“到此为止”信号

| 阶段 | 继续的信号 | 停的信号 |
| :-- | :-- | :-- |
| 判型 | 两条独立证据指向同一类 | 两轮仍摇摆 → `unknown` |
| 仪器 | 至少一项非 baseline 可用 | 全部 blocked → 转外部/网络 |
| OEP | 打分 ≥9 且四条硬判据过 | 两次无候选 → 熔断 |
| dump | 两次差分主代码节一致 | 一直变 → 回 OEP |
| 重建 | 四不变量全过 | 两次修不过 → 路线 B |
| IAT | `orphans=0` | 大量壳地址 → 回 OEP |
| 验证 | 干净机器行为一致 | 只在仪器下能跑 → 路线 B |

**用法**：每阶段结束在账本里写一行“继续/停 + 依据”，这张表就是验收口径。

## 十一、把踩坑变成判据（本页的用法）

1. 每次回退/失败后，先查是否已有编号；**有就引用编号**，不要新写一段散文。
2. 没有编号且**会再犯** → 追加 `UL-n`（只加不改号），并在"约束"里写清什么情况下这条不成立。
3. 同一条坑出现第三次 → 说明不是认知问题而是流程缺失，应当补到 `SKILL.md` 的判据或脚本里。
4. 台账条目只写"可判定"的话；"注意小心"这类不可判定的表述不许进表。

## 十二、两则复盘案例（照着写，不要写“感想”）

### 案例 A：节名像 UPX，但 `upx -d` 报错

```text
[UL-9 + UL-32] 现象：target.exe 节名为 UPX0/UPX1，upx -d 报 CantUnpackException
证据：upx -l => "NotPackedException"；strings -a | grep UPX! => 无输出；rabin2 -S => UPX0 RawSize=0
根因：节名被伪造（或壳头被抹），不是真 UPX
动作：改按 B 类走 —— 熵时间序列找解密完成点 → 外部 dump → 修 IAT
约束：若找到 UPX! 但 p_info 损坏，则属改头，可先修头再试 upx -d（只两次）
代价：+2h；未熔断（换了路线，不在同一手法上耗）
```

关键：**“像”不等于“是”**；签名缺失时节名不能定案，但节名也不足以否定壳——所以换路线而不是硬修。

### 案例 B：改了一个字节就自毁

```text
[UL-3 + UL-13] 现象：在 .text 写 0xCC 后 300ms 内进程退出，退出码 0
证据：dump 两次差分 => 该字节自动恢复；rabin2 -i 命中 CryptHashData；ExitProcess 断点提前命中
根因：完整性壳（节哈希 + 自修复），改字节必然被抓
动作：放弃磁盘/内存改字节；全程硬件断点 + 外部读；需要跟流程时用 ETW 定时间窗
约束：若目标是“改后即用”的瞬时补丁且自修复周期 >1s，可试顺位 2（带回滚点）
代价：-0.5h（及时停手）；已熔断（第二次同类失败）
```

关键：**先判形态再选策略**；自修复确认后，继续改字节就只是在帮目标反调试。

## 十三、坑单的维护规则

| 规则 | 理由 |
| :-- | :-- |
| 只追加 `UL-n`，不改号、不重排 | 其它页/报告可能引用编号 |
| 每条四要素齐（现象/判据/动作/约束） | 缺约束的条目会被误用 |
| 一条坑只写一次，重复出现就改“约束”列 | 否则台账变成散文集 |
| 能落成命令的，优先落成命令（如 §六） | 可复算 > 可阅读 |
| 台账超过 3 个月未动的条目，标注“待复验” | 防止用旧经验判新样本 |
| 与 `anti-debug-matrix.md` 的 AD/AV 编号不混用 | 一个是目标行为，一个是我方流程 |

**判据**：新增条目后，`grep -c '^| UL-'` 的计数与你新增的最后一个编号对得上。
找不到编号来源的结论，需要先确认写成“经验表明”。

## 十三bis. 写报告前的三句自检

```text
1) 我引用的每个 UL/AD 编号，都能贴出对应的命令输出吗？
2) 我声称“完成”的每一步，都有两种独立方法或干净环境支撑吗？
3) 如果明天换一台机器重做，我手上的记录足够复现吗？
```

三条都答“是”才能写结论；任一条为“否” → 回对应小节补齐，
不要用“效果良好/基本可用”这类形容词填空。
