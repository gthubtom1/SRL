# UART 接入与只读观测

这是有实物、合适探针和真人操作时的条件路线。无设备时可分析已有启动日志/固件，列出缺件；不能把本机 Windows、QEMU 或文档中有命令当成硬件可用。先读 [硬件接口深度参考](../../references/hardware-interfaces.md)，镜像处理交 [firmware-extract](../firmware-extract/SKILL.md)。

输入需有设备型号/PCB、供电方式、SoC/接口资料、允许操作及现有恢复能力。拆机、测量、焊接、上电、接线由具备条件的用户完成；Agent 只接收安全测量值和过滤后的日志。JTAG/SWD/SPI 与 UART 不是同一接口，不能用串口结论冒充其他总线已验证。

## 引脚、电平与波形

断电后核已知地与候选地连通，注意屏蔽罩可能非信号地；蜂鸣不能单独确认。上电测量需先确认参考地与量程。稳定高电平既可能是供电、上拉输入，也可能是空闲 TX，万用表读到“3.3V/2V 波动”不能可靠区分 TX/RX。

用资料和示波器/逻辑分析仪确认 IO 电平与串行波形：可能是 1.8V/2.5V/3.3V，也可能是 RS-232/RS-485 等不同电气标准。不能把 5V TTL 接到未知低压 IO。USB-TTL 的标称供电电压不一定等于 TX 电平；VCC 默认不接。先共地、仅适配器 RX 监听已确认的板 TX；确认电平、方向后再接板 RX。不可在带电状态用通断档找地或试短路。

波特率从位宽测量或已知文档推导，115200/57600/38400/19200/9600 只是候选；数据位、parity、stop bit、流控与反相也要核。乱码还可能是错电平、错地、二进制输出或采样率不足，不能靠换波特率宣布引脚确认。

## Bootloader 与转储边界

先被动采集启动阶段、版本与提示。中断启动或发送字符会改变状态，仅在当前目标确需、设备操作已确认时进行；不用连续发送任意控制字符当通用方法。提示符并不等于 root，也不证明能任意读 Flash。

U-Boot 命令集是编译可选的，先看设备 `help` 和对应命令帮助。`version` 可验证版本；`printenv` 可能含凭据，不能无选择全量导出，先由用户提供不含秘密的启动参数字段。`md.b` 只用于已确认非敏感且可读的内存范围；未知 MMIO 读取也可能有副作用。

不要固定执行 `setenv bootargs`、`saveenv`、`erase`、`mw` 或 Flash 写入。需要改变启动行为另按约定目标与恢复条件评估，不以拿 shell 为每次硬件审查的必选成果。

TFTP 的普通 `tftp`/`tftpboot` 在很多 U-Boot 中是**从服务器下载到设备 RAM**，不是上传备份。只有当前构建 `help tftpput` 明确存在时才考虑其上传语法，通常是地址、大小、目的 `host:filename`，仍以设备帮助为准。本指南不提供改系统网络、启动 TFTP 服务或刷写的执行指引；网络条件由现有隔离环境提供。无上传能力可由用户按设备支持的其他只读方式取得镜像，不伪造成功。

## 正反例与验收

正例：测量证据确认电平与位宽，过滤后的两次启动记录稳定可读，设备/固件身份、串口参数与阶段均可复查。若任务仅识别 UART，这已可按约定完成。反例：只有高电平或可读几字符、没有波形和稳定控制组；只能称候选。进入提示符但命令被限也必须保留限制。

转储任务另需源地址/大小、读取方式、重复读取一致性与镜像结构，不能仅以文件存在判断；只读取不含秘密的获准范围。日志若可能含凭据须在用户侧过滤，不得先把完整日志交给 Agent。

交接保留设备身份、采集时刻、电气参数、日志来源与未知项；固件/协议辅域结果返回同一 project/version/run。同形失败两次停止接线/重试，回测量与资料核对。
