# 03 · 接自己的授权平台（卡密 / 到期 / 机器码）

> **前提**：`01-gate-bypass` 与 `02-ui-rebrand` 已完成，产物功能全通、界面已是你的品牌。
> **本阶段的唯一目标**：把"谁可以用"这件事交回给你自己的授权平台。

---

## 1. 先定模式（二选一或并存）

| 模式 | 适用 | 机制 |
|---|---|---|
| **本地离线** | 单机、不能联网、要求极简 | 卡密 = `HMAC-SHA256(机器码, 你的盐)` 前 N 位；附到期时间与功能位，整体再签一次 |
| **在线** | 要能封禁、改期、按设备限制 | 卡密 → 你的 API → 返回票据（含到期/机器码/功能位）→ 本地缓存 + 定期复验 |

> 你已有通用授权页：**默认复用它**，只改「校验端点 / 公钥 / 盐 / 产品 ID」四处，不要重画。

---

## 2. 机器码（绑定标识）

```
Win: 卷序列号 + 主板 UUID + 系统盘序列号 → 拼接 → SHA-256 → 取前 16 字节 hex
Android: ANDROID_ID + Build.FINGERPRINT → 同上
```
- 只做"取指纹"，**不做反篡改**（那是加固阶段的事）；
- 指纹变化要给出明确提示（让用户知道是换了硬件，而不是"卡密错误"）。

---

## 3. 挂载点（三处，缺一不可）

| 挂载点 | 作用 | 行为 |
|---|---|---|
| 启动时 | 首屏授权页 | 无有效卡密 → 只显示授权页，功能不可达 |
| 功能调用前 | 防止绕过首屏直接调功能 | 每次关键入口校验一次（内存缓存，别每帧验） |
| 到期后 | 只读/降级 | 明确提示到期时间，不静默失效 |

---

## 4. 对接你的授权页

| 你的形态 | 接法 |
|---|---|
| 独立授权页（网页/小程序） | 产物内置一个"登录/输入卡密"窗口，调你的 API；成功后写本地缓存 |
| 通用授权 DLL/组件 | 直接引用其 `verify(card, hwid) -> ticket` 接口 |
| 纯本地发卡（无服务端） | 产物内置公钥验签；发卡工具用私钥离线生成 |

---

## 5. 验收（五条，全绿才算完成）

1. **无卡密**：启动 → 停在授权页，功能不可达
2. **有效卡密**：输入 → 全部功能打开，重启后仍有效（缓存）
3. **到期**：把系统时间调到到期后 → 拦截并提示（或按你策略降级）
4. **换机器**：在第二台机器用同一卡密 → 按你的策略（拒绝 / 允许 N 台）
5. **断网**：离线模式正常；在线模式给出明确"需联网激活"提示，不崩

---

## 6. 交付

- 接入后的产物（含授权页/组件）
- `license-integration.md`：端点、盐/公钥、机器码算法、缓存位置、失败码含义
- 你的发卡工具（生成卡密 + 到期 + 功能位）
- 验收记录（五条各一份原始输出）

---

### 顺手记账（下次更新的前提）

授权挂载点写进版本账的 `license[]`：`id / mode（local-hmac|online-ticket）/ site（指向哪个位点）/ endpoint`。
追版时按 `site` 重挂到新 RVA，不用重新设计授权对接。

## 7. 禁止项

- ❌ 改业务逻辑或绕过点（那是 01 的事）
- ❌ 把盐/私钥硬编码到可被 `strings` 直接读到的位置（至少做异或/分段）
- ❌ 只在首屏校验、功能入口不校验（等于没校验）
- ❌ 到期后静默退出而无提示（用户会以为是 BUG）
