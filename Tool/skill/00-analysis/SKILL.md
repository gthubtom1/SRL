# 00 · 分析透彻，出可复现报告

> **本阶段唯一的成功标准**：一份报告 —— 别人拿着它、拿着同一个样本，能**照着复现每一条结论**；
> 报告末尾明确写：**能不能赢、能赢到什么程度、下一步该走哪条路**。

> **通用性声明**：文中的节名、错误码、RVA 都是举例；判据看"形状"，实际以目标为准。

---

## 0. 阶段边界

| 本阶段做 | 本阶段**不做** |
|---|---|
| 结构 / 壳 / 资源 / 字符串 / 熵 | 改一个字节、打一个补丁 |
| 运行期观测（进程、加载、出站、对照实验） | 写 build.py / 造交付物 / 打包 |
| 授权面：权威在哪、门禁形态、钥匙在哪 | 接授权平台（那是 03） |
| 可行性裁定 + 推荐路线 + 成本先验 | 宣布"已交付 / 已可用" |
| 事实账 `facts.jsonl`（结论 + 证据 + 失效条件） | 把旧报告当自己的证据 |

**出口判据**：报告 8 节齐 + 每条结论有证据编号 + 可行性裁定明确 → 才允许进 `01-gate-bypass`。

---

## 1. 为什么必须有阶段 0（血案）

某次会话：**第 20 秒、只做了 4 次 `ls`/`head 上一轮报告`**，就报出了贯穿全程的 GATE 结论（还是照抄旧报告），
**3 分 46 秒后**开始写 `build.py`，3 小时 35 分后发现方向从一开始就错：

| 时间 | 它说 | 实际 |
|---|---|---|
| 第 1 分钟 | "无网络库 → 授权权威**纯客户端**" | 运行时动态加载 `winhttp.dll` → **服务端权威** |
| 第 46 分钟 | 改判"注入型 + 在线鉴权" | 对，但两小时已花在错误方向上 |
| 第 90 分钟 | "服务器连不上了"（真正答案） | 对，但本可在第 10 分钟说出 |

**结论：不是分析太少，是结论先于分析、把旧报告当证据。在错误结论上加速，是最贵的失败模式。**

## 2. 分析深度门（D0–D5，缺一级不许出报告）

| 深度 | 要做到什么 | 通过判据（写成证据编号） |
|---|---|---|
| **D0 结构** | 节表 / 资源 / 导入 / 字符串 / 熵 / 壳线索 | 能说出"东西都在哪"，并给出节表与关键资源清单 |
| **D1 存活** | 进程能否到**第一个窗口**；**双击 与 程序拉起分别测** | 两种方式各有明确结果（这次差异就是关键线索） |
| **D2 动态依赖** | **运行时**加载了哪些网络/加密库（加载器视角，不看 import 表） | 列出实际加载的 DLL 与时间点 |
| **D3 出站行为** | 一次抓包：DNS/TCP 数量、明文或 TLS、请求时机 | 能画出"第几秒发了什么" |
| **D4 对照实验** | 断网 / 换机 / 换目录 / 改系统时间，各重跑 | 每项都能说"变 / 不变" |
| **D5 钥匙归属** | 关键资源与密钥：文件里就有？内存里？还是授权后才产生 | 能指出"缺哪一把、什么时候产生" |

**铁律**：

1. **旧报告只能当 `hypothesis`**；照抄别人结论 = D0 都没过；
2. 每条结论挂证据编号（`GATE = 服务端权威 [D2,D3,D4]`），没编号的写"待验"；
3. D0–D2 没过，**不许写任何交付物**；第一个写入文件只能是 `facts.jsonl`；
4. 每 20 分钟写进度账（已证 / 待验 / 下一步 / ETA）；两次无新增证据 → 停手重判，并主动找**能推翻当前结论**的证据；
5. 结论改口必须写"旧结论 + 被哪条证据推翻"，不许静默翻案。

## 3. 报告结构（8 节，缺一节不算完成）

| 节 | 内容 | 必带 |
|---|---|---|
| 1 指纹 | hash / 大小 / 格式 / 架构 / 节表 / 熵 / 壳线索 | 命令与输出片段 |
| 2 结构地图 | 资源容器、UI 引擎、关键字符串表、配置/状态文件 | 偏移与提取方法 |
| 3 运行期行为 | D1–D4 全部结果 | 时间线（第几秒做了什么） |
| 4 授权面 | 权威（本地/服务端/混用）、门禁形态、校验点、票据/钥匙 | 证据编号 |
| 5 资源与钥匙 | 资源在哪、是否加密、钥匙何时产生、能否离线取得 | D5 结论 |
| 6 **可行性裁定** | 可赢 / 部分可赢 / **不可赢** + 天花板一句话 | 依据（哪几轴满分） |
| 7 **推荐路线** | 策略矩阵查表结果 + 成本先验 + 首选/备选 | 为什么选它、失败判据 |
| 8 待验清单 | 还没证实的假设 + 怎么验 + 影响哪个决策 | 编号 |

**"可复现"的定义**：每条结论后面都有 `[工具 + 命令/参数 + 关键输出]`。只写"经分析发现"= 不算证据。

---

## 4. 可行性裁定（这一节比技术细节更重要）

按五轴打分（0–5），任何一轴 5 分都要在裁定里点名：

| 轴 | 0 | 5 |
|---|---|---|
| 壳 / 虚拟化 | 无 | VMProtect / Themida / 自研 VM |
| 权威位置 | 纯本地 | 服务端全权 + 票据 + 吊销 |
| 交付形态 | 改字节 | 注入 + 反作弊对抗 |
| 环境耦合 | 无 | 硬件绑定 / 驱动检测 |
| 外部依赖 | 自包含 | 服务端已停 / 必须卡密才有钥匙 |

| 裁定 | 含义 | 允许进入的阶段 |
|---|---|---|
| **可赢** | 各轴 ≤ 3 | 01 → 02 → 03 |
| **部分可赢** | 有一轴 = 5 但可绕 | 01（只交 M2，标注受限点） |
| **不可赢** | 钥匙在服务端且服务端已停 | 只能交 M1 + 天花板声明；**不许承诺成品** |

> **早 10 分钟说"这条路走不通，能给你的是 M1"，比 3 小时后交一个用不了的东西有价值得多。**

## 5. 交付物（本阶段只交这三样）

| # | 产物 | 说明 |
|---|---|---|
| A1 | `analysis-report.md` | 上面 8 节，含证据编号与命令 |
| A2 | `facts.jsonl` | 一行一条：`{id, claim, status(proven/hypothesis/refuted), evidence[], how, ttl, refuted_by}` |
| A3 | 可行性裁定 + 推荐路线 | 报告第 6、7 节，**必须能一句话说给非技术用户听** |

**这三样不是靠自觉，是有闸的** —— 用 `Tool/scripts/case_state.py` 记账，`gate` 不给过就进不了阶段一：

```bash
C=<case目录>
python Tool/scripts/case_state.py init    --case $C --target "<样本>"
python Tool/scripts/case_state.py claim   --case $C --id C01 --text "权威在服务端" --status hypothesis --how triage
python Tool/scripts/case_state.py prove   --case $C --id C01 --evidence "procmon: 第1秒 winhttp 请求"
python Tool/scripts/case_state.py refute  --case $C --id C01 --by C05          # 旧结论保留，不删
python Tool/scripts/case_state.py depth   --case $C --level D2 --result pass --note "LoadLibrary 命中 winhttp"
python Tool/scripts/case_state.py verdict --case $C --value 部分可赢 --note "钥匙在服务端，服务端已停"
python Tool/scripts/case_state.py gate    --case $C        # 出口闸：不过就 exit 1
python Tool/scripts/case_state.py resume  --case $C        # 换会话接续：已证/待验/下一步
```

闸会拦住这些：深度没登记、`proven` 没证据、`proven` 没写"怎么测的"、没给裁定、
裁定"不可赢"却想按 M3 交付（会自动压回 M1）。

**裁定 → 交付上限（不许自己抬）**：

| 裁定 | 交付上限 | 允许的成品 |
|---|---|---|
| 可赢 | M3 | 完整成品（能跑 + UI 自家 + 授权自家） |
| 部分可赢 | M2 | 功能面通，但必须列出受限项 |
| 不可赢 | M1 | 只证明"能起、能进界面"，**不许承诺成品** |

**不许交**：exe / dll / 补丁 / build.py / "已可用"结论。

## 6. 完成判据（打勾才算过，然后进 01）

1. D0–D5 六级都有产物或明确"做不到 + 为什么"；
2. 8 节齐全，每条结论有证据编号；
3. `facts.jsonl` 里没有"没有 evidence 的 proven"；
4. 可行性裁定明确，且与 01 的交付形态一致；
5. 推荐路线写清首选/备选 + 成本先验 + 失败判据。

---

## 7. 禁止项（出现即返工）

- ❌ 读了旧报告就直接下结论（这是本次血案的第一因）
- ❌ 20 秒 / 几次 `ls` 就报 GATE
- ❌ 本阶段写 build.py、造交付物、宣布"能用"
- ❌ 用"看起来像 / 应该是"代替实测（D1–D4 全都要真跑）
- ❌ 结论改口不留旧结论与被推翻的证据
- ❌ 把"不可赢"包装成"部分可赢"去迎合期待
