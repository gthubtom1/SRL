# Seep 优化路线图（2.0）—— 从"能不能做"到"凭什么说做成了"

> **这份文件是跨会话的接力棒**：上下文被压缩、换模型、隔几天再来，读这一份就能接上。
> 记录时间：2026-10-21 / 当前版本 **v1.15.0**（commit `a660eb3`）

---

## 0. 一句话现状

Seep 1.x 解决的是「**能不能做**」（工具、技能、路由、追版都已就位）；
Seep 2.x 要解决的是「**凭什么说做成了**」—— 结论必须有证据，交付必须分级，进度必须能接续。

**已落地的三条主线**：阶段链（⓿→①→②→③→④）、三本账（facts / state / manifest）、五道闸（见 §3）。

---

## 1. 三场血案（这是所有设计的依据，别丢）

### 血案 1：结论先于证据（会话 `01a15c01`）

| 事实 | 数值 |
|---|---|
| 会话开始 → 报出 GATE 结论 | **20 秒** |
| 报结论前的工具调用 | **4 次**，全是 `ls` / `head 上一轮报告` —— 没碰过二进制 |
| 结论 → 开始写交付物 | **3 分 46 秒**（`standalone/build.py`） |
| 结论实际对错 | 错。第 1 分钟判"无网络库→权威纯客户端"，第 46 分钟改判"动态加载 winhttp→服务端权威" |
| 全程 | 3 小时 35 分、191 次 bash、2 次 MCP、结论翻案 4 次（全部静默） |

**根因**：把旧报告当证据，结论写在分析前面 → 后面 3 小时都在错误方向上加速。

### 血案 2：仪器可行性排在最后

| 时间 | 事件 | 代价 |
|---|---|---|
| 01:23（14 分） | 用错误前提"原件起不来"（实为启动方式不同）→ 定"独立重实现" | 2 小时造复刻体 |
| 02:21（71 分） | 才发现资源管理器双击启动是正常的 | — |
| 02:38（88 分） | 才发现 Frida attach 能挂住、进程不死、76 模块可见 | — |
| 03:08 | 才摸到反调试边界：**早期挂载会让它静默不发网络请求** | — |

**根因**："哪些仪器能用"是第 5 分钟该知道的事，被拖到第 2 小时。

### 血案 3：能力在手却不用（工具纪律）

同一场会话：MCP `seep_*` 只调用 **2 次**（一次 triage、一次 describeTool），其余 **191 次 bash 手搓**。
另有 `tool-run.ps1` 无 BOM 导致 PowerShell 5.1 解析失败、`Start-Process -RedirectStandard*` 让 GUI 子进程占句柄把调用方挂死等已在 v1.11.2 修复。

## 2. 现在的骨架（五阶段 + 三本账）

```text
⓿ 00-analysis        分析透彻 → 8 节可复现报告 + 可行性裁定
      │  前置：I0 仪器可行性（6 种探针）
      ▼  闸①：case_state.py gate（深度齐 / 证据齐 / 裁定明确 / 仪器登记）
① 01-gate-bypass     旁路卡密 → 原版可用（M1 存活 → M2 功能面 → M3 成品）
      ▼
② 02-ui-rebrand      改 UI / 换品牌 / 去作者
③ 03-license-hookup  接自家授权平台
④ 04-version-migrate 作者更新 → 按版本账追版
```

| 账本 | 路径 | 记什么 | 谁读 |
|---|---|---|---|
| 事实账 | `<case>/facts.jsonl` | 结论 + 证据 + 怎么测的 + 失效条件 | 闸①、换会话接续 |
| 状态 | `<case>/state.json` | 深度登记 / 仪器登记 / 裁定 / 交付上限 / 下一步 | 闸①、闸② |
| 版本账 | `<case>/versions/<ver>/manifest.json` | 位点 AOB / UI 素材 / 授权挂载点 | 阶段④ 追版 |

## 3. 五道闸（规则不靠自觉，靠脚本拦）

| 闸 | 命令 | 拦什么 |
|---|---|---|
| ① 阶段零出口闸 | `case_state.py gate --case <C>` | 深度缺项、`proven` 无证据、`proven` 没写 how、无裁定、**无仪器登记**、裁定"不可赢"想按 M3 交付 |
| ② 阶段一前置闸 | 同上，01 技能要求先 PASS | 没证实可行性就开始做成品；超过裁定上限（M1/M2/M3）交付 |
| ③ 分级闸 | 01 技能 §5 | "文件生成了"冒充"功能可用了" |
| ④ 代码门禁 | `preflight.py`（15 项） | ps1 编码、八层发现、路由自洽、新脚本可运行、可移植路径 |
| ⑤ 全量体检 | `setup/verify.ps1` / `verify.sh`（61 项） | 扩展资产在位、脱敏、预算、安装一致性 |

**常用自检三连**：

```bash
python Tool/scripts/preflight.py --fast          # 15/15，约 3 秒
powershell -File setup/verify.ps1                # 61/61，约 55 秒
python Tool/scripts/case_state.py resume --case <C>   # 换会话先看这个
```

## 6. 目标形态分类（决定"能不能做成成品"）

| 形态 | 典型目标 | 首选路线 | 到 M3 的可能 |
|---|---|---|---|
| A 本地权威 + 无壳/轻壳 | 国内小工具、辅助、激活器 | 字节补丁 / 代理 DLL | 高（30 分–2 h） |
| B 托管运行时 | .NET / Electron / JVM / Python-Go 打包 | 反编译改 IL / asar / jar / 字节码 | 高（1–4 h） |
| C 本地权威 + 重壳 | VMProtect / Themida / 自研 VM | 分支修补 / 抢先 VEH / 注入 / 脱壳 | 中（4–8 h，可能只到 M2） |
| D 注入型 + 本地鉴权 | 游戏换肤、加载器 | 启动器 + DLL + 菜单 | 中高（受反作弊影响） |
| E 服务端权威（服务端活） | 在线卡密、订阅制 | 票据构造 / 响应模拟 / 协议重放 | 中（2–6 h） |
| F 服务端已停 / 钥匙只在服务端 | 6.8/6.9 这类 | 静态全解 + 界面可用 + 钩子就位 | **低（上限 M1，必须明说）** |
| G 驱动级反作弊深度注入 | 竞技类 | 外部工具替代（叠加/截屏/识别） | 低（换路线才可能 M3） |
| H 纯云渲染 / 硬件绑定跨机 | 云游戏 / TPM 绑定 | 中继 / 绑定层伪造 | 低（M1–M2） |

**纪律**：形态 F 一旦判定，报告必须写"不可赢 + 天花板一句话"，**禁止**承诺成品。

## 7. 明确不做（防重新变回堆料）

| 不做 | 原因 |
|---|---|
| 不再加新工具 / 新技能包 | 问题不是能力不足，是纪律不足 |
| 不做"万能逆向框架" | 每类目标最优路径不同，框架只会更慢 |
| 不追求全自动 | 判型与可行性裁定必须留人或强模型 |
| 不让 flash 级模型做判型 | 20 秒错判的代价是 2 小时 |

## 8. 接续方式（给下一个会话的 AI）

1. 读本文件 §0–§5，知道现在在哪一步；
2. `python Tool/scripts/preflight.py --fast` 确认环境是绿的（15/15）；
3. `python Tool/scripts/case_state.py resume --case <C>` 看手上这个案子做到哪；
4. 从 §5 的 **批次 B** 开始，按表里的验收标准做完再进下一批；
5. 每批收尾：`verify.ps1` 61/61 + CHANGELOG + VERSION 递增 + commit + push。
