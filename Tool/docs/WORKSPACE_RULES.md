# 工作空间任务隔离与目录管理规范 (Workspace Rules)

> 本文件说明工作空间的目录约定。任务范围由用户提供的 scope 决定；本文件只管「产物放哪」。

---

## 核心约定：一任务一目录，根目录只留平台组件

所有在本工作空间开展的任务（逆向分析、漏洞挖掘、POC 复现、补丁研发、解包审计），按下面的约定组织产物。

### 1. 每个任务一个独立目录
- 接到任务时，先建以任务/目标命名的目录（`tasks/<目标>/` 或 `<目标>/`，如 `xyplorer/`、`mumu/`、`Hills/`）。
- 临时文件、提取物、解压结果、运行输出都放在该任务目录内，根目录保持只有平台组件。

### 2. 全生命周期产物归位
- 过程产物：分析日志（`*.log`）、抓取与截图（`*.png`、`*.jpg`）、中间提取（`*.txt`、`*.csv`、`*.json`）、
  汇编/机器码/内存 dump（`*.bin`、`*.dmp`、`*.id*`）、补丁代码与构建脚本（`*.c`、`*.py`、`*.ps1`、`*.dll`、`*.exe`）。
- 以上产物统一放在对应任务目录内，任务结束时整体归档或清理。

### 3. 命令执行上下文
- 根据工具要求选择 cwd。文档中的 `python Tool/scripts/...` 和安装命令从仓库根执行，用户材料与输出使用明确项目路径；需要就地生成产物的分析工具在任务目录运行，平台脚本使用绝对路径。不要切到任务目录后继续套用仓库相对命令。

### 4. 根目录保留项
- `Tool/`：全局工具链、通用脚本（`Tool/scripts/`）、技能与配方。
- `setup/`、`MANUAL/`、`docs/`：安装、手册、审计记录。
- 各任务独立目录（如 `Hills/`、`mumu/`、`xyplorer/`）。
- `Tool/docs/WORKSPACE_RULES.md`：本规范。

### 5. 与案例库的关系
- 可复用的产物按 `Tool/cases/<case>/` 归档，结构见 `Tool/cases/_templates/`；
- 任务目录里的过程文件留在任务目录，需要沉淀时再抽成案例。
