# 自主执行与长任务接续

本约定适用于九域任务和日常开发；当前用户指令、已有任务范围和宿主实际边界优先。它不创建新的运行许可，不要求简单任务进入专业案件流程。

## 1. 正常工作由 Agent 完成

用户说明目标后，Agent 自行阅读、查证、修改工作副本、调用工具、运行相称的测试/构建、启动本地服务和必要界面操作。已有范围直接沿用，不因工具调用、重启目标、切换主辅域或换会话重复索取许可。

日常开发不要求 lab、壳判型、四档上限、运行回执或专业报告。长期、多版本、多设备任务需要恢复时使用现有项目记录；现有 `autonomy.json` 可继续作为长任务偏好，不是自主工作的前置条件。

## 2. 何时才需要用户

- 缺少无法从项目和工具取得的用户独有输入、实体设备或必要选择。
- 新目标、环境或实际影响超出已有范围，或用户明确拒绝/撤回。
- 当前工具不能完成必要的本人验证、解锁或实体操作。
- 确实无法替代的权限/服务阻断，需要用户改变外部条件。

请求说明实际错误、为何现有能力无法解决、最少需要的动作和恢复点。可使用对话或宿主询问工具；用户不需要选择内部工具、编辑配置或执行普通技术步骤。缺口互相独立时合并询问，等待时继续不依赖答案的工作。

没有新增技术证据应先重判假设与路线；等待多久不是必须询问的理由，也不能用 30 分钟计时阻止及时询问真正缺失的信息。

## 3. 失败后诊断与继续

同一输入失败后先读取实际错误和状态，修复参数、源码或环境，按需换可用通道。相同调用无新证据连续失败两次，暂停该重复调用；不是停止整个任务，更不是默认由用户执行。

成功修改代码后允许再次运行同一测试；参数、目标和子命令不同的操作不应被误合并。副作用可能已发生的超时调用先观察状态，不能直接重放。工具成功不等于业务成功，必须检查后置条件。

## 4. 环境与凭据

日常宿主的全局网络、驱动、服务、引导、信任根与破坏性磁盘操作继续按现有边界保护。实验客户机、设备、容器和远端位置分别核对；名称含 vm、可回滚或做过快照都不能替代真实范围。不得把禁止动作转交用户或改用 GUI 绕过。

凭据、Token、Salt 和私钥在任务范围内可读可用；落盘只进 `~/.seep/secrets/<case>/`，不进入 git 跟踪文件、报告、交付材料或工具回显。已有安全输入通道可自主使用；缺少安全传递能力才请用户代输。凭据仓的清理按实际持有生命周期处理，不在仍需恢复时无条件删除。

仅在确有已授权可逆环境变更时使用既有 `env-ledger.py` 记录 before/after/restore。台账是记录和恢复工具，不授予系统修改权限；本约定不提供停驱动、改全局代理或改系统时间作为日常默认动作。

## 5. 长任务与收尾

长期任务定期记录已证事实、待验、已排除假设、下一步和具体阻碍；已有 project/version/run/case 继续复用，不另建账本。简单变更用会话和验证结果即可。

退出前检查本次拥有的服务、进程、连接和可逆变更。只关闭本次资源，不按名称杀掉用户已有进程，不覆盖用户未提交改动。需要保留运行环境供接续时明确记录，未清理事项如实报告。完成状态根据任务验收决定，不能只因文件生成或退出码为零就结案。

相关入口：`Tool/docs/EXECUTION.md`、`Tool/prompts/AGENTS.md`、`REQUIREMENTS.md`、`docs/CURRENT-STATE.md`。
