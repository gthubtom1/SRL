# 反作弊客户端取证与兼容性分析（只读取证面 + 判据）
- 触发词：反作弊、anti-cheat、EAC、BattlEye、Vanguard、驱动、兼容性、取证、驱动兼容、兼容层
- 输入（用户提供）：`<客户端安装目录>`、`<驱动 .sys>`、`<内存或崩溃转储>`、`<EVTX/hive>`、`<pcap>`、`<兼容性矩阵>`；范围由用户提供的 scope 决定，取证面只读。
- 用到的能力（capability id）：`tool:pe-sieve` `tool:capa` `tool:ghidra` `tool:ida` `tool:tshark` `repo:case_state` `repo:driver-triage` `repo:forensics-check` `repo:fs-timeline` `repo:pcap-summary` `repo:evidence-accept`
- 步骤：1) `python Tool/scripts/case_state.py init --case work/<case> --target <CLIENT>`，记录版本、哈希、采集时间与时区；2) `python Tool/skill/malware-analysis/scripts/driver-triage.py --file <DRIVER.sys> --json --top 20`，记录静态设备名/IOCTL 线索、危险导入与风险分；3) 对已确认不含真实秘密的测试镜像运行 `python Tool/skill/forensics-mobile/scripts/forensics-check.py --file <MEMORY.dmp> --json --out work/<case>/mem`，只得类型候选、哈希、文件时间与有限标记偏移。按 `Tool/skill/malware-analysis/subskills/memory-forensics/SKILL.md` 与 `Tool/skill/forensics-mobile/references/memory-forensics.md`，先核格式/系统/符号及实际插件帮助，再由 Volatility 3/MemProcFS 等解析所需实体；真实内存只接用户侧筛选的安全输出。保存工具/插件/符号身份、镜像哈希与原输出；缺工具/符号/安全材料记 blocked/unknown，不能用初检代替；4) `python Tool/skill/forensics-mobile/scripts/fs-timeline.py --input <EVTX> --input <HIVE> --out work/<case>/artifacts/timeline.json --json`，统一 UTC；5) `python Tool/skill/protocol-plugin/scripts/pcap-summary.py --file <PCAP> --json --out work/<case>/net`，对齐端点/时间，消息语义由 protocol-plugin 辅助核验；6) 兼容性矩阵写 `work/<case>/compat-matrix.json`（OS build、驱动签名、HVCI、游戏版本、实际结果与未测项），`python Tool/skill/forensics-mobile/scripts/evidence-accept.py --case <case> --json`；7) 主域 forensics-mobile 接回辅域静态/协议结果到同一 project/version/run。兼容性运行结论需对应环境实测，仓库检查不替代目标验收。
- 判据：静态驱动字符串仅是线索；内存实体结论需匹配解析器的进程 PID/创建时间、模块地址/路径及实际句柄表输出，按目标问题选择，不强求每份转储含全部对象；注入页需映射/代码与独立行为互证。`hints` 与 `extractables` 不证明实体已解析，初检 `ok=true` 也不证明没有隐藏/注入。timeline 事件四要素、PCAP 时间和兼容性矩阵各留原始证据，接受脚本通过不升级专业结论。｜不行就换：缺格式/符号 → 保留初检范围并列所缺；缺内存材料 → 用日志/崩溃转储支撑限定结论，不宣称完成内存实体分析。
