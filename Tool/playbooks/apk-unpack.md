# APK 加固脱壳（il2cpp / metadata / VMP）
- 触发词：APK 脱壳、加固、il2cpp、global-metadata、VMP、DexVMP、内存 dump、反调试
- 输入（用户提供）：`<apk>`、`<pkg>`、`<设备或模拟器 serial>`、`<壳类型线索>`、`<内存 dump 或进程>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`apk:static_native` `apk:static_dex` `apk:dart_aot_full` `apk:dex_dump_analysis` `apk:frida_dynamic` `apk:frida_rpc` `repo:case_state` `repo:doctor` `repo:apk-decode` `repo:dex_mem_scan` `repo:dex_dump_validate` `repo:elf_plt` `repo:vmp_diff_harness` `repo:apk_diff` `tool:frida` `tool:jadx` `tool:apktool`
- 步骤：1) `python Tool/skill/apkseep/scripts/doctor.py --capabilities --json` → rc=0 或 3，确认 frida_dynamic、dex_dump_analysis、static_native 是否 blocked；2) `powershell -File Tool/scripts/apk/decode.ps1 -ApkPath <apk> -Name <case> -OutRoot work/<case> -SkipJadx` → rc=0，先拿 apktool 树与 `lib/`；3) `python Tool/skill/apkseep/scripts/dex_mem_scan.py <mem_dump> --dump work/<case>/dex --json` → rc=0，按 dex magic 提取；4) `python Tool/skill/apkseep/scripts/dex_dump_validate.py work/<case>/dex --trim --json` → rc=0，去重并选出最像原始镜像的 dex；5) native 分支：`python Tool/skill/apkseep/scripts/elf_plt.py <lib.so> --symbol <symbol> --callers` → rc=0，确认 JNI/加载链；6) VMP 分支：`python Tool/skill/apkseep/scripts/vmp_diff_harness.py audit <original.dex>` 与 `compare <original.dex> <hardened.dex>` → rc=0，输出候选 opcode 表与置信度；7) `python Tool/skill/apkseep/scripts/apk_diff.py <original.apk> <rebuilt.apk> --summary` → rc=0，确认改动只落在预期条目；8) `python Tool/scripts/case_state.py deliver --case work/<case> --level L2 --evidence work/<case>/dump.json` → rc=0。
- 判据（可机检）：`dex_dump_validate` 选出 1 个主镜像且 `class_defs` 与原始差异可解释；`elf_plt` 能解析目标符号；VMP `compare` 有 `opcode_map` 与非空 `coverage`；`apk_diff` 只列预期变更；`doctor.py` 的 frida_dynamic 非 blocked。
- 失败判据 + 换路：frida attach 被反调试掐断 → 改 spawn/gadget 或外部 dump；只有 native 无 dex → 转 `static_native` 与 `dart_aot_full`；metadata 版本不匹配 → 换匹配的 dump 工具并记录版本；VMP 覆盖不足 → 补 labelled fixture 再 `compare`；重打包闪退 → 回 `dex_classdiff` 与签名链。
- 交付物：`work/<case>/dex/`、`dump.json`、`lib/`、`vmp-opcode-map.json`、`apk_diff.json`、`report.md`（壳型/仪器/dump/重建四段）。
