# SBOM / 可达性 / CI 权限 / 签名
- 触发词：供应链、SBOM、SCA、可达性、锁文件、CI 权限、action pin、签名、attestation、Docker、容器镜像
- 输入（用户提供）：`<repo>`、`<commit>`、`<lock 文件>`、`<SBOM>`、`<镜像 digest>`、`<CI 平台>`；范围由用户提供的 scope 决定，只做只读审计。
- 用到的能力（capability id）：`tool:nuclei` `repo:case_state` `repo:seep-start` `repo:sc-check` `repo:sbom-reach` `repo:ci-perm-audit` `repo:sc-accept` `repo:kb-query`
- 步骤：1) `python Tool/scripts/case_state.py init --case work/<case> --target <TARGET>` → rc=0，记录 commit、锁文件哈希与工作区状态；2) `python Tool/skill/supply-chain-security/scripts/sc-check.py --path <REPO> --out work/<case>/sc.json` → rc=0 或 1（high/critical 命中=1），读 `rule_hits` 与 `degraded`；3) `python Tool/skill/supply-chain-security/scripts/sbom-reach.py --sbom <BOM> --lock <LOCK> --freeze work/<case>/freeze.txt --source <REPO> --out work/<case>/reach.json` → rc=0，标每个组件 reachable/unreachable；4) `python Tool/skill/supply-chain-security/scripts/ci-perm-audit.py --path <REPO>/.github/workflows --out work/<case>/ci.json` → rc=0，列 permissions、triggers、checkout refs、secrets refs；5) `python Tool/skill/web-pentest/scripts/kb-query.py --query "dependency confusion" --limit 20` → rc=0，补判据；6) `python Tool/skill/supply-chain-security/scripts/sc-accept.py --case <case> --json` → rc=0，最后 `python Tool/scripts/preflight.py --fast` → rc=0。
- 判据（可机检）：`sc.json` 的 `rule_hits` 每条有 file/line/evidence；`reach.json.components_total>0` 且 `reachable[]` 有调用链或 import 证据；`ci.json` 的 permissions/triggers 可逐条复核；锁文件 `integrity` 完整；`sc-accept` rc=0。
- 失败判据 + 换路：无锁文件/无 integrity → 标“未钉住”，先补锁文件；无 SBOM → 从锁文件生成并记 `missing_from_sbom`；SCA 告警无调用链 → 只写版本命中，不写可利用；CI `write-all` → 核对触发器和 secrets 作用域后再定性；只有 tag 无 digest → 拉 digest 并重跑签名验证。
- 交付物：`work/<case>/sc.json`、`reach.json`、`ci.json`、`freeze.txt`、`report.md`（对象/清单/可达/权限/签名五段）。
