# OSINT 资产与人员情报测绘（域/子域/凭据泄露/身份）
- 触发词：OSINT、情报收集、信息收集、资产测绘、攻击面测绘、子域枚举、子域名、证书透明、CT 日志、ASN、网段归属、同 IP 旁站、源站 IP、CDN 回源、GitHub 泄露、代码仓库泄露、秘钥泄露、谷歌语法、Google Dorks、社工、人员画像、邮箱格式、员工名录、供应链关系、第三方依赖关系
- 输入（用户提供）：`<DOMAIN>` 主域、`<ASN>` 或 `<ORG>` 组织名、`<SCOPE>` 允许的资产边界、`<RATE>` 速率上限、`<OUT>` 输出目录；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`repo:case_state` `repo:kb-query` `repo:web-check` `repo:seep_kb_search` `tool:subfinder` `tool:amass` `tool:httpx` `tool:nuclei` `mcp:playwright` `repo:osint-secret-scan` `repo:osint-h1-ref`
- 步骤：1) 建案子并过闸（先有账再动手）：`python Tool/scripts/case_state.py init --case work/<case> --target <DOMAIN>` → rc=0；深度按 D0 结构 / D1 存活 / D2 依赖 / D3 出站 登记，`python Tool/scripts/case_state.py gate --case work/<case>` → rc=0 才继续；2) 先查知识库与公开报告，别重复踩坑：`python Tool/scripts/kb-query.py --board web-pentest --query subdomain --limit 10` → rc=0，命中即读原文（`seep_kb_read`）；同产品已披露报告对照 `python Tool/scripts/osint-h1-ref.py --query "<产品>" --limit 10 --json` → rc=0（没有公开报告也是 rc=0），结果只当假设清单，不当目标结论；3) 被动资产面（不直接打目标）：证书透明 `curl -s "https://crt.sh/?q=%25.<DOMAIN>&output=json" | jq -r '.[].name_value' | sort -u > <OUT>/ct.txt`；被动 DNS `subfinder -d <DOMAIN> -all -silent > <OUT>/subs.txt`；ASN 归属 `amass intel -org "<ORG>" -whois` 或 `whois -h whois.radb.net -- '-i origin <ASN>'`；4) 存活与指纹（必须限速，别把目标打挂）：`httpx -l <OUT>/subs.txt -sc -title -tech-detect -rate-limit <RATE> -o <OUT>/live.txt`；随后逐条 `python Tool/skill/web-pentest/scripts/web-check.py --url https://<HOST> --rate <RATE> --out <OUT>/<HOST>.json` → rc=0，拿响应头/robots/敏感路径矩阵；5) 源站与旁站：证书 SAN 交叉、历史 DNS（`securitytrails`/`viewdns` 查询页）、`<OUT>/live.txt` 里同 C 段反查；确认真实源站要两条独立证据（证书 + 回源行为），单条线索只算 hypothesis；6) 代码与凭据面：先扫已抓回的本地 JS/JSON/YAML：`python Tool/scripts/osint-secret-scan.py --path <OUT> --json` → rc=0（无命中）/1（有命中，必须人看），片段默认脱敏，核对明文才加 `--show-full` 且不外传；再看公开仓库：`gh api -X GET search/code -f q='"<DOMAIN>"'` 与 GitLab 公共项目搜索；命中的 secret 先登记为 claim（不落盘明文）：`python Tool/scripts/case_state.py claim --case work/<case> --id C<k> --text "<仓库/文件/行>"` → rc=0，证据写 `来源: 仓库URL@commit + 命中片段哈希（secret_scan pattern=… file:line）`；7) 人员与组织面：邮箱命名规则从 `mailto:` / `linkedin` 公开页归纳（`<first>.<last>@<DOMAIN>` 等模式），只归纳格式不复用凭据；员工名录与服务商关系写成表，标注「公开来源 + 抓取时间」；8) 汇总与交付：每条结论 `python Tool/scripts/case_state.py prove --case work/<case> --id C<k> --evidence work/<case>/<file>` → rc=0（证据路径必须真实存在）；`python Tool/scripts/case_state.py deliver --case work/<case> --level M1 --evidence work/<case>/recon.md` → rc=0。
- 判据（可机检）：`<OUT>/subs.txt` 行数 > 0 且每行可解析为主机名；`<OUT>/live.txt` 有状态码与 title；每个 `<HOST>.json` 有 `headers`/`robots`/`paths` 字段；源站判定必须 ≥2 条独立证据且写入 `recon.md` 的证据表；`osint-secret-scan.py --json` 结果含 `hits`/`counts`/`blocked_at`，`counts.total == len(hits)` 且 `blocked_at` 为 null，每条 hit 带 `pattern`/`severity`/`category`/`file`/`line`/`match`（默认 `masked:true`）；`osint-h1-ref.py --json` 结果含 `ok`/`reports`/`count`/`blocked_at`，`count == len(reports)` 且每条带 `title`/`url`；人员/组织结论必须带来源 URL 与时间戳；`case_state.py gate` 与 `deliver` 均 rc=0。
- 失败判据 + 换路：`subs.txt` 与 CT 结果都为空 → 目标可能只在内网或有 wildcard 过滤，改被动 DNS 历史 + ASN 网段枚举；httpx 大量 403/429 → 降 `--rate-limit` 并按主机分批，仍失败记 `blocked_at=rate-limit`；源站两条证据互相矛盾 → 判 hypothesis 不判 proven，转做 CDN 回源行为对照；凭据一旦命中真实有效口令 → 停手、只登记位置、不复制值（凭据红线）；`osint-h1-ref.py` 返回 `blocked_at=network-error` → 按本机出网受限处理，改浏览器人工搜 hacktivity 并记 `blocked_at`，不硬凑结论。
- 交付物：`work/<case>/recon.md`（资产清单 + 证据表 + 未证线索）、`subs.txt`、`live.txt`、`<HOST>.json`、`secrets.json`（脱敏命中清单）、`h1.json`（公开报告参照）、`claims.jsonl`、`gaps.json`（补不了的缺件与概率折损）。
