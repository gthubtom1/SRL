# 多账号批量执行器（池 / 限速 / 幂等 / 通知）
- 触发词：多账号、批量、账号池、并发、限速、幂等、通知、重试
- 输入（用户提供）：`<ACCOUNTS_JSON>`、`<并发数>`、`<QPS>`、`<任务名>`、`<通知 webhook>`、`<失败重试次数>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`repo:case_state` `repo:check-budget` `repo:env-ledger` `repo:preflight` `repo:pcap-summary` `repo:probe_api` `tool:fiddler` `tool:tshark`
- 步骤：1) `python Tool/scripts/check-budget.py` → rc=0，确认批量器没有把仓库预算撑爆；2) `python Tool/scripts/case_state.py init --case work/<task> --target <TASK>` → rc=0，建案例与状态；3) 批量器落到 `work/<task>/runner.py`，账号池只从 `ACCOUNTS_JSON` 读，先跑 1 个账号，`python Tool/skill/apkseep/scripts/probe_api.py --base <BASE> --path <TASK_PATH> --header <auth:...>` → rc=0，确认单账号基线；4) 每批结束 `python Tool/scripts/case_state.py prove --case work/<task> --id A<batch> --evidence work/<task>/batch-<batch>.json` → rc=0，记录耗时、成功数、限速命中数；5) 幂等键写 `work/<task>/idem.json`，`python Tool/scripts/case_state.py claim --case work/<task> --id I1 --text "同一任务同一账号只执行一次" --status hypothesis`，重复跑后 `prove --id I1 --evidence work/<task>/idem.json` → rc=0；6) 代理/hosts/时间等环境改动先记账：`python Tool/scripts/env-ledger.py record --case work/<task> --action "<change>" --before <before> --after <after> --restore "<restore>"` → rc=0，收尾 `python Tool/scripts/env-ledger.py check --case work/<task>` → rc=0；7) 汇总通知写 `work/<task>/notify.json`，`python Tool/scripts/case_state.py deliver --case work/<task> --level M2 --evidence work/<task>/notify.json` → rc=0，最后 `python Tool/scripts/preflight.py --fast` → rc=0。
- 判据（可机检）：批跑配置里 `qps`/`retry` 不超过设定值；`idem.json.duplicate_submits=0`；`env-ledger check` rc=0；`notify.json` 含成功/失败/限速三组计数。
- 失败判据 + 换路：429 集中出现 → 降 QPS、增加抖动并改串行；账号封禁/验证码 → 立即停该池并转 `captcha-handling`；token 过期 → 每账号独立刷新；部分成功但结果不一致 → 回 `qinglong-signin` 或 `app-daily-task` 重取单账号证据。
- 交付物：`work/<task>/runner.py`、`accounts.example.json`、`batch-*.json`、`idem.json`、`notify.json`、`report.md`（池、限速、幂等、通知四段）。
