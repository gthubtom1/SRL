# 固件仿真 / rehosting 失败归因
- 触发词：固件仿真、rehosting、QEMU、FirmAE、启动失败、kernel panic、服务不通
- 输入（用户提供）：`<firmware.bin 或 rootfs>`、`<设备型号>`、`<架构/端序>`、`<允许的仿真网络>`、`<目标服务端口>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`tool:binwalk` `repo:case_state` `repo:fw-triage` `repo:fw-repro` `repo:fw-accept` `repo:probe_api` `repo:env-ledger` `repo:kb-query` `repo:seep-start`
- 步骤：1) `python Tool/scripts/case_state.py init --case work/<case> --target <TARGET>`；2) `python Tool/skill/firmware-iot/scripts/fw-triage.py --file <FW> --json --out-dir work/<case>/fw`，先定容器、架构、端序、init 线索；3) `python Tool/skill/firmware-iot/scripts/fw-repro.py --file <FW> --out-dir work/<case>/fw --json`，拿到 rootfs 与推荐的 qemu 命令行；4) 启动仿真并保存 `work/<case>/emulate.log`，把“内核到 init / init 到服务 / 服务到端口”三段结果分别 `python Tool/scripts/case_state.py claim --case work/<case> --id E1/E2/E3 --text "<阶段结论>"`，再用 `prove --id E1 --evidence work/<case>/emulate.log`；5) 服务面：`python Tool/skill/apkseep/scripts/probe_api.py --base http://127.0.0.1:<PORT> --path / --no-proxy`；同一时刻记录进程、监听端口与业务响应，写入 `work/<case>/service.json`；6) 环境副作用先记账：`python Tool/skill/softseep/scripts/env-ledger.py record --case work/<case> --action "启动 qemu 网络" --before down --after up --restore "netsh interface set interface <name> admin=disable"`，收尾 `check`；7) `python Tool/skill/firmware-iot/scripts/fw-accept.py --case <case> --json`，最后 `python Tool/scripts/preflight.py --fast`。
- 判据：emulate.log 出现 init 或 shell 提示；service.json 同时有 pid、listen、response_code；probe_api rc=0 且响应体非空；env-ledger check rc=0；fw-accept rc=0。｜不行就换：kernel panic → 核对架构/端序/机器 ID，换内核或 DTB；init 起不来 → 补 /dev、NVRAM、看门狗桩
