# Web 签名参数还原（补环境 → 复算 → 重放验证）
- 触发词：Web 签名、sign 参数、加密参数、补环境、js reverse、复算、重放
- 输入（用户提供）：`<url>`、`<目标请求>`、`<账号或 cookie 占位>`、`<抓包文件>`、`<期望响应字段>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`repo:case_state` `repo:kb-query` `repo:web-check` `repo:web-repro` `repo:web-accept` `repo:probe_api` `tool:fiddler` `tool:tshark` `mcp:playwright`
- 步骤：1) `python Tool/scripts/seep-start.py --domain web-pentest --case <case> --target <URL>` → rc=0；2) `python Tool/skill/web-pentest/scripts/web-check.py --url <URL> --out work/<case>/page.json` → rc=0，记录脚本 URL、cookie 形态与目标请求的 initiator；3) `python Tool/scripts/kb-query.py --query "补环境" --limit 20` → rc=0，把命中的补环境/签名条目抄进 `work/<case>/notes.md`；4) 用 `js-reverse_*` 工具抓 `list_scripts`、`get_request_initiator`、`break_on_xhr`，把函数入参/返回值写 `work/<case>/trace.json`，`python Tool/scripts/case_state.py claim --case work/<case> --id S1 --text "sign 由 <func> 生成" --status hypothesis` 后 `prove --id S1 --evidence work/<case>/trace.json` → rc=0；5) 把脚本与最小环境带到 Node，`python Tool/skill/web-pentest/scripts/web-repro.py --probe work/<case>/probe.json --out work/<case>/verdict.json` → rc=0，`probe.json` 记录原请求、复算参数、三次运行结果；6) 重放：`python Tool/skill/apkseep/scripts/probe_api.py --base <API_BASE> --path <PATH> --param <sign=...> --header <cookie:...>` → rc=0，响应字段与期望一致；7) `python Tool/skill/web-pentest/scripts/web-accept.py --case <case>` → rc=0，最后 `python Tool/scripts/preflight.py --fast` → rc=0。
- 判据（可机检）：`verdict.json` 中复算 sign 与抓包 sign 三次全等；`probe.json` 含 `source_url`、`function`、`inputs`、`outputs`；重放响应 `code`/`token` 与期望一致；`web-accept` rc=0；`case_state show` 的 S1 为 proven。
- 失败判据 + 换路：本地报 `window/document/navigator is not defined` → 按 first divergence 逐个补，单次只补一个对象；sign 不等 → 回步骤 4 取同一请求的完整入参与环境版本；服务端 nonce/时间窗 → 带服务端原值复算并标 `partial`；触发验证码/风控 → 转 `captcha-handling`；纯 WASM 签名 → 转 `reverse-survey` 做二进制测绘。
- 交付物：`work/<case>/trace.json`、`probe.json`、`verdict.json`、`sign.js`、`env.js`、`notes.md`、`report.md`（观察/采样/补环境/重放四段）。
