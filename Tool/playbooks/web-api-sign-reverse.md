# Web 签名参数还原（补环境 → 复算 → 重放验证）
- 触发词：Web 签名、sign 参数、加密参数、补环境、js reverse、复算、重放
- 输入（用户提供）：`<url>`、`<目标请求>`、`<账号或 cookie 占位>`、`<抓包文件>`、`<期望响应字段>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`repo:case_state` `repo:kb-query` `repo:web-check` `repo:web-repro` `repo:web-accept` `repo:probe_api` `tool:fiddler` `tool:tshark` `mcp:js-reverse`
- 步骤：1) `python Tool/scripts/case_state.py init --case work/<case> --target <TARGET>` → rc=0；2) `python Tool/skill/web-pentest/scripts/web-check.py --url <URL> --out work/<case>/artifacts/page.json` → rc=0，`page.json` 顶层直接含 `url`/`status`/`headers`（脚本 URL、cookie 与目标请求的 initiator 不在本步产出，见第 4 步）；3) `python Tool/skill/web-pentest/scripts/kb-query.py --query "补环境" --limit 20` → rc=0，把命中的补环境/签名条目抄进 `work/<case>/notes.md`；4) 用 js-reverse MCP 抓签名，工具名按序（产物全部落 `work/<case>/artifacts/`）：`mcp__js_reverse__select_page` 选中已开页面（没有则先 `mcp__js_reverse__new_page` 打开 `<URL>`）→ `mcp__js_reverse__list_scripts` 取脚本列表写 `scripts.json`（拿到脚本 URL/sourceMap）→ `mcp__js_reverse__break_on_xhr` 在 `<目标请求>` 上设断点，命中后调用栈写 `trace.json` → `mcp__js_reverse__get_request_initiator` 定位发起函数写 `initiator.json` → `mcp__js_reverse__evaluate_script` 在断点帧里取明文入参与返回值写 `sign_inputs.json`；随后 `python Tool/scripts/case_state.py claim --case work/<case> --id S1 --text "sign 由 <func> 生成" --status hypothesis` → rc=0，`python Tool/scripts/case_state.py prove --case work/<case> --id S1 --evidence work/<case>/artifacts/initiator.json` → rc=0；5) 复算：用第 4 步 `evaluate_script` 取到的明文入参（`sign_inputs.json`）在本地 Node 跑 `sign.js` + `env.js` 三遍，把三次 sign 与抓包原值一起写 `work/<case>/artifacts/sign_check.json`（`web-repro` 只负责重放；签名复算在本步的本地 Node 里做，两者分开）；6) 重放：`python Tool/skill/apkseep/scripts/probe_api.py --base <API_BASE> --path <PATH> --param <sign=...> --header <cookie:...>` → rc=0，响应字段与期望一致；注入类重放另跑 `python Tool/skill/web-pentest/scripts/web-repro.py --probe work/<case>/artifacts/probe.json --out work/<case>/artifacts/replay.json` → rc=0；7) `python Tool/skill/web-pentest/scripts/web-accept.py --case <case>` → rc=0，最后 `python Tool/scripts/preflight.py --fast` → rc=0。
- 判据（可机检）：`page.json` 含 `url`、`status`、`headers`；`work/<case>/artifacts/` 下 `scripts.json`、`trace.json`、`initiator.json`、`sign_inputs.json` 均在；`sign_check.json` 中三次复算 sign 全等且与抓包 sign 一致；重放响应 `code`/`token` 与期望一致；`web-accept` rc=0；`case_state show` 的 S1 为 proven。
- 失败判据 + 换路：本地报 `window/document/navigator is not defined` → 按 first divergence 逐个补，单次只补一个对象；sign 不等 → 回步骤 4 取同一请求的完整入参与环境版本；服务端 nonce/时间窗 → 带服务端原值复算并标 `partial`；触发验证码/风控 → 转 `captcha-handling`；纯 WASM 签名 → 转 `reverse-survey` 做二进制测绘。
- 交付物：`work/<case>/artifacts/page.json`、`scripts.json`、`trace.json`、`initiator.json`、`sign_inputs.json`、`sign_check.json`、`probe.json`、`replay.json`、`sign.js`、`env.js`、`work/<case>/notes.md`、`work/<case>/report.md`（观察/采样/补环境/重放四段）。
