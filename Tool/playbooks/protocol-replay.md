# 私有协议复刻（分帧 → 状态机 → 构造新请求）
- 触发词：私有协议、二进制协议、分帧、长度字段、CRC、状态机、重放、构造新请求
- 输入（用户提供）：`<pcap/pcapng>`、`<客户端或设备>`、`<账号占位>`、`<允许重放的端点>`、`<状态机边集>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`tool:tshark` `tool:dumpcap` `repo:case_state` `repo:pcap-summary` `repo:proto-repro` `repo:proto-accept` `repo:protobuf_decode_raw` `repo:seep-start`
- 步骤：1) `python Tool/scripts/seep-start.py --domain protocol-plugin --case <case> --target <PCAP>` → rc=0；2) `python Tool/scripts/pcap-summary.py --file <PCAP> --extract work/<case>/streams --tshark-check --json` → rc=0，确认双向会话、应用层字节与候选流编号；3) `python Tool/skill/protocol-plugin/scripts/proto-repro.py --pcap <PCAP> --stream <n> --json` → rc=0，输出 `frames[]`、`stats`、字段表和 `crc_ok`；4) 构造新请求：`python Tool/skill/protocol-plugin/scripts/proto-repro.py --pcap <PCAP> --stream <n> --frame-index 0 --rebuild --set <field=value> --payload-text '<json>' --out work/<case>/new-frame.bin --json` → rc=0，`rebuild.verify=true`；5) 状态机：把边集写 `work/<case>/edges.json`，`python Tool/skill/protocol-plugin/scripts/pcap-summary.py --file <PCAP> --state-model work/<case>/edges.json --edge-threshold 0.6 --json` → rc=0，`edge_coverage>=0.6`；6) 非文本载荷用 `python Tool/skill/apkseep/scripts/protobuf_decode_raw.py <payload.bin> --json` → rc=0，确认字段树与长度；7) `python Tool/skill/protocol-plugin/scripts/proto-accept.py --case <case> --json` → rc=0，最后 `python Tool/scripts/preflight.py --fast` → rc=0。
- 判据（可机检）：`stats.consumed+trailing==bytes`；`frames[].crc_ok=true`；`rebuild.verify=true` 且新帧被服务端接受；同一请求重复 3 次响应结构一致；`edge_coverage>=0.6`；`proto-accept` rc=0。
- 失败判据 + 换路：连续两次抓包无应用层字节 → 改进程内 hook 或显式 keylog；长度/校验覆盖定不下 → 换样本、换观测层，字段表先不写；只能原样重放、改字段即拒 → 定位签名/nonce 覆盖范围，标 `partial`；429/验证码/封禁 → 立即停，留证并重定 scope；服务端下发新协议版本 → 回步骤 2 重抓并重跑状态机。
- 交付物：`work/<case>/streams/`、`frames.jsonl`、`schema.json`、`new-frame.bin`、`edges.json`、`coverage.json`、`report.md`（分帧/字段/校验/状态机四段）。
