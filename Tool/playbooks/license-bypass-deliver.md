# 客户端授权旁路交付（判权威 → 补丁 / 代理 DLL / 重打包 / 注入 → 验收）
- 触发词：授权旁路、卡密、注册机、补丁、代理 DLL、重打包、注入、可用成品
- 输入（用户提供）：`<target.exe/apk>`、`<版本号>`、`<卡密或账号占位>`、`<允许修改的副本目录>`、`<验收功能清单>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`tool:ida` `tool:x64dbg` `tool:frida` `tool:diec` `tool:pe-sieve` `repo:case_state` `repo:preflight-classify` `repo:tool-acquire` `repo:dump-restore` `repo:patch-verify` `repo:reverse-accept`
- 步骤：1) `python Tool/skill/softseep/scripts/preflight-classify.py <TARGET> --hint`，拿到 platform/protection/sections 与建议路线；2) `python Tool/scripts/tool-acquire.py --tool <TOOL_ID> --json`（仪器可用性；每次一条，落 `work/<case>/probe.json`），登记 baseline/x64dbg/frida/external/network 六种仪器的可用性；3) `python Tool/skill/malware-analysis/scripts/dump-restore.py pe-info <TARGET>`，记录节表、入口、熵、TLS/异常目录；4) 判权威：用 x64dbg/frida 观察首个网络请求与校验分支，把“本地/服务端/混用”写进 `work/<case>/authority.md`，`python Tool/scripts/case_state.py verdict --case work/<case> --value 可赢 --tier T1 --note "<authority>"`；5) 选路线并落补丁清单：单点分支改 `patch.json`，`python Tool/skill/softseep/scripts/patch-verify.py --file <TARGET> --manifest work/<case>/patch.json --out work/<case>/out/<name>`，代理 DLL/注入器同样先写 manifest 与回滚；6) 验收：`python Tool/skill/softseep/scripts/reverse-accept.py --case <case> --manifest work/<case>/patch.json`，再按功能清单逐项跑并截图；7) `python Tool/scripts/preflight.py --fast`。
- 判据：probe.json 至少一种非 baseline 仪器可用；patch.json 每条 offset/original/new 等长且唯一；patch-verify 输出 ok=true 且 result_sha256 复算一致；启动到主界面或宿主内菜单；功能清单逐项有截图/日志；reverse-…｜不行就换：壳或自毁阻断 → 回 apk-unpack 或 dump-restore 路线；调试器被检测 → 转 frida attach 或外部观测
