# 浏览器扩展 / Electron / VSIX 四件事
- 触发词：浏览器扩展、CRX、MV3、Electron、asar、VSIX、JetBrains、插件、扩展点
- 输入（用户提供）：`<plugin.crx/vsix/asar>`、`<宿主版本>`、`<安装来源>`、`<账号占位>`、`<动态观测窗口>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`tool:dnspy` `tool:de4dot` `tool:jadx` `repo:case_state` `repo:seep-start` `repo:plugin-triage` `repo:plugin-repro` `repo:plugin-accept` `repo:check-extension-conflicts`
- 步骤：1) `python Tool/scripts/case_state.py init --case work/<case> --target <TARGET>` → rc=0；2) `python Tool/skill/_pending/plugin-targets/scripts/plugin-triage.py --path <PLUGIN> --json --out work/<case>` → rc=0，得到 container/manifest/permissions/entry/remote URLs；3) `python Tool/skill/_pending/plugin-targets/scripts/plugin-repro.py --path <PLUGIN> --out work/<case>/repro --json` → rc=0，拿解包树、权限证据、数据流、最小可改单元；4) 四件事逐条 `python Tool/scripts/case_state.py claim --case work/<case> --id P1/P2/P3/P4 --text "<入口/权限/数据来源/最小单元>"`，再对每条 `prove --id P1 --evidence work/<case>/repro/entry.json` → rc=0；5) 浏览器扩展加载前 `python Tool/scripts/check-extension-conflicts.py --json` → rc=0 或 1，确认 replaceable 与宿主冲突；6) `python Tool/skill/_pending/plugin-targets/scripts/plugin-accept.py --case <case> --json` → rc=0，最后 `python Tool/scripts/preflight.py --fast` → rc=0。
- 判据（可机检）：`plugin-triage.json` 的 `container` 明确且 `entry.exists=true`；`repro/permissions[].status=observed` 且有 file/line；`data_flow` 至少一条边有 file/line；`minimal_unit.path` 存在且有 baseline/回退；`plugin-accept` rc=0。
- 失败判据 + 换路：MV3 service worker 休眠导致未观测 → 用唤醒源触发后再抓；权限能列但无代码路径 → 标 `unexplained-static` 并补动态；Electron 只有 `.jsc`/原生模块 → 转 `reverse-survey` 或 `ida`；VSIX 激活事件不触发 → 换命令/工作区触发；Unity/IL2CPP 版本不匹配 → 锁版本重 dump。
- 交付物：`work/<case>/repro/`、`entry.json`、`permissions.json`、`data-flow.json`、`minimal-unit/`、`plugin-accept.json`、`report.md`（四件事各一段）。
