# 后端复刻（API 面 → 签名 → 协议 → 切换验证）
- 触发词：后端复刻、API 面、服务端重建、签名复算、协议复刻、切换验证、T2/T3、SaaS、本地版、后台复刻、接口 mock
- 输入（用户提供）：`<客户端>`、`<原后端地址>`、`<抓包文件>`、`<账号占位>`、`<自有后端域名>`、`<下发物样本>`；范围由用户提供的 scope 决定。
- 用到的能力（capability id）：`tool:tshark` `tool:katana` `tool:ffuf` `tool:nuclei` `repo:case_state` `repo:web-check` `repo:pcap-summary` `repo:proto-repro` `repo:web-accept` `repo:probe_api` `probe:sign-recompute`
- 步骤：1) `python Tool/scripts/case_state.py init --case work/<case> --target <TARGET>`，写清 T2/T3 与 scope；2) `python Tool/skill/web-pentest/scripts/web-check.py --url <ORIGIN> --max-paths 200 --out work/<case>/api-surface.json`，列端点、状态码、头与重定向；3) `python Tool/skill/protocol-plugin/scripts/pcap-summary.py --file <capture.pcap> --extract work/<case>/streams --json`，把登录、心跳、业务、下发四类请求按 host/path 归档；4) 签名与 key 归属：`python Tool/skill/apkseep/scripts/probe_api.py --base <ORIGIN> --path <PATH> --token <TOKEN>`，配合 `python Tool/scripts/case_state.py claim --case work/<case> --id K1 --text "key 在客户端/服务端"` 与 `prove --id K1 --evidence work/<case>/key-map.json`；5) 协议复刻：`python Tool/skill/protocol-plugin/scripts/proto-repro.py --pcap <capture.pcap> --stream <n> --json`，再加 `--frame-index 0 --rebuild --set <field=value> --payload-text <json> --out work/<case>/new-frame.bin --json`；6) 自有后端起在 `<LOCAL_BACKEND>`，切换 hosts/代理后 `python Tool/skill/web-pentest/scripts/web-check.py --url http://127.0.0.1:<PORT> --out work/<case>/switched.json`，正常/超时/错误码三条路径各跑一次；7) `python Tool/scripts/case_state.py verdict --case work/<case> --value 可赢 --tier T3 --note "业务在后端"`，`python Tool/skill/web-pentest/scripts/web-accept.py --case <case>`，最后 `python Tool/scripts/preflight.py --fast`。
- 判据：api-surface.json 每个 path 有实现或 404/405 语义；key-map.json 每个 key 有归属；proto-repro 的 rebuild.verify=true；切换后 switched.json 登录/心跳/业务/下发四类均通；关停后端行为与基线一致；web-a…｜不行就换：抓包只有 TLS 密文 → 设 SSLKEYLOGFILE 或进程内取明文；端点被截断/别名 → 按实际 path 实现并登记别名
