# 架构不变量（Architecture Invariants）

> **这一页定的是"改动的边界"，不是"功能的清单"。**
> 起因（2026-10-25）：连续 20 小时"修→审→又发现问题"的循环。根因不是缺陷多，而是
> **没有可判的"逻辑闭环"标准** —— 于是每次评审都能提出新的"这一处也没验"。
> 用户的原话：成熟项目不会把每个领域都真跑一遍；要保证的是**逻辑与架构没问题**，
> 之后只做小范围优化。

## 一、为什么"每个域都真跑"不是标准

| | 真跑每一个域 | 不变量（本页） |
| :-- | :-- | :-- |
| 成本 | 9 域 × 每个域一套仪器/样本/环境 | 一次静态计算，0.1 秒 |
| 可复现 | 依赖机器、样本、设备 | 只依赖仓库内容 |
| 能挡住什么 | 该域**这一条**路上的问题 | 该域**所有**路线上的结构性断点 |
| 换机器后 | 结论作废 | 结论仍成立 |
| 什么时候失效 | 内容变了就得重跑 | 只有"不变量本身错"才会失效 |

真跑只有**一个**不可替代的用途：验证"运行时模型会不会照做"。那已经用一次真实任务
（`docs/audits/2026-10-25-acceptance-run.md`）验过了，不需要按域再来 9 次。

## 二、九条不变量（`Tool/scripts/invariants.py`）

| ID | 不变量 | 违反会怎样 |
| :-- | :-- | :-- |
| **I1** | 入口唯一：判型只在一处（`seep-router`），其它域不自称总控 | 两条路由打架，用户说法落到错的域 |
| **I2** | 能力可达：`pack.tools` 里每个工具都有落点（域脚本 / 能力表 / MCP 注册） | SKILL 写着某工具，实际调不到 = 承诺空转 |
| **I3** | 交接闭包：SKILL 里指向别处的路径都存在，且不指向自己 | 跨域交接断链（如"脱壳交给 X"，X 不存在） |
| **I4** | 证据同构：所有域的 `evidence_contract` 完全相同 | 有的域能"没证据也算过"，等于假绿入口 |
| **I5** | 等级唯一：M1–M4 只在 `seep-router` 定义，其它域只引用 | 同一句"能到 M2"在不同域含义不同 |
| **I6** | 失败可表达：每个域都有判废条件（什么情况停、回哪一层） | 卡住时继续硬凑结论 |
| **I7** | 见证可跑：每个域的 `witness_tool` 脚本文件真实存在 | 门禁绿、工具不在 |
| **I8** | 部署等价：仓库技能 ↔ 已部署技能 哈希一致 | 改仓库不生效（"我明明改了"） |
| **I9** | 能力有路线：声明"脱壳/加壳/加固"的域必须指向 `unpack-loop` | 带壳 APK 被直接改 dex（今天实测到的真缺口） |

跑法：

```bash
python Tool/scripts/invariants.py            # 9 域 × 9 条 的矩阵（客户可见域，含 apkseep）
python Tool/scripts/invariants.py --check    # 违反 → 退出码 1（已进 check.py 套件）
```

**反向验证**（防"恒绿"）：故意删掉 `apkseep` 里的 `unpack-loop` 指针 → I9 立刻红。
这条验证是必须做的：今天已经发现过一次"判据自己在空转"（触发面矩阵的路由层）。

## 三、以后只允许三类改动

| 类型 | 判据 | 允许的规模 |
| :-- | :-- | :-- |
| **A. 修违反** | `invariants.py --check` 或 `preflight` 红；或用户实测踩到 | 局部，一次一处，必须同时补/改一条机检 |
| **B. 加不变量** | 出现"新的一类"失败（不是既有不变量的实例） | 一次加一条，且在 `docs/LESSONS.md` 记为什么 |
| **C. 内容补深** | 只动 `references/*.md`，不动结构、不加 pack、不改判据 | 只受 A+ 棘轮约束（行数/篇均/命令覆盖） |

**门槛**：再出现"总攻式重写"时——一次改动超过 20 个文件、或动了 `pack.json` 的 schema、
或新增第 10 个域——三者任一发生，先写一页说明"为什么现有不变量挡不住它"，再动手。

## 四、今天这个循环为什么停得下来

| 之前 | 现在 |
| :-- | :-- |
| 评审提什么就修什么（每次都冒新问题） | 评审意见先归类：**违反某条不变量**才修，否则进 backlog |
| "深度"用行数衡量（可以无限加） | 深度用棘轮（只许变好，不许倒退）+ 三条 A+ 门槛 |
| "完成"= 全绿 | "完成"= 不变量全成立 + 连续 3 次真实任务无 A 类 + 干净机器可复现 |
| 每条判据都可能自己空转 | 判据必须过**反向验证**（改坏必须变红），mutation 6/6 常驻 |
