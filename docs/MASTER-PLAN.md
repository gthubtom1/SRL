## 1. 需求（用户原话，不是需求文档）

| # | 用户原话（节选） | 可判定标准 |
| :-: | :-- | :-- |
| R1 | 「我不懂技术，丢个软件/APP/网站/固件给它」 | 零基础用户能只靠"说人话"开始，不需要记命令、不需要改文件 |
| R2 | 「它先说清这是什么、有没有加固、能不能改、能到哪一步」 | 第一次响应必须包含：判型 + 交付上限 M1–M4 + 缺什么 |
| R3 | 「需要我提供什么（卡密/账号/设备/抓包）」 | 缺输入时**在对话里列 A/B/C** 问；不许自己假设"没有" |
| R4 | 「能覆盖 9 个领域」 | 9 个域包各有判据、见证案例、工具链 |
| R5 | 「能自己干的自己干，干不了的停下来问我」 | 只读分析不打断；需要设备/凭据/启动目标时停下问 |
| R6 | 「我随时能加新技能，丢进去就能用」 | 加技能 = 1 处（丢目录）；不需要改配置/跑脚本 |
| R7 | 「别让我记命令、别搞一堆斜杠命令」 | 部署目录里 0 个斜杠命令（当前状态） |
| R8 | 「真拿项目来用要靠得住，别白忙」 | 无幻影工具/路径；工具名真实；数字与实测一致 |
| R9 | 「别改一个坏一个」 | 同一事实只有 1 处陈述；改完 `check.py` 全绿 |
