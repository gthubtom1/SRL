# 深度计划（DEPTH-PLAN）：加深度，不加数量

> 触发：用户指出「内存转储与还原解包是逆向里最难的一块」，并给了 4 个外部技能参考，
> 问：到底要**技能更多**还是**深度更深**？所有域的深度够不够？
> 本文件回答三件事：**标准**（多深算够）、**记分卡**（现在多深）、**计划**（补哪、按什么顺序）。

---

## 0. 结论先说

| 问题 | 答案 |
| :-- | :-- |
| 要不要加技能/域？ | **不要**。9 域已定；每加一个域就要按 C1 给真见证，成本高且会串味。 |
| 深度够不够？ | **不够**，但不是"全线不够"：`unpack-loop` 与 8 个域的**内容深度不均**，且**动作密度低**（很多篇没有可执行命令）。 |
| 怎么衡量深度？ | 四个可数指标（见 §1）。**深度 = 可枚举的条目数 × 每条的可执行判据**，不是字数。 |

外部参考（2026-10-25 实读）：

| 来源 | 深度形态 | 对我们的启示 |
| :-- | :-- | :-- |
| `dslsdzc/re-anti-analysis`（SkillsDirectory A 级） | **45 条 AD-n + AV-n**，每条固定**五字段**（Trigger/Observation/Inference/Action/**Constraint**），网关+5 个子技能 | 反调试/反VM 必须**可枚举 + 带约束**，不能是一篇散文 |
| `yaklang/hack-skills` 的 `vm-and-bytecode-reverse` | dispatcher 识别表 + 5 步方法论 + **自建反汇编器代码模板** + CTF 模式 | "VM/字节码"这一层要有**可复制的代码**，不是描述 |
| `P4nda0s/reverse-skills` | 索引型仓库（体积小） | 索引本身不产生深度 |
| `zhaoxuya520/reverse-skill` | 路由包（MASTER-ROUTING + case-init + evidence 链） | 我们已有等价结构（router + case + 证据） |

## 1. 深度标准（四条，全部可机检或可数）

| # | 标准 | 判据 | 现状 |
| :-: | :-- | :-- | :-: |
| **D1** | **可枚举**：难技法必须编成条目（有编号），能逐条引用与核对覆盖 | 条目数 ≥ 30 且字段齐（如反调试矩阵） | ✅ 反调试矩阵 **39 条 × 五字段** |
| **D2** | **可执行**：每个技法页至少 1 个可复制命令块（命令 + 期望输出） | `preflight` 判据「深度棘轮」 | ⚠️ 仍有 **11 篇**无命令（目标 0） |
| **D3** | **可定位**：每个域有"症状索引"（现象 → 读哪篇），命中即停 | `preflight` 判据「references 索引完整」 | ✅ 9/9 域有（apkseep 用 routing.md） |
| **D4** | **不重复**：同一技法只在一处定义，其余引用 | 人工抽查 + `总控唯一` 类判据 | 🟡 反调试有两篇（`anti-debug.md` 与 `anti-debug-matrix.md`），需合并 |

## 4. 明确不做

| 不做 | 理由 |
| :-- | :-- |
| 把外部技能整包搬进来（exe-reverse / re-anti-analysis / vm-and-bytecode-reverse） | 与本域 pack/gate 契约冲突；且它们的"深度"我们已经用矩阵 + 命令块的方式吸收 |
| 为凑数把"索引页/边界页"也塞命令 | 会制造假动作；棘轮判据已排除这类页面 |
| 加第 10 个域 | 每域要真见证；会串味 |

## 5. 怎么验收（下次外部评审会查这些）

1. `check.py --fix` 7 套件全绿
2. `深度棘轮：无命令的技法页 ≤ 0`
3. `反调试矩阵 ≥ 39 条 × 五字段`
4. `references 索引完整（无孤儿）`
5. 反问：**随便挑一篇 reference，能不能照着跑出一条命令并得到期望输出？**（不能就算不深）
