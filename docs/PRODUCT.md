# PRODUCT —— 这个项目到底该长什么样（产品规格，非计划书）

> 写这份的原因：此前一直是"用户报问题 → 我修一处"，结果是 4 套路由、163 项门禁、29 个配置的"四不像"。
> 这份文件只做一件事：**把产品钉死**，之后任何改动都要能回答"符合 PRODUCT 哪一条"。

---

## 1. 定位（一句话）

> 给一个目标，先说清**这是什么 / 能到哪一级 / 缺什么**；然后按该领域的技能链干活，每步留证据，结论可复查。

**不做**：不做"一键全自动出成品"。深度上限由壳/授权位置/服务端权威决定，谎报做不到的事比做不到更糟。

## 2. 用户与主回路（用户只感知 4 步）

```
/rev <目标>              ← ① 选域（显式斜杠命令，100% 加载该域技能链）
判型 + M1–M4 + 我缺什么    ← ② 30 秒内必须给；缺输入就问（问不是退缩）
按该域 SKILL 干活          ← ③ 工具/命令/hook，硬规则写在命令卡里
证据落账 → 可复查          ← ④ facts.jsonl + artifacts/MANIFEST + 结论分级
```

**入口只有 2 个**：`/域` 命令（显式）+ 技能 `description`（兜底）。`route.py` 只是测试工具。

## 3. 内容三层（渐进披露，不再加层）

| 层 | 内容 | 体量 | 谁读 |
| :-: | :-- | --: | :-- |
| L1 | 10 张 `/域` 命令卡 | ~12 行/张 | 用户打 `/` 时 |
| L2 | 每域 `SKILL.md` | ≤600 行 | 模型必读 |
| L3 | `references/` + `_pending/` 归档子技能（18 个，按需链接） | 按需 | 模型按需 |

## 4. 状态与证据（唯一事实源）

| 文件 | 作用 | 谁写 |
| :-- | :-- | :-- |
| `<case>/case.json` | 结构化元数据（域、目标、上限、结论） | `case_state.py init/verdict` |
| `<case>/facts.jsonl` | 逐条事实（claim / state / event / gaps / plan / ask） | 工具与 Agent |
| `<case>/artifacts/MANIFEST.sha256` | 交付物哈希 | 生成脚本 |
| `<case>/scope.md` | **授权与边界契约**（做什么/不做什么/环境） | `init` 自动生成 |
| `docs/LESSONS.md` | **跨案例经验回流**（同类工作台都有的 field journal） | Agent 结案时追加 |

## 10. 关于"要不要斜杠命令"（2026-10-24 定）

**结论**：要，但只能是**薄指针**（≤16 行），不得复制任何协议/判据。

| 事实 | 数据 |
| :-- | :-- |
| 技能常驻成本 = 只有 `name` + `description` | 10 个 ≈ **518 tokens**；27 个 ≈ **1692 tokens** |
| 技能正文 | 不常驻，`read` 到才进上下文（2848 行 / 10 个技能） |
| 所以"几百个技能不炸" | 因为描述便宜。122 个 ≈ 5–7k tokens，放得下 |

**卡片为什么必须薄**：卡片一旦复制"判型/硬规则"，就产生**第二个事实源**。
实测代价：一次使用暴露 3 个缺陷（`--resolve ""`、路径不全、没有目标还往下走）。
现在卡片只做三件事：指路（SKILL.md 绝对路径）、传目标（`$@`）、无目标先问。

**技能数量不是约束**：约束是**描述质量**。归档的 17 个技能描述是名词式
（"【00｜阶段零·分析透彻出可复现报告】"），直接部署上去只会加噪声、不会命中。
要恢复它们，正确顺序是：**先重写描述为"用户原话+后缀" → 再加进探针表 → 才部署**。

## 11. 加技能 = 只改一处（约定优于配置）·2026-10-24 定

**问题**：我们原来加一个技能要动 **5 处**（SKILL.md / pack.json / trigger-probes / tasks 卡片 / 部署）；
Anthropic Agent Skills 规范只要 **1 处**（丢一个带 frontmatter 的 `SKILL.md`）。
每加一个技能都要改代码，这不叫产品。

**现在**：

| 动作 | 要做什么 |
| :-- | :-- |
| 加技能 | 把目录丢进 `Tool/skill/<名字>/`（含 `SKILL.md`：frontmatter 里写 `name` + `description`） |
| 部署 | 跑 `setup/install-pi.ps1`（会**自动** gen-commands → 生成 `/名字` 命令卡 → 复制到 pi） |
| 验证 | `python Tool/scripts/check.py --fast` |

**派生关系（单向，不会漂）**：

```
Tool/skill/<名>/SKILL.md  ──gen-commands.py──▶  Tool/prompts/tasks/<名>.md  ──install──▶  ~/.pi/agent/prompts/
        （唯一事实源）                              （自动生成，带 AUTO-GENERATED 标记）            （斜杠命令）
```

- 生成的卡带 `<!-- AUTO-GENERATED -->`；**手写卡（无标记）不会被覆盖**
- 卡片只做三件事：指路、传 `$@`、无目标先问 —— **不复制任何协议**（协议只在 SKILL.md 一份）
- 判据：`gen-commands.py --check` 有漂移就红；有技能没卡也红

**已实测**：丢一个只有 `SKILL.md` 的目录 → 命令卡自动出现 → `--check` 通过（11 个技能）。

**什么时候才需要动配置**（例外，不是常规）：

| 情况 | 为什么 |
| :-- | :-- |
| 该域要进 `pack.json` 的域级判据（gate 的 6 道） | 只有"要当见证域"时才需要 |
| 想给它加探针（`trigger-probes.json`） | 只有"核心域"才加；普通技能靠描述命中即可 |

## 12. 零基础用户的实际使用流程（3 步，不需要知道命令）

```
① 装一次： clone → setup/install-pi.ps1（把技能/命令/扩展装进 pi）
② 说人话： 「我有个 exe，想看看能不能改」/「这个 apk 想去广告」
          → 系统按描述自动选域；选不准就问，不瞎猜
③ 跟着走： 它给「判型 + 能到哪一级 + 缺什么」→ 你补齐（账号/卡密/设备/抓包）
          → 它干活并留证据；结束给你可复查的结论
```

**斜杠命令是可选加速**（`/rev` `/apk` …），不是必须。不知道打什么就直接说人话。

## 13. 规模化架构：常驻的是"域"，不是"技能"（2026-10-24 定）

**用户的反对意见（成立）**：如果每个技能都生成一个斜杠命令，几百个技能就是几百条命令，
人翻不动、记不住；而且"加技能还要跑脚本"违反常识（别人就是拖进去）。

**结论**：

| 层 | 放什么 | 是否常驻上下文 | 谁看见 |
| :-: | :-- | :-: | :-- |
| **L0 意图** | 用户说话（自然语言） | — | 用户 |
| **L1 域** | `~/.pi/agent/skills/<域>/SKILL.md`（当前 10 个） | ✅ 只有 **name + description**（≈50 tokens/个） | 模型据此选域 |
| **L2 子技能** | `Tool/skill/_pending/<名>/SKILL.md`（当前 17 个） | ❌ 不常驻，需要时 `ls` + `read` | 域 SKILL.md 里写了"何时读哪个" |

**所以技能能到几百个**：常驻成本 = **域的数量 × 50 tokens**，不是技能数量。
例子：10 个域 + 300 个子技能 ≈ 500 tokens 常驻 + 按需读取。

**斜杠命令的地位**：**不是必须，也不再自动生成。** 只保留 3 张手写任务卡
（`/reverse` `/analyze` `/reverse-deliverable`）作为可选快捷方式。
理由：命令是"人的记忆负担"；真正该做的是让模型按描述选域，不确定就问。

## 14. 加技能：拖拽即可（零脚本）

| 做 | 做法 |
| :-- | :-- |
| 加一个**新域**（要常驻、要能被自动选中） | 把目录放进 `~/.pi/agent/skills/<名>/`，内含 `SKILL.md`（frontmatter 写 `name` + `description`）→ **下次会话自动加载** |
| 加一个**子技能**（不常驻，按需调用） | 放进 `Tool/skill/_pending/<名>/`，并在所属域 SKILL.md 的"何时读哪个"里加一行 |
| 验证 | `python Tool/scripts/check.py --fast`（判据：`拖拽式技能`——SKILL.md frontmatter 合法） |

**不需要**：改 pack.json、改探针表、跑生成脚本、改路由。

## 15. 人机协作原则（谁做、谁问、谁停）

| 情形 | 谁做 | 依据 |
| :-- | :-- | :-- |
| 只读分析、结构/壳/字符串、查 KB | **AI 自己推进**，不打断 | 副作用 L0/L1 |
| 需要目标进程真实运行才能取证（动态调试/内存 dump） | **AI 自己启动**（按启动纪律：explorer 父进程），但先声明"我要启动它" | AGENTS §五之四 |
| 需要用户手里的东西（卡密/账号/硬件狗/设备/抓包） | **停下问**，给两条路线（有/没有各怎么走） | 缺输入必问，问不是退缩 |
| 会改系统级配置或装驱动/反作弊 | **必须先问**，默认不做 | 副作用 L3 |
| 深度超出能力（服务端权威、强壳无样本） | **明说上限**（M1/M2），并给天花板原因 | 不许谎报 |

一句话：**能自己做的不问，做不了的不硬撑，越界的先问。**

## 16. 加技能：用户只说一句话（2026-10-24 定）

**原则：用户不该懂格式。** 他说「我要加这个技能 <路径/链接>」，剩下的判定/改造/安装/验证都是 Agent 的事。

```bash
python Tool/scripts/skill-import.py --from <目录或 SKILL.md> [--dry-run]
```

它做四件事（机械、可校验）：

| 步 | 做什么 | 判据 |
| :-: | :-- | :-- |
| ① | 校验 frontmatter（`name` + `description` 必须齐） | 缺 description 直接拒（它是模型选中它的唯一依据） |
| ② | **判定域 / 子技能** | 正文 ≥120 行、覆盖 ≥3 种后缀、≥4 类技法 ⇒ 域技能；否则子技能 |
| ③ | 放到正确位置 | 域 → `Tool/skill/<名>/`；子 → `Tool/skill/_pending/<名>/` |
| ④ | 域技能自动部署 | 拷到 `~/.pi/agent/skills/<名>/` → 下次会话自动加载 |

然后打印**收尾清单**（给 Agent 看的，用户不用管）：
1. 描述要不要改写成"用户原话 + 文件后缀"
2. 子技能要在父域 SKILL.md 加一行"何时读它"
3. 跑 `python Tool/scripts/check.py --fast`

**自测**：`skill-import.py --selftest` 会造一个"长正文多后缀"和一个"短正文单技法"的假技能，
断言前者判域、后者判子技能（2/2）。这条已进 preflight，坏掉就红。
