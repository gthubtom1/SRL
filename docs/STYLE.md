# STYLE.md — 文档措辞规范（scope 由用户声明）

> 本仓文档只描述**做什么、由谁做、判据是什么**。能不能做、做到哪，由用户在 `scope` 里声明。
> 措辞 lint 由 `python Tool/scripts/preflight.py --fast` 的 [13 措辞] 项执行（0 命中为 PASS）。

## 1. 三条硬规则

| # | 规则 | 说明 |
|---|---|---|
| R1 | **scope 由用户声明** | 域名/IP/账号/资源清单、动作等级、时间窗由用户提供；文档写「清单内按任务执行」，边界裁决权在用户。 |
| R2 | **路由用肯定句** | 写「本域负责 X；Y 由 `<domain>` 承担」，把邻域写成「由谁承担」。 |
| R3 | **纪律用肯定句** | 写「哈希必须由文件字节复算」「路径必须由 `__file__`/`--root` 推导」，纪律句只用肯定式。 |

## 2. 需要改写的写法 → 合规范写法

| 场景 | 旧写法（返工） | 新写法（合规范） |
|---|---|---|
| 权限/目标 | 「第三方设备/账号/云资源一律回避」 | 「执行范围由 `scope` 声明：域名/IP/账号/资源清单由用户提供；清单内按任务执行」 |
| 域边界 | 「本域不解析 TLS，见 protocol-plugin」 | 「本域负责分帧与状态机；TLS 握手由 `protocol-plugin` 承担」 |
| 章节标题 | 「适用 / 该域之外（边界）」 | 「范围与路由（边界）」：本域输入面 / 输出物 / 相邻域 |
| 参考页页眉 | 「本页之外：插件装载链」 | 「路由：插件装载链由 `plugin-targets`（R25）承担」 |
| 质量纪律 | 「别编造哈希 / 别写死盘符」 | 「哈希必须由文件字节复算 / 路径必须由 `__file__` 推导」 |
| 阶段边界表 | 「本阶段做 ｜ 本阶段之外」 | 「本阶段做 ｜ 本阶段移交（由谁承担）」 |
| 返工清单 | 「负面清单」 | 「返工项（出现即返工）」 |

## 3. scope 的落盘与引用

1. 正式评估在 `work/<case>/scope.md` 记录：授权人/工单、域名/IP/端口、账号、资源清单、动作白名单、时间窗、回滚方式。
2. 文档里统一用 `` `scope` `` 指代该文件，不重复抄清单（单一事实源，避免漂移）。
3. 清单外动作：先停、写 `blocked_at=out-of-scope`，由用户扩清单后再继续。
4. 生产/第三方系统按单独授权单执行；凭据、Token、Salt、私钥只留指纹。

## 4. 术语保留（属技术名词，照常使用）

- **拒绝服务 / 校验被拒 / 协议拒绝**：描述服务端或解析器的行为，不是任务禁令。
- **模型拒答 / 防拒绝熔断**：描述提示词工程的既有机制（见 `Tool/prompts/AGENTS.md` §三）。
- **未授权访问**：Web/取证判据里的漏洞类别名，保留原词。
- **N-A / unknown / blocked**：判定档位，含义见各域 `02-failure-criteria.md`。
