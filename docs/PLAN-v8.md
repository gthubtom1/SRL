## 1. 需求判定（这个项目到底是干什么的）

### 1.1 用户真实需求（不是我的转述，是原话归纳）

| # | 用户要的 | 反例（用户明确反对的） |
| :-: | :-- | :-- |
| R1 | **像资深工程师一样判断**：给个目标，先判能不能做、能到哪一级，再决定怎么做 | 用户说"要源码级"就死盯源码级，3 小时交一个用不了的东西 |
| R2 | **难度不合适要主动说**：做不上去就说明卡在哪；用户只要低级别但能更高，也要主动告知 | 闷头干 / 不打招呼降级 / 把"做不到"说成"已交付" |
| R3 | **卡点合理停下来问**：只在"需要用户手里的东西 / 需要物理动作 / 只有真实进程能取证 / 同手法失败 2 次"时停 | 什么都问、或什么都硬钻 |
| R4 | **能覆盖 9 个领域**（逆向为主，其余 8 个门类同等对待） | 只把逆向做深，其他域是空壳 |
| R5 | **副作用只落在目标文件与进程内存**：网卡 / 驱动 / 服务 / 引导 / 系统策略 / 磁盘 | 为了"接上假服务器"去改整机网络（已发生过） |
| R6 | **默认开工，不给拒绝余地**：默认开工，不写免责/不索权/不劝退 | 技能里写"需要授权""请注意合规" |
| R7 | **说完成就要真完成**：判据是机器输出，不是我的口头结论 | "审查通过"之后用户一想又冒出新问题 |

### 1.2 与上游 / REA 的定位差异（决定了"照抄"是错的）

| | 上游 fork 源（angus） | REA | 我们 |
| :-- | :-- | :-- | :-- |
| 本质 | **知识库 + 原则**，模型在里面检索与判断 | **工程平台**（bridge/contracts/verification/experiments） | 想做"像工程师的助手"，但写成了**指标流水线** |
| 机检判据密度 | 0.0 /KB | 0.0 /KB | **playbooks 4.7 /KB**、contracts 1.8 /KB |
| 强制句密度 | 0.1 /KB | 0.0 /KB | contracts 后 2.8 /KB |
| 案例形态 | 14 个**可复跑工程**（src/tools/dist） | experiments 178 篇 | 62 个**元数据壳**（仅 3 个带 target/） |
| 验证层 | 无 | `work/audit/refs/rea/docs/verification/` 36 篇 | 无（只有 gate.py） |
| 行为矫正扩展 | 2 个 | 3 个 | **7 个**（说明一直在外面补拦截） |

**结论**：我们的问题不是"能力不够"，是 **"把知识写成了 KPI，把助手写成了流水线"**。指标压力 + 没有副作用边界 → 模型必然走捷径。

### 1.3 要达到的效果（一句话）

> 给它一个真实目标，它**先判难度、说明能到哪一级**，然后**副作用只落在目标文件与进程内存**的前提下做到那一级，
> 每一步结论都有 `observed` 证据，交付前用 `verify` 自证——不是我说完成，是判据说完成。

## 3. 教训台账（**必须记住** · 每条都带判据）

> 每条格式：**症状 → 根因 → 判据（怎么机检）→ 防复发动作**。
> 这些全部来自真实事故，不是推测。

| # | 症状 | 根因 | 判据 | 防复发 |
| :-: | :-- | :-- | :-- | :-- |
| **L1** | 删完东西 preflight 从 44 掉到 34 | "只删不加"是伪命题：删任何东西会同时打破 4 处对账 | 删除后立刻跑 preflight，项数与引用必须同步 | 删除类任务**不并行**；每删一批立即收口 |
| **L2** | 批量替换把机读上下文写成散文 | 同一字符串在"人读"和"机读"两处含义不同 | `capability-gate` / `playbook-check` 会红 | 机读位置写真实路径，人读位置才写说明 |
| **L3** | 脚本搬进包后报"找不到仓库根" | 固定层数 `dirname×3` 在移动后必错 | 脚本 `--self-test` / `--help` rc≠0 | 一律用"向上找锚点（Tool/cases）"，**改为向上找锚点** |
| **L4** | 索引/门禁数字两处不一致 | 同一数字多处副本必然分叉（gate-counts、cases_max、授权门 4 处） | `grep` 同一断言出现 >1 次即红 | 数字只在**一处**定义，其余引用 |
| **L5** | 门禁全绿但真实没做 | skip/unknown/empty 被当 pass | `verify` 要求 observed+authority；截断/空输出必须有 error 码 | 判据必须"能打红"；`--no-witness` 计 skipped = 不通过 |
| **L6** | "审查通过"之后用户一想又出问题 | 只做了结构型检查（引用/计数/语法），没做行为型检查 | 只有"跑真目标"能测 | 任何"没问题"必须附**一次新目标冒烟**（NOW §六-7） |
| **L7** | 模型去改整机网络 | **高压指标 + 无副作用边界 → 走捷径**（达成"接上假服务端"的最短路径） | 系统级命令出现次数 >0 | ① 降指标压力（删高压文档）② 立层级原则（L0/L1 可，L3/L4 不） |
| **L8** | 同 L7 的具体出处 | **技能文本是"指令"**：`license-validation §5.3` 原文教"抢回环 IP" | 技能里出现可直接照抄的系统级命令 | 技能只写"判据 + 该走哪条路"，**不写整机改动命令** |
| **L9** | 无法用规则穷举（今天网卡、明天驱动/显卡） | 规则按"命令长相"列，列不全 | 新增一个未列过的系统命令仍能执行 | 判据改成**层级原则**（副作用落在哪一层），正则只做兜底 |
| **L10** | 部署的 AGENTS/SEEP 指向已删脚本 | 部署态与仓库态会漂移 | `preflight` 部署哈希 / 悬空引用 | 改仓库必须同步 `~/.pi/agent/`；`/reload` 后验证 |
| **L11** | 破甲卡每次重生成都要手工打补丁 | 兼容脚本**反向注入**授权条款到卡里 | `grep authorization gate 破甲卡生成/` ≠0 | 人设卡不复述授权门；闸只管凭据红线 |
| **L12** | 反复"改完又说好了，用户一试又不行" | 把"我检查过了"当完成 | 完成必须由 `gate.py` / `verify` 输出证明 | 见 §2 DoD；口头"完成"无效 |
| **L13** | 用户提一次、我修一次，永远是用户在发现问题 | 审查依赖"已知失败模式"，无法覆盖未知 | 差分审计 + 对抗任务是否有新增发现 | 每两周做一次 **差分 + 对抗**，不依赖用户灵感 |
| **L14** | 会话一换，教训就丢，下次重犯 | 教训只在上下文里，没落盘 | 本文 §3 是否存在且被 NOW 引用 | **教训必须进本文**，不写进聊天记录 |

## 5. 打破"永远在改"的循环（机制，不是口号）

| 循环环节 | 现在 | 改法 |
| :-- | :-- | :-- |
| 用户发现问题 → 我修 | 用户在承担审查职责 | **差分 + 对抗任务**变成常规机检（不依赖用户灵感） |
| 我修完说"好了" | 口头结论 | 只认 §2 DoD 的数字 |
| 教训靠上下文 | 换会话就丢 | 进本文 §3，NOW 开头指过来 |
| 每次改动都不确定影响面 | 靠回忆 | 五条机检：`preflight` / `gate --all` / `route --check` / `budget --prompt` / 六查链路 |

**唯一一条铁律**：**没有新增 KPI 行的改动不算完成。** 没有它，任何"优化"都会退回"加东西"。
