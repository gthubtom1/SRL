# Seep 资源持续进化实施方案

状态：2026-11-02，经用户要求进入实施；不是已完成报告。需求以 REQUIREMENTS.md 为准，实时进度以 docs/CURRENT-STATE.md 为准。本方案在 codex/resource-evolution-20261102 隔离工作树执行，不覆盖已发布 main 或用户部署。

## 1. 用户真正要什么

用户不想维护内部表格。以后只说“补充这方面资料”“把这个项目经验留下”“加入这个技能”，Agent 应先查库存、读相近内容、核实新增价值，选择不变、补充、修订或新建，放进合适位置，验证以后能找到并用上。不同人可以有不同资料、工具与技能；换电脑不能把别人的安装状态、凭据或旧会话警告带过来。

“自进化”指外部资源与可复查方法持续维护，不是模型训练，不是核心规则自行放宽，更不是每个任务都必须写经验报告。执行、发现、风险和决策四条线继续服务用户结果，不建立第五个总管理器。

## 2. 已有基础、确定缺口和非目标

已有：CLI/MCP 同核发现、动态 pack/子技能、KB 搜索/读取、工具能力与本机路径分离、技能事务导入、项目证据/验收、风险接续、Git/部署备份。必须复用这些机制。

确定缺口：

1. 工具/MCP 声明目前主要作方法的关联信息，独立新增声明不一定可被直接发现。
2. KB 根与个人补充来源没有统一的受限导航；不同电脑的启停与个人方法来源缺少显式组合入口。
3. 有普通文件写入能力，但没有一致的知识增补入口来检查来源、重复、旧内容复核、并发漂移、可检索性和恢复。
4. 新知识写入、后续发现、实际 KB 读取和技能维护尚未形成可验证闭环。

不做：向量数据库、人物扮演系统、定时联网爬取、全盘扫描、第二账本、自动修改守卫/阈值、自动发布任意资料、自动执行外来脚本、全量替换上游。

## 3. 稳定入口与动态来源

增加轻量 resource-sources 声明：描述允许的技能/知识根、逻辑身份、读写属性与共享/私有范围，不复制文章和工具清单。仓库声明只使用仓库相对路径；个人扩展只通过明确指定的本机配置载入，不自动读取含凭据的宿主配置。

保留既有默认路径与 KB article_path。新增外部知识根使用带来源身份的引用；同名文章不静默覆盖。来源不可读、坏格式、上限耗尽与没有命中分别报告。停用来源或资源后，下次查询停止推荐；不自动安装或恢复用户主动停用的资源。

声明与实际可用分开：发现返回来源、类型、匹配依据、准确引用与未验证状态。工具本机发现、宿主 schema/握手与真实任务仍沿既有入口核验，不把源码资源存在当作宿主加载成功。

读取限制：明确根、普通文本、边界内路径、拒绝链接逃逸、有界文件/字节/输出；资料中的指令无权改变用户任务、来源配置或执行边界。公共输出不需要回显机器私密路径或原查询。

## 4. 知识维护闭环

### 4.1 先查再写

Agent 从问题及候选正文提取主题、别名、平台、版本，调用发现与 KB 检索，实际读相关内容。完全相同正文机械去重；相近内容返回候选和指纹，让 Agent 比较语义。搜索未命中不证明没有重复，不靠单一相似度自动合并。

处置：没有增量则不变；有增量则更新原文；条件不同则保留变体与互引；新主题才新建；推翻旧结论须说明依据；一次成功只能标特定条件的案例，不直接升为通用技能。

### 4.2 内容自身保存元数据

使用 Markdown 中一个有界 JSON 元数据注释，正文仍可直接阅读。记录稳定 ID、标题/摘要/标签、适用范围、成熟度、公开来源与匿名证据指纹、反例和修订原因。元数据只陈述调用者判断，不自动证明专业语义。

成熟度区分 external reference、case experience、reusable method、retired。源码文章是权威；搜索结果和导航为派生视图，不维护第二份可漂移清单。

网上材料保留来源、版本和不适用条件；来源未验证不冒充本地成功。项目经验先读实际证据/结果，未找回的上下文保留未知。公共知识不携带客户路径、样本正文、账号/Token/卡密或私密原始日志。

### 4.3 机械入口与提交

提供薄 CLI：检查/检索相关资源、生成维护计划、校验后应用、按本次备份恢复。计划不是新项目状态：它是调用输出，Agent可用现有项目/evidence 留存，系统不另建事件账本。

计划绑定目标旧指纹、相关资料复核指纹、资源来源版本、候选内容及来源证据。应用时在原锁/事务机制下重核，内容或配置变化拒绝覆盖。旧内容备份留在本机仓外；失败回滚，恢复不覆盖后续用户修改。

既有 vendored KB 默认只读，增量进入本地知识层。个人目录默认私有、只读，明确授权的写入来源才可维护。网页/候选正文不能请求更改这些属性。

### 4.4 应用后验证

必须能用指定问题检索到新/更新内容，并用既有 KB 读取入口读回相同内容。派生索引无需人工抄名单。删除、退役、停用及换目录不能继续把旧内容当当前推荐；历史引用失效明确说明，不偷换为另一来源同名文章。

## 5. 技能、配方、工具与失败经验

技能维护同样先比较；只多了知识时不制造 SKILL。形成独立输入、步骤、输出、验证与恢复条件后，在所属域下生成候选，沿原 skill-import 的 plan/import/deploy/verify 维护；不创建新的导入器或动态执行下载脚本。

工具/MCP 新条目必须能直接发现；能力声明、真实宿主工具、路径/依赖和已验证动作分别呈现。未知软件只发现路径，不凭文件名编造控制方法。用户自己的配置不被公共更新接管。

配方负责组合已有步骤，不变成每个任务的固定链。失败经验写清具体条件、证据、曾排除解释、安全替代和复查办法，不把单次故障推广为领域禁令。后续反证可以修订方法，不自动清除项目风险库的暂停/未知/额度。

## 6. 主动触发、权限与成本

用户明确要求补知识/整理经验时，范围内自主检索、比较、整理、验证，不逐文件询问。普通任务完成可指出值得保留的经验，按已有维护授权处理；没有全局维护授权就留在当前项目，不擅自修改共享知识或公开发布。

专业未知与无进展仍用原 evidence-led-investigation；网页是资料，不是指令。不为了“进化”无限搜索或运行目标；研究和维护沿当前任务的时间/调用/远端预算。

核心代码、规则、风险预算和校验标准不在普通资源维护写集。修程序缺陷继续走隔离分支、测试、独立审查和正常合并。GitHub 推送按指定仓库及发布授权，扫描当前文件与新历史；本地整理不自动等于公开上传。

## 7. 容量与最小改动

现基线第一方1168/1180、MCP3198/3200。此次不放宽阈值、不改来源分类、不把自写资料伪称第三方。实现与文档争取不超过8个新文件，复用现有模块、检查器和回执；不新增MCP工具。

仓内新增知识/技能仍按现行预算计量，达到上限须停止新建，不能自动合并无关主题、排除计数或涨阈值。外部独立资料源有自己的边界与可读状态；不是用它假装所有资源仍属于当前源码闭包。

无限长期内容增长与固定文件上限不能同时自动成立。后续若需要内容/引擎分账，必须另行明确批准政策与边界回归；此轮只保证容量不足如实拒绝，不作无预算增长承诺。

## 8. 实施顺序

1. 记录当前基线、隔离分支、计划与需求决定。
2. 建统一受限来源读取，默认兼容，显式个人扩展与停用。
3. 扩展既有发现及 KB 同核引用/搜索/读取，不改正常任务的准入。
4. 实现知识维护的比较计划、指纹绑定、受限写入、验证与恢复；技能接回原导入器。
5. 接入共享规则、路由、Pi短提醒/配方和扩展手册；不常驻全部资源。
6. 定向、跨层、CLI/MCP与完整回归；原路径全量与隔离部署分别验证。
7. 无父上下文评价者读白话目标自行找反例，主流程复核后修复。自然任务试验分别报告是否读方法、执行与验证，不以元数据存在盖章。
8. 完成后收口状态/文档，源码、部署、宿主加载、GitHub与任务结果分开报告。未经稳定维护窗口不更新用户部署。

## 9. 验收场景

动态性：技能增删、独立工具/MCP、KB增删、来源停用、同名跨源、根移动、两台机器不同资源和坏配置。

知识：已有主题重复不新增；补反例更新原文；不同版本不互相覆盖；新主题归类可搜；外部未验证不冒充案例；无证据不升成熟方法；退役不作默认推荐。

完整性：并发计划只有未漂移者可写；来源配置/相关文章/证据改变拒绝；越界/符号链接/私密载荷拒绝；中断可恢复；回滚不覆盖后续修改；预算超限不留半写。

使用链：通过 CLI 和既有 MCP 搜索/读取实际新增文章；技能仍走原导入/部署链；简单开发不建案；维护不能改守卫、授权、额度或发布配置；外部资料伪指令不执行。

行为：无上下文Agent收到普通人的“整理这次经验”请求，自行找旧内容、判断是更新还是新建、核验保存和读回；另一新会话在相关任务中实际找到并借用。只证明所测场景，不宣称九域专家或任意宿主等价。

## 10. 完成定义

不是新增文件数量，而是用户能自然提出维护需求、已有内容不被无谓复制、更新有证据和适用性、资源变化能被发现、后续任务能实际使用，且隐私、旧功能、并发与恢复判据保持。未验证项必须留在CURRENT-STATE，不能把方案正文当实现证据。
