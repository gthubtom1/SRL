## 二、已修（本轮实证到的具体缺陷）

### R3-1（A，最严重）**触发面矩阵的"路由层"是空转** —— 我的判据自己在说谎

- 现象：`preflight` 长期报"[PASS] 16 句…路由一致"，实际**恒绿**。
- 证据：`preflight.py` 取 `d.get("pack")`，而 `route.py --resolve --json` 的输出是
  `{"query":…, "hits":[{"pack":…}]}` → `got` 永远空 → 比较永远不成立。
- 修：取 `hits[0]["pack"]`；**空 hit 也算错**（不许静默通过）。
- 修完后立刻暴露 **6 处真实错投**（见下）。

### R3-2（A）6 处真实路由错投（修前 `route.py` 全投给 softseep 兜底）

| 用户原话 | 修前 | 修后 |
| :-- | :-- | :-- |
| 帮我测这个站有没有注入 | softseep（兜底） | **web-pentest** |
| 这个协议怎么构造请求 | softseep（兜底） | **protocol-plugin** |
| 这道题能不能打通 | softseep（兜底） | **pwn-crypto** |
| 能不能去广告改会员 | softseep | **交由判型层**（载體不明，硬投 apkseep 是猜） |
| 还不确定属于哪个领域 | softseep | **交由判型层**（seep-router 无 pack） |
| 这个软件加壳了怎么脱壳 | malware-analysis | malware-analysis（保持；`unpack-loop` 为横切能力、不进路由） |

- 修法：给 web-pentest / protocol-plugin / pwn-crypto 的 `must` 补"用户原话"正则；
  两条真有歧义的标 `route_exempt`（只做技能层断言，不断言路由）。

### R3-3（A）报告校验可被"空内容"绕过
- 原实现只查五个标题存在 → 标题齐全但内容空的报告算合格。
- 修：每段 ≥2 行实质内容；结论段 ≤3 行；**已确认段必须出现 E-/C-/F- 证据 ID**；禁用措辞即不合格。

### R3-4（C）`check.py --fast` 的绿容易被误读为全绿
- 修：`--fast` 现在打印"[注意] --fast 跳过：e2e、kb-tests、mutation —— 通过 ≠ 全部通过"。
