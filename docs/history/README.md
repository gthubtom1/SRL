# history —— 历史归档（**默认不要当现状读**）

本目录只放「当时有用、现在只作追溯」的文档。**它不描述当前项目状态。**

当前状态的唯一入口（按顺序）：

1. `README.md` 顶部「现状卡」——版本、门禁、一句话定位
2. `docs/FORK-BRIEF.md`——二开差异、需求、契约、债务
3. `docs/RELEASE-1.26.1.md`——最近一轮交付台账
4. `ROADMAP.md`——现在能做什么
5. `docs/DEFERRALS.md`——延迟项 + 明确不做
6. 实跑 `python Tool/scripts/preflight.py`（应为 45/45）

## 归档清单

| 文件 | 是什么 | 为什么会被误读 |
| :-- | :-- | :-- |
| `AUDIT-2026-10-21.md` | 2026-10-21 那次终审的完整台账（P0/P1 逐条） | 里面的数字（20/20、40/40 等）是当时的门禁条数 |
| `HANDOFF-2026-10-19.md` | 2026-10-19 的交接记录（接手背景与踩坑） | 描述的目录结构与技能数与今天不同 |
| `OPTIMIZATION-2.0.md` | v1.25 之后的一次优化清单 | 条目多以「待做」语态写，实际已完成大半 |
| `audit/A.md … E.md` | 早期五份专项审计（一致性/深度/可跑性/架构/上下文遗漏） | 描述的是当时发现的问题，部分已修、部分转 `DEFERRALS.md` |
| `audit/CLOSURE.md` | 上述审计的逐条闭环记录 | 同上；闭环状态以 `DEFERRALS.md` 为准 |

## 规矩

1. **只读归档**：新增内容一律进权威文档，不往这里加。
2. **不修数字**：归档里的旧数字保持原样（改了就变成"伪造历史"）；要写新结论去权威文档。
3. **引用时可指过来**：需要"当时怎么判的"，链接到本目录；不要把它当作判据来源。
4. 目录本身被 `preflight` 的数字对账和措辞 lint 跳过（`docs/history/`），因为它不承担现状声明。
