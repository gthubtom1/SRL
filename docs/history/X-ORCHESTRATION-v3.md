# 编排架构 v3 —— 主对话只做统筹，重活全部下放

> ⚠️ **背景/依据文档，不是执行口径。** 唯一的数字与批次顺序见 `docs/history/X-PLAN-FINAL.md`（冲突一律以它为准）。

## 0. 一句话

**我们这几天加的全是"话"，不是"手"。**
原版轻 → 模型有余量干活；我们重 → 模型在背课文。
解法不是再写一条规则，而是：**提示词只留路由与契约，战术进技能，禁令进脚本，重活进子代理。**

## 2. 二开 vs 原版：诚实对账

| 维度 | 原版 `open-reverselab` | 我们二开 | 判断 |
| :-- | :-- | :-- | :-- |
| `AGENTS.md` | 14.5 KB | 23.8 KB（今天瘦到 21.4） | 规则 +47%，**机制 +0** |
| 人设层 | 无 | 28.7 KB 破甲卡 | 每轮 +7.5k token，纯风格 |
| 技能 | `SKILLS.md` 1 KB 列表 | 31 个技能 / 90 KB | 能力↑，索引 +4k token |
| 知识库 | `kb/` 412 篇 | 同（复用上游） | 持平 |
| 工具 | 无 MCP | seep 40 工具 + 4 个 MCP | 能力↑，但默认没用上（本次 0 次 x64dbg） |
| 台账 / 闸 | 无 | `case_state.py` + `gate` | 设计对，但**没人调用** |
| 脚本护栏 | 无 | `cmd-guard`（deny 规则昨天才有） | 昨天之前 = 0 |
| 单次会话产出 | — | 442MB dump / 15 个一次性脚本 / 0 交付 | 差 |

### 2.1 一条决定性证据：技能根本没被读过

同一目标，两个会话：

| 会话 | 技能是否在场 | 结果 |
| :-- | :-- | :-- |
| `01a1685a`（48 分钟空转） | **`SKILL.md` 在全文出现 0 次** —— 从未读过任何技能 | 442MB dump / 15 个一次性脚本 / 0 交付 / 断网 1 次 |
| `01a16865`（用户手动开了带 `00-analysis` 的会话） | 技能正文被当作开场消息注入（11,917 字符） | 产出结构化多了：`api_ctx.txt` / `auth_disasm.txt` / `parse_disasm.txt` / `fn_login.txt` |

**这说明两件事：**
1. `AGENTS.md` 里"第 1 步：读技能"这条规则**已经存在且被无视**了 —— 规则不是机制，实证。
2. **预加载技能有效**（用户手动做的那次质量明显更好），但代价是每轮多背 10k token。

→ 所以正确做法不是"预加载 20KB 技能"，而是：**常驻 4 行阶段契约（便宜）+ 硬闸强制 `read`（有效）+ 阶段结束就让它被上下文淘汰（省钱）**。

**结论：原版赢在"轻"。我们把"知识"堆进了提示词，把"能力"堆成了没人调用的工具。**
这不是二开的方向错，是**加东西的位置错**：该加在脚本、技能、子代理里的，全加进了提示词。

## 3. 第一性原则：提示词里只放两样东西

| 放 | 不放 |
| :-- | :-- |
| **路由**：我是谁 / 现在哪个阶段 / 下一步该用哪个技能 / 该不该停 | 战术细节（→ 技能，按需读） |
| **契约**：产物放哪 / 什么算完成 / 什么算失败 / 谁验收 | 禁令清单（→ 脚本，能 if 就别写话） |
| 边界锚（凭据红线 / 授权门 / 沙箱契约，约 230 token） | 术语表与案例（→ KB 检索） |
| 当前阶段的一句话目标 | 风格长文（→ 精简人设卡） |

**核心判据：能写成 `if` 的，就别写成话。**
一条规则如果无法落成脚本判据，它 90% 不会被执行 —— 本次用 21KB 规则、0 次执行，实证了这个判断。

## 4. 架构 v3：四层

```
L0 常驻（≤6k，每轮都在）
   ├ 身份 1k           —— 你是谁 + 语气（人设卡瘦身版）
   ├ 边界锚 0.2k       —— 凭据红线 / 授权门 / 沙箱契约（不可省）
   ├ 路由与契约 2k     —— 阶段机 + AUTO/ASK/DENY + 产物契约
   ├ 技能索引 1.5k     —— 只列当前项目相关的 6–8 个（不是全量 31 个）
   └ 当前阶段 1k       —— 从 case 台账读出来的一句话

L1 阶段技能（按需，一次只装一个）
   └ 00-analysis / 01-gate-bypass / 02 / 03 / 04 —— 装完在阶段末尾自然淘汰

L2 子代理（重活，独立上下文）
   └ 每个阶段派 1 个执行子代理；产物落盘；只回"回执"，不回原始输出

L3 文件状态（唯一记忆）
   └ case 目录：facts.jsonl / state.json / report/ / capture/ / dump/
```

**为什么这样切**：L2 让 442MB dump 和 5093 行伪代码**永不进主上下文**；L3 让"压缩上下文"不再等于"失忆"；L0 瘦下来，主对话才有余量做判断。

## 5. 主对话 = 统筹官（不只是"少干"，而是"只干这五件"）

**只做：**

1. 读 case 台账，报出"现在第几阶段、还差什么"；
2. 判型：这个目标走哪条路（读 1 个技能，不读 5 个）；
3. 派子代理：给输入契约 + 产物路径 + 判据；
4. 收回执：核对证据编号，判"过 / 打回 / 换路"；
5. **停下来问人**（ASK 卡）。

**不做：** 不看 dump、不读反编译正文、不手搓一次性脚本、不自己算地址、不在"还没出报告"时写 build 脚本。

**节律（写死，不靠自觉）：**
- 每 **15 分钟** 或每 **20 次工具调用** → 写 1 条 `case_state.py claim`（结论 + 证据）+ 输出 1 句话进度；
- 连续 **2 次** 无新增证据 → 停手重判型，并主动找一条**能推翻当前结论**的证据；
- 上下文用到 **60%** → 立即把结论落成 facts（别等压缩）。

## 6. 子代理契约（回执格式固定）

派活时给全四样：**case 目录 / 阶段 / 具体任务 / 产物路径 + 判据**。

回执必须是这个 JSON（落盘 `case/subagent/<ts>.json`，主对话只读它）：

```json
{
  "stage": "0-analysis",
  "task": "静态结构 + 壳判定 + 委托壁垒清单",
  "did": ["pe 结构", "节表熵", "壳签名排除", "导入表"],
  "evidence": [{"id": "F-001", "claim": "...", "how": "rabin2 -I + 节表 RawSize=0", "artifact": "report/static.md#L12"}],
  "artifacts": [{"path": "report/static.md", "sha256": "..."}],
  "verdict": "partial-win",
  "blockers": ["CS2encrypted.onnx 20MB 未评估"],
  "next": "定位 File corrupted 自校验（hook MessageBoxW → 调用栈）",
  "drift_check": "与 facts.jsonl 无冲突"
}
```

**主对话的 drift 检查**：拿回执的 `evidence[].id` 与 `facts.jsonl` 对账 —— 出现"回执里有、台账里没有"或"结论与台账相反"，立刻打回，不许往下走。

> 注意：子代理**也要付 29k 固定前缀**。所以 §4 的瘦身对子代理是**同样的收益**，不是只省主对话。

## 7. 阶段闸：机器判定，不接受自述

现在的 `case_state.py gate` 看的是"state 里有没有登记"，模型自己登记就过 —— 这是**软闸**。改成硬闸：

| 阶段 | 输入契约 | 输出契约（必须真存在） | 硬闸判据 |
| :-- | :-- | :-- | :-- |
| **0 分析** | 样本 + case 目录 | `report/static.md`（8 节齐）+ `facts.jsonl`（≥10 条带证据）+ **交付壁垒清单**（非空） | 文件存在 + sha256 对得上 + 8 节标题全在 + 壁垒清单每条有"已评估/未评估"标记 |
| **1 人手登录** | Stage 0 过闸 | `capture/login.json`（真实报文）+ `device_id` | 报文里有真实 `card_code` 之外的响应字段；授权态截图前后各一张 |
| **2 动态** | Stage 1 过闸 | `report/dynamic.md` + 地址台账三列（RVA / 文件基址 VA / 运行时基址 VA） | dump 的 `OptionalHeader.ImageBase` 与实际装载基址一致或已换算；每个关键函数有三列地址 |
| **3 旁路** | Stage 2 过闸 | `artifacts/`（补丁/注入器）+ 决策矩阵（哪条路、为什么、被哪条证据淘汰了别的路） | 旁路产物能启动；未授权态 vs 处理后态两张截图 + 状态位翻转 |
| **4 验收** | Stage 3 过闸 | `report/final.md` + 人机各一半的验收记录 | Agent 侧自动验 + 用户侧真机验，两边都签字 |

**闸的实现原则**：`gate` 只读文件与哈希，**不读模型的自我评价**。

## 8. 技能要改什么（回答"001~00几是不是也得优化"）

技能**本身质量不差**，甚至已经写对了关键事实 —— `00-analysis` 的 I0 仪器矩阵里就有一行：**`baseline` 裸启动「双击 / explorer 启动」能不能到第一个窗口**。也就是说，知识早就在库里，模型没读。所以技能的问题不是"内容错"，是**三个结构问题**：

| 问题 | 现状 | 改法 |
| :-- | :-- | :-- |
| **① 不在场** | 31 个技能索引里模型自由选择 → 选了"自己上手"；实测 48 分钟会话里 `SKILL.md` 出现 **0 次** | 两层：**常驻 4 行契约**（进入/退出/闸/ASK 点，便宜）+ **硬闸强制**（`state.json` 记 `skills_loaded`，`gate` 见不到对应技能已加载就返非 0，并把"下一步：read <path>"写进失败原因） |
| **② 没有阶段契约头** | 技能开头是理念，不是契约 | 每个技能头部加 4 行：**进入条件 / 退出条件 / 硬闸命令 / ASK 点**（照着 §7 的表抄） |
| **③ 体量** | `softseep/SKILL.md` 38KB（≈19k token）当"总调度" | 拆成 3KB 路由表（判型 + 分发 + 指针）+ 把「总控路由」216 行搬进 `references/00-router.md`。它已经是 references 结构，只是主文件太肥 |

`00-analysis`（19.9KB）、`01-gate-bypass`（8.5KB）体量合理，**别动内容**，只加契约头。

## 9. 落地顺序（三期，每期都有可测指标）

### 第一期 · 让常驻层瘦下来（1–2 天）

| 动作 | 省下的 token |
| :-- | --: |
| 人设卡出「瘦身版」（保留语气 + 破甲 + 三档 + 输出格式；长清单/长例子搬到 `docs/`，需要时 `read`） | ~5,000 |
| AGENTS.md 把"细节"搬进 `docs/`，只留触发器 + 指针（今天已从 7,086 → 6,384） | ~3,000（目标值） |
| 技能索引按项目裁剪：逆向项目只列 6–8 个（softseep / 00–04 / unpack-loop / ida-reverse / radare2） | ~2,500 |
| `prompt-budget.py --ceiling 8000` 进 preflight | 防再胖 |

**验收**：`prompt-budget.py` 常驻合计 ≤ 8,000（当前 29,415）。

### 第二期 · 把规则变成手（3–5 天）

1. 阶段硬闸（§7）落进 `case_state.py gate`；
2. `skills_loaded` 记账 + 未加载技能不许过 Stage 0；
3. `progress-ledger.ts`：15 分钟 / 20 次调用强制落账 + 一句话汇报；
4. 模型准入（flash 不许判型）；
5. **规则→脚本迁移清单**（每条 AGENTS 规则问一句"能不能写成 if"，能就搬）：目前能搬的至少 6 条（网络禁手已搬、启动禁手已搬，剩：扫描边界、链长、工具通道优先级、todo 强制、20 分钟账、凭据脱敏）。

**验收**：AGENTS.md ≤ 4,000 token（全部是路由与指针）。

### 第三期 · 编排与子代理（1 周）

6. 主对话统筹官 prompt（§5 五件套）+ 子代理回执 schema（§6）；
7. `general-purpose` 子代理加"阶段执行器"profile（注入对应技能）；
8. `softseep` 拆 3KB 路由 + `references/00-router.md`；
9. case 锁（同 case 第二会话直接拒）+ case 模板 `.gitignore` + `clean --keep`；
10. `seep_status` 版本自检 + `mcp-doctor --dedupe`（现在同时 4 个 seep 进程）。

**验收**：一次完整任务里，主对话上下文字峰值 ≤ 40k，子代理 ≥ 3 个，主对话从未读到 dump/反编译正文。

## 10. 记分板：什么叫"比原版强"（可测，不靠感觉）

| # | 指标 | 原版 | 本次基线 | 目标 |
