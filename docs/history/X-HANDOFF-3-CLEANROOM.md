# 全新审查任务书（第三条线：只看项目本身，从代码判断）

> 这是一次**全新对话**的审查任务。前情提要：**没有**。你不需要知道我们之前讨论过什么，也不用去猜。
> 我们只要你做一件事：**把这个项目通读一遍，然后告诉我们它离"我要的效果"还差什么。**

## 一、这个项目是干什么的（大白话）

我（用户）一个人用这套东西。它装在我的电脑上，是一个"AI 助手 + 一大堆工具和手册"的组合。
我平时把各种活丢给它，让它自己判断、自己动手，我要的是**结果**，不是过程好看。

我说的是这些活（不是只有"逆向"一种）：

| 我会丢给它的东西 | 我想要的交付物 |
| :-- | :-- |
| 一个 Windows 软件（可能带壳、带卡密联网授权） | 一个能用的成品：原版能跑、功能全开；或者明确告诉我"做不到，卡在哪" |
| 一个安卓 APK | 去掉广告/限制、能装能用的包；或者带证据的结论 |
| 一个网站 / 一套接口 | 把协议搞清楚，能自己发请求复现；或者指出鉴权/越权在哪 |
| 一个浏览器插件 | 搞清它干了什么、能不能改 |
| 一个固件 / 一台设备 | 能不能进去、能不能改、改坏了能不能救 |
| 一个不知道是什么的文件 | 10–20 分钟内告诉我：什么类型、有没有壳、大概什么架构、值不值得深入 |
| 有时候我只要一份报告 | 给客户/存档用的分析报告，每条结论都能被人照着复现 |

除了这些"硬活"，还有些日常要求：帮我看看这个程序为什么起不来、这个壳能不能脱、这段算法是什么、
这个授权是本地的还是联网的、这批样本里有没有可疑的。

**我还要能加新领域。** 今天做逆向，明天可能做协议，后天做插件。我不想每上一个新领域就把整个系统推倒修几天。

## 二、我在意的到底是什么（这几条比什么都重要）

1. **要效果，不要规范。** 文档写得再整齐、检查全绿，最后没东西交付，对我来说等于零。
2. **该停就停，该找我找。** 有些事只有我能做（在我自己的电脑上双击程序、输卡密、看界面）。
   到这种时候它应该停下来，告诉我"请你做这三步"，而不是自己想办法硬凑。
3. **别把我电脑搞坏。** 这台机器就是我平时用的。它要是改了网络、改了系统设置导致我上不了网，那就没法用了。
4. **别闷头跑。** 我可以接受它慢，但不能接受它跑四十分钟一句话都不说，我完全不知道它在干嘛。
5. **钱要花得值。** 我付 token 的成本。跑很久可以，但得有对应的产出；跑很久还啥都没有，就是浪费。
6. **做不到就早说。** 有些目标是真的做不到（服务端说了算、资源加密、硬件绑定）。我希望它早点告诉我"天花板在哪"，
   而不是烧两小时后交一个没法用的东西。

## 三、最终要到什么程度（我心里合格的标准）

不是一个模糊的"很智能"，是这四级里能稳到哪一级：

- **M1**：能说清这目标是什么、能不能做、卡在哪（一份可复核的分析）
- **M2**：能拿到关键一步的证据（登录报文、内存里的明文、算法还原），但还不是成品
- **M3**：能出一个**我自己启动、自己操作就能用**的成品
- **M4**：1:1 复刻（界面、功能、授权全部到位）

**现在我最想要的是 M3，而且希望它自己判断这次最多能到哪一级、并说清依据。**
长期看，这套东西要能覆盖上面所有领域，加新领域时**不改主流程**。

### 4.3 请回答的问题

按顺序写，**每条都要有证据**（`文件:行号` 或「命令 + 输出片段」）：

1. **它现在实际能做到什么？** 按我上面列的领域逐一说：哪块真的能跑通、哪块只是有架子。给证据。
2. **虚能力清单**：仓库里有多少东西**只存在于文档/配置里，代码里并没有实现**，或者实现了但没人调用？
   这一节请单独列成表（能力名 / 声称在哪 / 实际实现状态）。
3. **每个领域的缺口**：要做成我要的 M1–M3，这块具体缺什么（缺能力 / 缺机制 / 缺验证）。
4. **从工程角度看，哪些结构性问题会挡住我的目标？** 注意：我要的是结构问题，不是"文档写得不好"。
5. **可优化空间**：按"对交出成品的帮助"从大到小排，每条给：改什么 / 大概成本 / 怎么验证改好了。
6. **如果只能先改 5 件**，是哪 5 件？为什么是它们，不是别的？
7. **它最可能死在哪一步？** 用一条时间线说清（一个真实目标从进门到交付，会在哪一步卡死）。
8. **加新领域时的成本**：现在要加一个新领域（比如"协议逆向"），实际要改哪些地方？会不会动到主流程？
