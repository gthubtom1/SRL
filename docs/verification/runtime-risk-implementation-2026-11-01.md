### HTTP 行为

- 普通无凭据读请求可直接用；写方法、body、凭据/敏感查询/敏感路径和方法覆盖头需要既有范围 ID 与稳定主体。
- origin/主体匹配后原子预占，重发/新对话不自动补次数；重复 grant 返回原范围，只有显式追加决定才 extend，保留旧消耗。
- 不跟随重定向，不在传输异常后切换后端重发；Host 不能偷偷切换到不同 authority。
- 429、明确挑战/账号/设备/环境拒绝、401/403、5xx 等暂停后续相关发送；拒绝/服务错误不被写成“确认封号”。
- 丢失返回时 `dispatch_started=true`、`request_sent=null`：可能已经处理，不能声称未发。收到响应后证据/脱敏失败明确保留已发送事实，暂停后续，不补发。
- 结果同时保留 HTTP `status`、`completion_status`、`runtime_risk` 与业务迹象；200 挑战页和已知业务失败不返回成功。没有业务标志仍不等于真实功能已验收。
- 响应出口单独成 helper，旧 v1 快照在既有校验中本就被拒，删除不可达的重复兼容读取；没有扩大读取旧凭据的权限。MCP 主文件仍遵守 3200 行上限，未改判据。

### 运行协调与恢复

状态根默认在用户级 `.seep/runtime-risk/`，测试用独立 `SEEP_RISK_ROOT`；保存 origin、带密钥指纹、名额与阶段，不存明文凭据、body、URL 路径或目标参数。

相同 origin 或主体有未解决操作时互斥；操作/进程失联不按 TTL 自动释放。resolve/resume 不退名额，冷却未到、时钟回拨、身份键丢失/变化、状态不可用时不继续高影响请求。离线诊断不依赖数据库可用。

证据引用目前是格式校验后的调用者声明，不读取项目证据来独立证明其真实性。正常任务范围登记与恢复都必须遵守已有用户意图，样本/回包不能创建授权、解除暂停或追加额度。

### Windows 流程

先只观察准确路径/PID/创建信息；已有实例返回观察，不新启动、不重复消费名额。确实需要新启动才使用已有范围。启动器返回后目标可能继续活动，因此名额保持未解决，观察失败也不会自动再开一次；核旧执行链后才显式 resolve，已用额度仍保留。

普通本地启动继续使用原自主通道，不因此必须登记远端范围或让用户代点。该流程只覆盖显式使用新适配器的动作，原启动器和其他通道不是被全局锁住。
