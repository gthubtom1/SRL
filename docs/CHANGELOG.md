# 变更说明

本文件只记录已发生的实现变更；有效范围见 [REQUIREMENTS](../REQUIREMENTS.md)，最新验收与适用边界见 [CURRENT-STATE](CURRENT-STATE.md)。1.30.0 的追版增量见[定制分支跟随更新回执](verification/custom-branch-follow-2026-10-30.md)；1.29.0、1.28.1、1.28.0 和 1.27.0 的历史证据继续保留。

## 1.30.0 定制分支跟随更新

- 扩展现有 `version-migrate` 配方，没有新增正式域、固定阶段链或第二套工作流引擎。首次定制现在要求登记旧上游、成品、补丁、定制 UI、构建、验收和回滚入口；后续更新先找回唯一旧项目，再比较旧上游、新上游和我方定制成品。
- `version-migrate.py add-ui` 向现有 `seep-reverse-baseline/1` 的 `ui[]` 写入受验证记录：UI 技术栈、应用方式、上游锚点、机读清单、资产、前后截图和验收项。路径必须位于项目内且为普通文件，资产/清单/截图记录 SHA256 与大小；拒绝时基线字节不变。
- 首次 UI 定制以覆盖层、自有启动器或服务端内容为优先，其次外部资源，再到接口锚点、AOB 和代码级重写。新版新增功能必须并入定制 UI，旧 RVA、相似文件名或孤立截图不能作为追版成功。
- 新增“软件更新了，跟随更新”“保留我们的 UI，更新到新版”“把上一版的补丁适配到新版”“新版路径是刚拖进来的新版文件”等精确入口；普通依赖、文档和系统更新不会命中追版。APK/AAB 追版复用同一配方并走 Android 重打包、签名和安装验证。
- 修正追版文档中旧 `patch-verify.py fingerprint/align/report` 命令，统一为 `version-migrate.py`。旧 `_pending/00..05` 继续只作历史资料，第一版支持面明确为 PE/Windows 与 APK。
- 新增 12 条追版/负例意图探针和 7 项 UI 账本拒绝回归；追版交付专项共 15 项通过。九域端到端、部署哈希、运行时注册和版本账恢复通过。

本轮没有在真实客户软件上执行追版，也没有把 UI 应用、未知载体或设备相关结果宣称为已验证。首个真实目标仍须按具体壳、签名、UI 栈、服务端和构建条件完成运行验收。
